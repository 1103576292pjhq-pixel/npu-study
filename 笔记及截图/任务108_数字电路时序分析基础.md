## 1. 数字 IC flow 的关键是交付物一路变具体

数字 IC 设计不是一串工具名，而是一条表示层级逐步降低、约束逐步具体、证据逐步收敛的链。前端把需求变成可验证 RTL，再由综合变成 gate-level netlist；后端把网表放到真实物理版图里，再用 STA/DRC 等检查保证能制造和能工作。

流程可以压成：

```text
spec/performance/power/area
  -> C/C++ model or architecture model
  -> RTL coding
  -> functional verification
  -> logic synthesis: gate-level netlist + SDC
  -> DFT insertion
  -> APR / place and route
  -> STA / physical DRC / signoff
  -> GDSII to foundry
```

DFT 画成虚线，是因为它不是“逻辑功能必须有”的步骤，但正常芯片几乎都会做。没有 DFT，制造缺陷很难定位；加入 DFT 会增加面积和成本。这是典型 PPA/可测性 trade-off。

STA 常用 PrimeTime 一类工具做 signoff；DRC 在这里主要指 physical DRC，检查版图层面的几何规则，而不是前面逻辑/综合阶段的 design rule check。

## 2. 组合逻辑看当前输入，时序逻辑记住历史状态

组合逻辑的输出由当前输入决定，输入一变，经过传播延时后输出就变；它不保存状态。时序逻辑由 clock edge 触发，只有在有效边沿到来时才把 D 端采样到 Q 端，因此能保存状态。

![组合逻辑和时序电路对比](<./screenshots/任务108_数字电路时序分析基础/task108_dense_0720s_00h12m00s.jpg>)

RTL 中常见对应关系：

```verilog
// 组合逻辑
always @(*) begin
  a = b & c;
end

// 时序逻辑
always @(posedge clk) begin
  q <= d;
end
```

阻塞赋值和非阻塞赋值不是唯一判断依据，但它们反映了常见编码意图：组合逻辑用阻塞赋值描述立即组合关系；时序逻辑用非阻塞赋值描述边沿采样后的寄存器更新。

## 3. Latch 的风险来自电平敏感和不完整赋值

Latch 是电平敏感且能存储的器件。它面积可能比触发器小，但对毛刺敏感，时序分析更复杂，因此常规同步 IC 设计中应尽量避免无意 latch。

![Latch 产生原因](<./screenshots/任务108_数字电路时序分析基础/task108_dense_0960s_00h16m00s.jpg>)

容易产生 latch 的 RTL 写法包括：

| 场景 | 为什么会产生 latch | 修正口径 |
|---|---|---|
| `if` 没有完整 `else` | 条件不成立时输出需要保持旧值 | 给默认赋值或补全所有分支 |
| `case` 描述不全 | 未覆盖取值需要保持旧值 | 加 `default` 或覆盖所有枚举 |
| 组合 always 敏感列表不全 | 某些输入变化时不触发更新 | 使用 `always @(*)` 或 `always_comb` |

面试中问“什么情况下会产生 latch”，不要只答“if 没有 else”。更完整的答案是：组合逻辑描述中存在未定义输出值的路径，综合器为了让输出在未赋值路径保持旧值，就会推断 latch。

## 4. 同步复位和异步复位的区别在触发条件

同步复位必须等 clock edge 到来才生效；异步复位不需要正常时钟边沿，只要 reset 的有效边沿或电平发生，就能立即让寄存器进入复位状态。

```verilog
// 同步复位
always @(posedge clk) begin
  if (!rst_n) q <= 1'b0;
  else        q <= d;
end

// 异步复位
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) q <= 1'b0;
  else        q <= d;
end
```

同步复位更容易放进同步时序分析；异步复位响应快，但释放时要注意与时钟的关系，否则可能引入恢复/去除时间问题或 CDC 风险。这里的重点不是偏向哪一种，而是知道 reset 是否进入 sensitivity list 决定了它是否脱离 clock edge 生效。

## 5. RTL 和 gate-level netlist 是不同抽象层

RTL 中可以有 `always`、`if/else`、`case`、`<=` 等行为描述；gate-level netlist 中主要剩下 standard cell instance、pin、net 和 port 连接。

![RTL vs Gate](<./screenshots/任务108_数字电路时序分析基础/task108_dense_1200s_00h20m00s.jpg>)

例如 RTL 中的触发器行为：

```verilog
always @(posedge clk) begin
  q <= d;
end
```

综合后可能变成：

```verilog
DFF_X1 u_q_reg (
  .D(d),
  .CK(clk),
  .Q(q)
);
```

gate-level 的可读性更低，但它携带了真实库单元、驱动能力、面积和 timing arc，后端和 STA 需要的正是这些信息。

## 6. Setup time 的本质是“下一拍前必须赶到”

Setup 检查看的是 launch register 在一个 clock edge 发出的数据，能否在下一个 capture edge 到来前到达并稳定。工具真正能优化的是两个寄存器之间的组合逻辑延时 $T_{comb}$。

![建立时间推导](<./screenshots/任务108_数字电路时序分析基础/task108_dense_1440s_00h24m00s.jpg>)

看这张 setup 推导图时要盯住一个事实：综合器真正能大幅改变的是寄存器之间的组合逻辑延时 $T_{comb}$。周期、触发器 setup、触发器 clock-to-Q 来自目标和库模型，不是工具可以随便抹掉的变量。

简化 setup 公式：

$$
T_{ck\to q}+T_{comb}+T_{setup}\le T_{period}
$$

考虑 clock skew 后，可以写成更接近工程直觉的形式：

$$
T_{comb}\le T_{period}-T_{ck\to q}-T_{setup}-T_{skew\_margin}
$$

其中：

- $T_{ck\to q}$ 来自触发器库特性。
- $T_{setup}$ 来自触发器库特性。
- $T_{comb}$ 是综合器要通过 mapping/optimization 尽量压低的组合逻辑延时。
- $T_{skew\_margin}$ 是时钟到两个寄存器的到达差异带来的保守量。

这解释了为什么频率越高，setup 越难过。频率升高等于周期 $T_{period}$ 变小；右边预算变小，组合逻辑就必须更短、更快。

一个数值例子：若 $T_{period}=2.0ns$，$T_{ck\to q}=0.12ns$，$T_{setup}=0.08ns$，预留 skew/uncertainty 为 $0.20ns$，那么组合逻辑预算只有 $2.0-0.12-0.08-0.20=1.60ns$。如果 report 里一条 reg-to-reg data path 是 1.75ns，setup slack 约为 $-0.15ns$，这不是“差一点点没关系”，而是说明下一拍采样边沿到来时数据还没稳定。

## 7. Hold time 的本质是“同一拍的新数据不能太快污染旧采样”

Hold 检查看的是同一个 clock edge 后，launch 端的新数据不能太快跑到 capture 端，否则 capture register 还没完成对旧数据的保持窗口，新数据就把它污染了。

简化 hold 公式：

$$
T_{ck\to q}+T_{comb}\ge T_{hold}
$$

考虑 skew 后，hold 也会被 clock 到达差异影响。setup 希望数据路径够快；hold 希望数据路径不要过快。综合和后端就是把 $T_{comb}$ 夹在两个约束之间：

```text
hold 下限 <= Tcomb <= setup 上限
```

DC 前端综合通常更重视 setup，因为把逻辑延时变小很难；hold 不满足时，后端常能通过插 buffer 增加数据路径延时来修。这个说法不是说 hold 不重要，而是说明修复手段和阶段不同。

setup 像赶下一班车，数据必须在车门关闭前到站；hold 像刚上车的人还没站稳，下一批数据不能立刻冲进来把旧采样撞掉。这个比喻只服务一个边界：setup 给路径设上限，hold 给路径设下限，两者夹住的是同一条 $T_{comb}$。

## 8. Pipeline 用面积换速度

当一个时钟周期内的组合逻辑太深，综合器怎么优化都压不下 $T_{comb}$ 时，就要考虑插 pipeline register，把长路径切成多段短路径。

![流水线切分组合逻辑](<./screenshots/任务108_数字电路时序分析基础/task108_dense_2160s_00h36m00s.jpg>)

如果原来是：

```text
Reg -> Logic1 -> Logic2 -> Logic3 -> Reg
```

插 pipeline 后变成：

```text
Reg -> Logic1 -> Reg -> Logic2 -> Reg -> Logic3 -> Reg
```

每段 $T_{comb}$ 变小，周期可以缩短，频率可以提高。代价是寄存器面积增加、时延 latency 增加、控制逻辑可能更复杂。CPU pipeline 的直觉也是如此：取指、译码、执行可以在不同指令上并行推进，提高吞吐率，但每条指令仍然要经过多个阶段。

## 9. CTS 解决的是 clock 到达差异，不是 DC 里手动插几棵树

Clock Tree Synthesis 的目标是把 clock 从源头分发到各寄存器，并控制 skew、transition、insertion delay。CTS 通常在 APR 阶段做，因为只有布局位置确定后，工具才知道每个寄存器离 clock source 多远。

![Clock Tree Synthesis](<./screenshots/任务108_数字电路时序分析基础/task108_dense_2400s_00h40m00s.jpg>)

看 CTS 图时要明确它不是在介绍一个遥远的后端细节，而是在解释为什么前端综合不能永远假设 ideal clock。真实 clock tree 会引入 skew、latency 和 transition，这些都会回到 setup/hold 预算。

DC 阶段可以估计 clock latency、uncertainty、transition，但不负责真正基于 placement 生成 clock tree。后端会根据实际摆放插 buffer/inverter，让不同寄存器的 clock 到达时间尽量接近，同时满足驱动能力和 transition 约束。

## 10. Cell delay 来自 lookup table，不是工具凭空估计

Standard cell delay 和 output transition 通常由 library 中的查找表给出。查表输入常见是 input transition 和 output load；输出是 cell delay、output transition 等 timing 数据。

![cell delay 与 transition](<./screenshots/任务108_数字电路时序分析基础/task108_dense_2520s_00h42m00s.jpg>)

这张图讲单个 cell 如何按 input transition 和 output load 查表；下一张 PVT 图讲同一个 cell model 在不同 corner 下整体漂移。前者是局部查表机制，后者是全局工作条件变化。

直觉上，电路延时来自充放电：

- input transition 越慢，后级门看到的有效切换越慢，延时通常变大。
- output load 越大，需要充放电的电容越大，延时通常变大。
- 驱动能力越强，同样负载下 transition 更陡，延时更小。

DC 不会每条路径都从晶体管级重新仿真；它会根据库表查每个 cell 在当前 transition/load 条件下的延时，再把路径上的 cell delay 和 net delay 累加。

## 11. PVT 和 wire delay 把“同一电路”变成多个角落

同一个 cell 在不同工艺、电压、温度下延时不同，这就是 PVT corner 的原因。

![PVT 特性](<./screenshots/任务108_数字电路时序分析基础/task108_dense_2640s_00h44m00s.jpg>)

| 因素 | 延时趋势 | 原因 |
|---|---|---|
| Process | slow/typical/fast corner 不同 | 晶体管制造偏差改变驱动能力 |
| Voltage | 电压越高通常越快 | 充放电驱动力更强 |
| Temperature | 温度越高通常越慢 | 迁移率下降，等效电流变小 |

不同 corner 对应不同 library。STA 不能只看一个典型点，因为芯片要在最坏条件下也满足时序。

Wire delay 则来自 RC 模型。金属线越长、电阻电容越大，延时越大。后端修长线的一种办法是在中间插 buffer，把一条很长的 RC 线分成几段，改善 transition 和驱动能力。

## 本章收束与检查

### 本章最该记住的结论

- 数字 IC flow 的核心是交付物从 spec 到 RTL 到 netlist 到 GDS 逐步具体。
- 组合逻辑不存状态；时序逻辑靠 clock edge 存状态。
- 不完整组合逻辑赋值会让综合器推断 latch。
- Setup 要求数据下一拍前赶到；hold 要求同一拍后新数据别太快污染旧采样。
- Pipeline 通过增加寄存器和 latency 换更高频率。
- CTS 要基于物理摆放做，DC 只能估计相关时钟效应。
- cell delay 来自 library lookup table；PVT 和 wire RC 会改变 timing。

### 复现清单

1. 画出从 RTL 到 gate-level netlist 的表示变化。
2. 给一个 `if` 没有 `else` 的组合 always，说明为什么会推断 latch。
3. 用 $T_{ck\to q}+T_{comb}+T_{setup}\le T_{period}$ 手算 setup 预算。
4. 用一组数字同时判断 setup slack 和 hold 是否可能太短。
5. 解释为什么 hold violation 常可通过插 buffer 修，而 setup violation 更难。
6. 用 pipeline 把一条长组合路径切成三段，说明频率、面积和 latency 的变化。

### 自测题

1. 为什么 setup violation 通常比 hold violation 更难修？

   答：setup 要把组合逻辑延时压小，可能需要重构逻辑、换更强 cell、插 pipeline 或放宽频率；hold 可以通过增加数据路径延时等方式在后端较常修复。

2. 为什么 latch 在常规同步 IC 设计中要避免？

   答：latch 电平敏感，对毛刺更敏感，时序分析和约束更复杂；无意 latch 常来自不完整赋值，可能导致功能和时序都不稳定。

3. PVT corner 为什么会影响 STA？

   答：process、电压、温度会改变 cell 延时和功耗。STA 必须在不同 corner 下分析，保证芯片在最坏工作条件下也满足时序。
