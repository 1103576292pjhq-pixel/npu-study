# 任务08：gvim 正则表达式

## 本章知识全景图

### 1. 一眼看懂这讲在讲什么

gvim 正则表达式的核心不是背符号，而是把“要找的文本形状”写成模式，再让 gvim 对匹配到的片段或整行执行搜索、替换、删除、重排。数字前端里，正则常用于批量改信号名、清理空行、整理 filelist、交换字段、生成重复结构和处理脚本输出。

核心概念：底行模式、`:%s/pattern/replace/g`、`global`、行首 `^`、行尾 `$`、字符类、空白字符、数量词、分组捕获、反向引用、函数式替换、sed。

逻辑主线：

- 先理解替换命令的四段结构：范围、动作、匹配、替换。
- 再用字符类和数量词描述“某一类字符出现多少次”。
- 然后用锚点描述位置，比如行首、行尾、单词边界。
- 接着区分替换片段的 `:%s` 和处理整行的 `:g/pattern/command`。
- 最后用捕获和反向引用完成结构化重排。

### 2. 概念地图

| 能力层 | 典型命令 | 解决的问题 | 最容易错在哪里 |
|---|---|---|---|
| 查找替换 | `:%s/old/new/g` | 全文件替换文本 | 把 `%` 和行内 `g` 混淆 |
| 行处理 | `:g/pattern/d` | 删除匹配行 | 把 global 当成 substitute |
| 位置匹配 | `^`、`$`、`\<`、`\>` | 匹配行首、行尾、单词边界 | 把位置当成可见字符 |
| 字符集合 | `[abc]`、`[^abc]`、`\s` | 匹配一类字符 | 误以为 `[abc]` 匹配字符串 `abc` |
| 重复次数 | `*`、`\+`、`\?` | 控制前一项出现次数 | 不清楚数量词作用对象 |
| 结构重排 | `\(...\)`、`\1`、`\2` | 捕获并复用匹配片段 | 不知道自己捕获了哪一段 |

### 3. 最短学习路径

1. 先掌握 `:%s/pattern/replace/g` 的结构。
2. 用 `[Hh]elp` 理解字符类匹配“一个候选字符”。
3. 用 `^$` 和 `^\s*$` 区分真正空行和只含空白的行。
4. 用 `:g/pattern/d` 理解整行删除。
5. 用 `\(...\)` 与 `\1`、`\2` 做字段交换。
6. 所有批量替换先小范围测试，再全文件执行。

正则表达式可以理解成“文本模具”和“筛网”的结合：pattern 先决定哪些文本能通过筛网，replace 再决定通过后的材料被怎样重新压成新形状。这个比喻的边界是：正则不懂 RTL 语义，它只懂字符形状；所以批量替换越强，越需要边界和 diff 审查。

## 1. 正则表达式是底行模式里的“文本形状语言”

gvim 有命令模式、插入模式和底行模式；正则表达式主要服务底行模式的搜索和替换。它不是普通搜索的另一个名字，而是把一类文本写成可匹配的模式。

视觉验证：02:34，画面展示正则表达式在 gvim、Linux 工具、脚本中的用途。

![正则表达式入口](<./screenshots/任务008_gvim正则表达式/01_regex_intro_02m34s.jpg>)

这张图要看应用范围：gvim、脚本和 Linux 工具都能用正则思想。后续不要把正则当成某个编辑器的小技巧，它是批量处理文本结构的通用方法。

最常见命令：

```vim
:%s/pattern/replace/g
```

拆开看：

- `:` 进入底行模式。
- `%` 表示范围是整个文件。
- `s` 表示 substitute，也就是替换。
- `pattern` 是要匹配的文本模式。
- `replace` 是替换后的内容。
- 最后的 `g` 表示一行内所有匹配都替换；没有它时每行只替换第一个匹配。

一个稳妥的理解顺序是：先问“在哪些行上做”，再问“找什么形状”，再问“替换成什么”，最后问“一行内替换几次”。

## 2. 字符类：`[abc]` 匹配一个字符，不是匹配整个字符串

字符类用方括号描述“候选集合”。`[Hh]elp` 表示第一个字符可以是 `H` 或 `h`，后面必须是 `elp`，所以它能匹配 `Help` 和 `help`。

视觉验证：06:50-07:30，画面用大小写 `help` 说明字符类的匹配方式。

![大小写 help 替换](<./screenshots/任务008_gvim正则表达式/02_special_chars_07m44s.jpg>)

这张图要看数量词表，而不是一次背完。正则的核心不是符号多，而是每个符号都在回答“匹配一个什么东西、重复多少次、停在哪里”。

例子：

```vim
:%s/[Hh]elp/HELP/g
```

常见字符类：

| 模式 | 含义 |
|---|---|
| `.` | 任意单个字符 |
| `[abc]` | `a`、`b`、`c` 中任意一个字符 |
| `[a-z0-9]` | 小写字母或数字 |
| `[^abc]` | 不是 `a`、`b`、`c` 的任意一个字符 |
| `\d` | 数字 |
| `\D` | 非数字 |
| `\s` | 空白字符，包括空格和 Tab |
| `\S` | 非空白字符 |

关键区别：`[abc]` 匹配的是单个字符 `a` 或 `b` 或 `c`；如果要匹配连续字符串 `abc`，直接写 `abc`。如果把 `[abc]` 当成“字符串 abc”，删除行时会删掉所有以 a、b、c 任一字符开头的行。

## 3. 锚点和空白：空行不等于只有空格的行

`^` 和 `$` 匹配的是位置，不是可见字符。`^$` 表示行首后立刻就是行尾，所以只能匹配完全空行；如果一行里有空格或 Tab，它就不是 `^$`。

视觉验证：12:54-15:30，画面讨论删除空行，以及为什么 `^$` 删除不了含空格或 Tab 的空行。

![删除空行](<./screenshots/任务008_gvim正则表达式/03_delete_blank_lines_12m54s.jpg>)

这张图要看两种空行：真正没有字符的空行，以及肉眼看起来空但包含空格/Tab 的行。日志和复制文本里后者很常见。

删除真正空行：

```vim
:g/^$/d
```

删除只含空白的行：

```vim
:g/^\s*$/d
```

区别：

- `^$`：行首直接接行尾，中间什么都没有。
- `^\s*$`：行首后可以有 0 个或多个空白字符，然后到行尾。
- `\s` 包括空格和 Tab，比直接敲一个空格更稳。

数字前端常见场景：清理工具生成的 filelist、log 摘要、端口列表时，空白行可能包含 Tab 或空格。只用 `^$` 会漏掉这些“看起来空”的行。

## 4. `global` 命令处理整行，`substitute` 命令替换片段

`:g/pattern/d` 的含义是：在指定范围内找匹配 `pattern` 的行，然后对这些行执行命令 `d`。它处理的是整行；`:%s/pattern/replace/g` 处理的是行内匹配片段。

视觉验证：15:53-17:30，画面讲解 global 命令的范围、pattern 和 command。

```vim
:g/ERROR/d       " 删除包含 ERROR 的整行
:g/^$/d          " 删除所有完全空行
:v/^$/d          " 删除所有非空行，保留空行
```

判断口径：

- 要删除整行，用 `:g/pattern/d`。
- 要替换一行中的某段文本，用 `:%s/pattern/replace/g`。
- 要删除匹配片段，也可以用空替换：`:%s/pattern//g`。

把两者混淆会导致结果完全不同。例如删除所有以数字开头的行，用 `:g/^\d/d` 更直接；如果写成 `:%s/^\d//g`，只是删掉每行开头的数字，不会删整行。

## 5. 行首行尾批量插入：锚点匹配的是“位置”

锚点可以作为替换目标，因为它表示位置。把 `^` 替换成前缀，就是在每行行首插入；把 `$` 替换成后缀，就是在每行行尾追加。

视觉验证：18:03-19:30，画面演示在每行开头插入符号、在行尾追加字符。

![行首行尾操作](<./screenshots/任务008_gvim正则表达式/04_line_ops_18m03s.jpg>)

这张图要看 `^` 和 `$` 是位置。它们像每行左右两端的挂钩，你不是替换一个可见字符，而是在挂钩处挂上前缀或后缀。

示例：

```vim
:%s/^/prefix_/g
:%s/$/_suffix/g
:%s/^[ \t]*//g
```

工程用途：

- 给 filelist 每行加目录前缀。
- 给信号名批量加模块前缀。
- 删除复制表格时带来的前导空格。
- 给脚本输出追加统一后缀。

注意：`^` 和 `$` 不消耗字符。它们像“光标位置”，你替换的是位置，不是原文本。

## 6. 数量词：它只修饰前一项

数量词控制前一项出现多少次。` \+` 表示一个或多个空格；`\s\+` 表示一个或多个空白字符；`.*` 表示任意字符出现 0 次或多次。

视觉验证：23:13 附近，画面通过多个例子说明字符类和重复匹配。

![字符类与数量词](<./screenshots/任务008_gvim正则表达式/05_class_and_duplicate_23m13s.jpg>)

这张图要观察数量词修饰的是“前一项”。如果前一项是 `[abc]`，重复的是 a/b/c 中的一个字符；如果前一项是 `\(abc\)`，重复的才是一整组。

常见数量词：

| 模式 | 含义 |
|---|---|
| `*` | 前一项出现 0 次或多次 |
| `\+` | 前一项出现 1 次或多次 |
| `\?` | 前一项出现 0 次或 1 次 |
| `\{n}` | 前一项出现 n 次 |
| `\{m,n}` | 前一项出现 m 到 n 次 |

例子：

```vim
:%s/ \+/ /g
:%s/\s\+/ /g
```

第一条只压缩空格，第二条压缩空白字符，包括 Tab。处理从 PDF、网页、Excel 或工具日志复制来的文本时，第二条更稳。

## 7. 捕获和反向引用：正则从查找升级为结构改写

分组捕获用 `\(...\)`，替换区用 `\1`、`\2`、`\3` 取回捕获到的内容。它的核心是“先保存文本片段，再在替换结果里重新排列”。

视觉验证：33:42-38:42，画面讲解 `\1` 的含义，以及重复行压缩和反向引用。

![捕获和反向引用](<./screenshots/任务008_gvim正则表达式/06_duplicate_compact_33m42s.jpg>)

这张图要看分组编号：第一个括号里的内容叫 `\1`，第二个叫 `\2`。捕获像临时把匹配到的字段放进盒子，替换区再按新顺序把盒子倒出来。

### 7.1 压缩连续重复行

```vim
:%s/^\(.*\)\n\1$/\1/g
```

理解：

- `^\(.*\)`：从行首捕获一整行内容，保存为 `\1`。
- `\n\1$`：下一行必须和刚才捕获的内容相同，并到行尾。
- 替换成 `\1`：把两行重复内容压成一行。

这条命令只适合连续重复行。非连续重复行不是它要解决的问题。

### 7.2 交换冒号两侧字段

```vim
:%s/^\(.*\) : \(.*\)$/\2 : \1/g
```

输入：

```text
ABC : XYZ
```

输出：

```text
XYZ : ABC
```

机制：

- 第一组 `\(.*\)` 捕获冒号前的 `ABC`。
- 第二组 `\(.*\)` 捕获冒号后的 `XYZ`。
- 替换区写 `\2 : \1`，所以两个字段交换位置。

视觉验证：38:42-43:51，画面解释冒号位置不变，把第二组放前面、第一组放后面。

![反向引用交换字段](<./screenshots/任务008_gvim正则表达式/07_backreference_38m42s.jpg>)

这张图要看“冒号不是被捕获对象，而是边界”。如果边界写错，`\1` 和 `\2` 装进去的内容就会错，替换结果再整齐也没意义。

## 8. 字段边界必须写清楚：逗号、空格、括号都可能改变匹配

复杂替换的难点不是 `\1` 怎么写，而是边界怎么定义。课程中讨论了逗号分隔字段、冒号分隔字段、`test` 开头的模式，以及 `[^,]` 这类“非逗号字符”。

视觉验证：43:51-55:07，画面演示字段调换与非逗号匹配。

![函数参数重排](<./screenshots/任务008_gvim正则表达式/08_swap_fields_43m51s.jpg>)

这张图要看逗号、括号和参数之间的边界。处理函数参数、端口列表、CSV 时，`[^,]*` 这种“非分隔符字段”通常比 `.*` 更安全。

例如要处理逗号分隔字段，常用 `[^,]` 表示“不是逗号的字符”：

```vim
:%s/^\([^,]*\),\([^,]*\),\([^,]*\)$/\2,\1,\3/g
```

输入：

```text
A,B,C
```

输出：

```text
B,A,C
```

这个例子能说明正则的工程原则：不要用 `.*` 贪婪吞掉所有内容，能写清边界就写边界。处理 RTL 端口、CSV、filelist、约束脚本时，边界通常是逗号、空格、括号、分号、冒号或行尾。

## 9. 函数式替换：替换结果可以由表达式计算

gvim 替换区如果以 `\=` 开头，后面可以接表达式，替换结果由表达式计算出来。课程用“把 ID 字符串替换为行号”“把每行开头单词替换成行号减十”说明这个能力。

视觉验证：56:48-59:04，画面讲解 `\=` 后接函数式表达式，以及 `line(".")` 表示当前行号。

![函数式替换](<./screenshots/任务008_gvim正则表达式/10_sed_usage_59m20s.jpg>)

这张图要看替换结果来自表达式计算。函数式替换像给每个匹配点装了一个小计算器，适合编号和生成临时标记，但也更应该先限定行号范围测试。

示例：

```vim
:%s/\<ID\>/\=line(".")/g
:%s/^\w\+/\=line(".")-10/g
```

用途：

- 给行自动编号。
- 根据行号生成临时标记。
- 批量构造测试数据或脚本片段。

风险：函数式替换更强，也更容易误伤。必须先用小范围测试，例如：

```vim
:10,20s/\<ID\>/\=line(".")/g
```

确认结果正确后，再扩大到全文件。

## 10. 正则在 RTL 工程里的安全用法

正则能大幅提高速度，也能大幅扩大错误影响面。工程里不要直接对全文件、全工程做高风险替换。

### 10.1 推荐流程

1. 先搜索，不替换：

```vim
/pattern
```

2. 小范围替换：

```vim
:10,30s/pattern/replace/gc
```

3. 加 `c` 逐个确认：

```vim
:%s/old/new/gc
```

4. 替换后再次搜索旧名字：

```vim
/old
```

5. 用 diff 审查修改。

### 10.2 RTL 示例：批量改信号名

假设要把独立单词 `id` 改为 `instr_id`，不要直接替换所有 `id`，否则 `valid`、`id_next`、`bridge_id` 都可能被错误影响。

更安全的写法：

```vim
:%s/\<id\>/instr_id/gc
```

`\ <` 和 `\>` 表示单词边界，能避免匹配到其他单词内部的 `id`。

### 10.3 filelist 示例：每行加路径前缀

```vim
:%s/^/../rtl\//g
```

执行后检查：

- 空行是否也被加了前缀？
- 注释行是否应该跳过？
- 相对路径是否相对于仿真命令工作目录？

如果要跳过空行和注释行，不能只靠一条简单替换硬上，要先定义清楚匹配范围。

## 11. 最后速记

### 11.1 本章最该记住的结论

- `:%s/pattern/replace/g` 替换行内片段；`:g/pattern/d` 对匹配整行执行命令。
- `^`、`$` 是位置，不是字符；`^$` 只匹配完全空行。
- `[abc]` 匹配一个候选字符，不是字符串 `abc`。
- `\(...\)` 捕获片段，`\1`、`\2` 在替换区复用片段。
- 字段重排的关键是边界，不是正则写得越长越好。
- 批量替换必须先小范围测试，再全文件执行，最后 diff 审查。

### 11.2 自测题

1. `:%s/old/new/g` 中 `%` 和最后的 `g` 分别表示什么？  
   答案要点：`%` 表示全文件范围；最后 `g` 表示一行内所有匹配都替换。

2. 为什么 `:g/^$/d` 删除不了只含空格的行？  
   答案要点：`^$` 要求行首后立刻行尾；含空格的行中间有空白字符，应使用 `^\s*$`。

3. `[abc]` 和 `abc` 有什么区别？  
   答案要点：`[abc]` 匹配一个字符 a/b/c 任一；`abc` 匹配连续字符串 abc。

4. `\1` 是什么？  
   答案要点：它是第一组 `\(...\)` 捕获到的内容，可在替换结果中复用。

5. 批量改 RTL 信号名前为什么要用单词边界？  
   答案要点：避免把其他标识符内部的同名片段误替换，例如 `valid` 中的 `id`。

### 11.3 实践动作

在一个临时文本文件中写入：

```text
Help
help

ABC : XYZ
id valid id_next id
```

依次练习：

```vim
:%s/[Hh]elp/HELP/g
:g/^\s*$/d
:%s/^\(.*\) : \(.*\)$/\2 : \1/g
:%s/\<id\>/instr_id/gc
```

检查结果是否符合预期，并说明每条命令的匹配对象和替换对象。
