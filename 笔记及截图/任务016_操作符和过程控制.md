# 任务16：操作符和过程控制

## 本章知识全景图

### 1. 一眼看懂这讲在讲什么

- 本章主题：SystemVerilog 的操作符和过程控制不是软件语法练习，而是在决定位宽、X 传播、MUX、优先级、latch、寄存器更新和可综合边界。
- 核心概念：数字格式、4-state、算术/关系/逻辑/位运算、拼接、移位、`==`/`===`/wildcard equality、强制类型转换、阻塞/非阻塞赋值、`if/else`、`case`、`unique`、`priority`、`casez`、`casex`、循环、`wait`、延时。
- 逻辑主线：表达式先看位宽和符号，条件先看 X/Z 会不会被掩盖，分支先看会综合成 MUX、优先级还是 latch，赋值先看是组合计算还是时序寄存器更新。

## 1. 数字格式先写清位宽和符号

数字字面量的格式决定位宽、符号、扩展、截断和比较结果。写 RTL 时，常量越靠近地址、计数器、掩码和总线字段，越应该显式写位宽。

![数字格式与基础语法](<./screenshots/任务016_操作符和过程控制/number_formats_160s.jpg>)

视觉核验：视频 00:30-04:30，画面讲注释、二进制/十进制/十六进制和 `X/Z`；读者应确认 `X/Z` 是 4-state 语义的一部分，不是显示异常。

注释：

```systemverilog
// 单行注释

/*
  多行注释
*/
```

数字格式：

```systemverilog
4'b1010
8'hA5
16'd1024
32'hDEAD_BEEF
8'shFF
```

可按下面理解：

```text
位宽 ' 符号性 基数 数值
```

`8'shFF` 是 8-bit signed 十六进制值，`8'hFF` 是 8-bit unsigned 十六进制值。下划线只增强可读性，不改变数值。

## 2. 操作符先分清整体真假和逐 bit 运算

逻辑操作符把表达式整体当真假判断，位操作符逐 bit 计算。多 bit 总线中混用两者，是 RTL 里很常见的隐蔽错误。

![操作符总览](<./screenshots/任务016_操作符和过程控制/operators_overview_700s.jpg>)

视觉核验：视频 05:00-12:00，画面按类别讲算术、关系、逻辑、位运算、移位和拼接；读者应把每类操作符和结果位宽联系起来。

| 类别 | 操作符 | 硬件直觉 |
|---|---|---|
| 算术 | `+ - * / %` | 加法器、减法器、乘法器、取模逻辑 |
| 关系 | `< <= > >=` | 比较器 |
| 逻辑 | `! && ||` | 整体真假判断 |
| 位运算 | `~ & | ^ ~^` | 每 bit 独立逻辑 |
| 移位 | `<< >> <<< >>>` | 移位网络、符号扩展相关 |
| 条件 | `?:` | 二选一 MUX |
| 拼接 | `{}` | 位向量拼接 |
| 比较 | `== != === !== ==? !=?` | 数值比较、全等比较、通配比较 |

对比：

```systemverilog
if (a && b)  // a、b 是否整体为真
if (a & b)   // a、b 每一位相与
```

如果 `a` 和 `b` 是多 bit 总线，`&&` 更像“是否非零”，`&` 产生逐 bit 结果。写掩码逻辑用 `&`，写条件判断通常用 `&&`。

## 3. 拼接和移位直接决定位宽结构

拼接不是字符串相加，而是硬件位向量重组。移位也不是抽象数学动作，而会生成连接、移位网络或符号扩展逻辑。

```systemverilog
logic [7:0] a;
logic [2:0] b;

assign a = {5'b0, b};  // 高 5 位补 0，低 3 位来自 b
```

这段代码把 3-bit 信号扩展成 8-bit。对 NPU/总线设计，拼接常用于 opcode、地址字段、byte lane、mask 和 payload 打包。写拼接时最重要的是总位宽必须对上，不能靠工具隐式扩展猜你的意图。

移位也要分清：

- `<<` / `>>`：逻辑移位，通常补 0。
- `<<<` / `>>>`：算术移位，右移时可能保留符号位。

signed/unsigned 与移位一起出现时要格外谨慎，尤其是量化、地址计算和定点算术。

## 4. `if` 遇到 X/Z 可能把未知态吞掉

条件语句在仿真中遇到 `X/Z` 时，可能走确定分支，让波形看起来稳定，但真实硬件选择信号未知时并不稳定。

![if 条件中的 X 处理](<./screenshots/任务016_操作符和过程控制/logic_if_x_270s.jpg>)

视觉核验：视频 12:00-18:00，画面讲比较中出现未知态和高阻态时的结果；读者应警惕 `if` 条件把 `X` 静默变成某个分支输出。

示例：

```systemverilog
logic sel;
logic y;

always_comb begin
    if (sel)
        y = 1'b1;
    else
        y = 1'b0;
end
```

当 `sel = 1'bx` 时，仿真条件语义可能让代码走 `else`，于是 `y` 看起来是确定的 `0`。但硬件上的 MUX select 未知，输出本应存在未知风险。关键控制信号应通过断言、波形检查或 `$isunknown()` 暴露异常。

## 5. `==`、`===` 和通配比较要按检查目标选择

`==` 是逻辑相等，遇到 `X/Z` 结果可能为 `X`；`===` 是 case equality，把 `X/Z` 也当作可比较值；`==?` 是通配比较，右侧的 `X/Z/?` 可作为 don't care。

![类型转换与比较操作](<./screenshots/任务016_操作符和过程控制/type_casting_850s.jpg>)

视觉核验：视频 14:00-25:00，画面讲存在未知态/高阻态时的比较结果，并进入类型转换；读者应区分数值比较、全等比较和通配比较的用途。

```systemverilog
logic [1:0] a = 2'b1x;
logic [1:0] b = 2'b1x;

// a == b   结果可能是 X
// a === b  结果是 1
```

使用建议：

| 场景 | 推荐 |
|---|---|
| 普通 RTL 条件 | 谨慎用 `==`，避免把 `X` 当合法业务值 |
| TB 检查是否包含未知态 | `===`、`!==`、`$isunknown()` |
| scoreboard 需要逐位连 X 也匹配 | `===` |
| 带 don't care 的模式匹配 | 谨慎用 `==?`，明确通配位置 |

不要为了让仿真“通过”而用 `===` 掩盖 RTL 的未知态传播。检查语句可以认识 X，设计逻辑不能随便把 X 当正常状态。

## 6. 类型转换改变位宽和符号解释

强制类型转换不是格式化显示，而是改变表达式的位宽、signed/unsigned 解释和扩展/截断方式。

```systemverilog
int'(expr)
logic [7:0]'(expr)
signed'(expr)
unsigned'(expr)
```

写 cast 时必须问：

1. 目标位宽是多少？
2. 目标是否有符号？
3. 扩展时补 0 还是符号扩展，截断时会丢哪几位？

在 AI/IC 中，这类 bug 常出现在量化数据、累加器、地址计算、比较器和移位运算里。8-bit 激活值、16-bit 权重、32-bit 累加值混合计算时，signed/unsigned 写错会直接改变数值含义。

## 7. 阻塞/非阻塞赋值决定仿真调度语义

组合逻辑用阻塞赋值表达“当前过程内立即算出中间结果”，时序逻辑用非阻塞赋值表达“同一时钟沿采样旧值并统一更新寄存器”。

| 场景 | 推荐赋值 | 含义 |
|---|---|---|
| `always_comb` | `=` | 当前过程内按顺序计算组合中间值 |
| `always_ff @(posedge clk)` | `<=` | 所有寄存器同一时钟沿基于旧值更新 |
| testbench 驱动/采样 | 视调度目的选择 | 必须明确是否模拟同拍采样或延迟驱动 |

对比：

```systemverilog
always_ff @(posedge clk) begin
    a <= b;
    b <= a;
end
```

这会交换旧的 `a/b`。如果写成阻塞赋值：

```systemverilog
always_ff @(posedge clk) begin
    a = b;
    b = a;
end
```

第二句读到的是已经被第一句改写后的 `a`，仿真语义会制造“寄存器不是同沿更新”的错觉。后续 RTL 编码课还会深入讲，但本章先记住：组合用 `=`，时序用 `<=` 是最基本的安全边界。

## 8. `if/else` 是 MUX 或优先级，不只是软件跳转

RTL 里的 `if/else` 更像条件选择硬件连接。多个 `else if` 往往表达优先级链，条件越多，路径可能越长。

![if/else 顺序控制](<./screenshots/任务016_操作符和过程控制/if_else_flow_1705s.jpg>)

视觉核验：视频 30:00-35:00，画面讲 `if/else`、`begin/end` 和过程控制；读者应把它映射为 MUX 或优先级选择，而不是只按软件执行流理解。

组合逻辑中必须保证所有路径都有赋值：

```systemverilog
always_comb begin
    y = '0;       // 默认值，避免 latch
    if (en)
        y = data;
end
```

默认值不是为了代码整齐，而是为了告诉综合器：没有分支命中时，输出也由明确逻辑驱动，不需要记住旧值。

## 9. 循环在 RTL 中通常是展开硬件

软件循环是运行时重复执行，RTL 中固定次数 `for` 通常会在综合时展开成多份硬件或多条连接。

![循环、break 和 continue](<./screenshots/任务016_操作符和过程控制/loops_break_continue_1905s.jpg>)

视觉核验：视频 31:00-35:00，画面讲 `repeat/for/foreach/while/do-while/break/continue`；读者应区分固定展开和仿真运行时循环。

```systemverilog
for (int i = 0; i < 4; i++) begin
    mask[i] = req[i] & grant_en;
end
```

这通常不是“运行 4 拍”，而是生成 4 路并行逻辑。可综合 RTL 中的循环要满足：

- 次数在综合前可确定。
- 每次迭代对应固定硬件结构。
- 不依赖运行时动态退出条件生成不确定硬件。

`while`、`do-while`、`break/continue` 在 testbench 中很常见，放进 RTL 时必须确认工具支持和硬件边界。说不清会展开成什么，就先当作 TB 结构。

## 10. `case`、`unique`、`priority` 描述多路选择的意图

`case` 常用于译码和多路选择。`unique` 表达分支应互斥，`priority` 表达分支有优先级。乱加这些关键字会把设计意图写错。

![case 语句基础](<./screenshots/任务016_操作符和过程控制/case_statement_2135s.jpg>)

视觉核验：视频 35:00-38:00，画面讲 `case/endcase`、`default` 和分支形式；读者应检查分支覆盖、默认赋值和是否存在优先级。

```systemverilog
always_comb begin
    y = '0;
    unique case (opcode)
        2'b00: y = a + b;
        2'b01: y = a - b;
        2'b10: y = a & b;
        2'b11: y = a | b;
        default: y = '0;
    endcase
end
```

![unique 和 priority case](<./screenshots/任务016_操作符和过程控制/unique_priority_case_2185s.jpg>)

视觉核验：视频 37:00-40:00，画面讲 `unique` 与 `priority`；读者应确认互斥分支用 `unique`，真实仲裁优先级用 `priority`。

| 结构 | 硬件直觉 | 风险 |
|---|---|---|
| `if/else if/else` | 优先级选择链 | 不需要优先级时可能增加路径复杂度 |
| `case` | 多路选择 | 覆盖不全可能推断 latch |
| `unique case` | 互斥译码/MUX | 分支重叠或遗漏应报警 |
| `priority case` | 优先级译码 | 误用会掩盖本应互斥的条件 |

`unique` 不是“优化魔法词”。如果条件不互斥，仿真警告是在帮你发现设计错误。

## 11. `casez/casex` 通配越强，越容易隐藏 bug

`casez` 把 `Z/?` 当 don't care，`casex` 把 `X/Z/?` 都当 don't care。`casex` 尤其危险，因为它可能把真实未知态当通配符吞掉。

![casez 与 casex 的 don't care](<./screenshots/任务016_操作符和过程控制/casez_casex_2495s.jpg>)

视觉核验：视频 40:00-45:00，画面讲 `casez/casex` 和问号通配；读者应特别检查 `X` 是否被当作 don't care 隐藏。

| 语句 | 通配范围 | 建议 |
|---|---|---|
| `case` | 不通配 `X/Z` | 普通 RTL 优先 |
| `casez` | `Z/?` 通配 | 可用于清晰标注的掩码译码 |
| `casex` | `X/Z/?` 都通配 | 可综合 RTL 中尽量避免 |

控制逻辑和状态机中应优先使用普通 `case` 或 `unique case` 加默认处理。若必须用 `casez`，要让 `?` 的含义可审查；不要让输入里的未知 `X` 静默命中某个分支。

## 12. `wait`、延时和事件控制主要服务仿真

`wait`、`#` 延时、事件等待在 testbench 中很常见，用于驱动激励、等待时钟沿或模拟时间间隔；它们通常不可综合。

```systemverilog
wait (ready);
@(posedge clk);
#5 data = next_data;
```

这类语句描述的是仿真时间调度，不是固定硬件结构。RTL 里真正的等待通常要写成状态机：一个状态等待条件，条件满足后转移到下一个状态。不要把 testbench 的 `wait/#delay` 直接搬进设计代码。

## 13. 推荐 RTL 模板

```systemverilog
always_comb begin
    y = '0;
    unique case (opcode)
        3'b000: y = a + b;
        3'b001: y = a - b;
        3'b010: y = a & b;
        3'b011: y = a | b;
        default: y = '0;
    endcase
end

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= '0;
    else
        q <= y;
end
```

这份模板体现了五个边界：

- 常量和信号位宽明确。
- 组合逻辑先给默认值。
- 分支互斥才使用 `unique`。
- 时序寄存器用非阻塞赋值。
- 非法或未覆盖情况有默认处理。

## 14. 审查练习：从代码找硬件风险

给定代码：

```systemverilog
always_comb begin
    casez (opcode)
        3'b00?: y = a + b;
        3'b010: y = a & b;
    endcase
end

always_ff @(posedge clk) begin
    a = b;
    b = a;
end

for (int i = 0; i < 4; i++) begin
    mask[i] = req[i] & grant_en;
end
```

审查结果：

| 片段 | 风险 | 修改口径 |
|---|---|---|
| `always_comb` 无默认值 | 未命中分支时 `y` 可能推断 latch | 开头写 `y = '0;`，或补齐 `default` |
| `casez` | `?` 通配可能掩盖部分编码错误 | 确认通配位是设计意图；必要时用 `unique casez` 加断言 |
| 时序块用 `=` | 仿真中读写顺序可能错误 | 改为 `a <= b; b <= a;` |
| `for i < 4` | 固定展开为 4 路硬件 | 可接受，但要确认 `mask/req` 位宽至少 4 |

修正示例：

```systemverilog
always_comb begin
    y = '0;
    unique casez (opcode)
        3'b00?: y = a + b;
        3'b010: y = a & b;
        default: y = '0;
    endcase
end

always_ff @(posedge clk) begin
    a <= b;
    b <= a;
end
```

## 15. 深层理解：操作符是在布线，不是在写算术题

SystemVerilog 操作符看起来像软件表达式，但在 RTL 里它们会落成线、门、MUX、比较器、加法器、移位网络和优先级结构。写 `a + b`，工具可能生成加法器；写 `sel ? x : y`，工具可能生成 MUX；写不完整 `if/case`，工具可能为了“记住旧值”推断 latch。每个符号都像在原理图上多接一段线，不能只按软件直觉读。

几个高风险心智模型：

| 语法点 | 软件直觉 | RTL 直觉 |
|---|---|---|
| `&&` | 条件真假 | 把多 bit 表达式整体归约成真假判断 |
| `&` | 也是与 | 逐 bit 并行与门，结果位宽随操作数变化 |
| `==` | 相等就是 true/false | 遇到 X/Z 可能产生未知，条件分支会吞掉不确定性 |
| `case` | 多分支跳转 | 多路选择器、优先级选择器或译码结构 |
| `for` | 运行时循环 | 固定次数通常被展开成重复硬件 |
| `<=` | 赋值 | 时钟边沿采样旧值，统一更新寄存器 |
| `#5` / `wait` | 等一下 | 仿真时间控制，不是固定硬件结构 |

最可靠的审查方法是“从代码反推硬件”：每看到一个表达式，就问它会变成多少根线、多少级逻辑、是否有优先级、是否有未覆盖路径、X 会不会被吞掉。

## 16. 配图复盘与风险定位

| 配图 | 读图重点 | 关键风险 |
|---|---|---|
| 数字格式与基础语法 | 位宽、进制、符号位是否写清 | 隐式位宽和符号扩展导致截断或比较错误 |
| 操作符总览 | 操作符类别和结果形态 | 把逻辑操作符和位操作符混用 |
| if 条件中的 X | X 在条件判断中的传播 | 未知态被当成普通分支处理，bug 被隐藏 |
| 类型转换与比较操作 | cast、`==/===` 的检查目的 | TB 和 RTL 误用同一套比较语义 |
| if/else 顺序控制 | 分支顺序和默认值 | 优先级链过长、漏赋值推 latch |
| 循环、break、continue | 循环边界是否固定 | 把软件循环误认为硬件多拍执行 |
| case 语句基础 | case item 覆盖是否完整 | default 缺失、重复命中、非法编码未处理 |
| unique/priority case | 意图声明和检查能力 | 声明与实际编码不一致 |
| casez/casex | don't care 如何匹配 | 真实 X 被通配吞掉，控制错误难发现 |

## 17. 操作闭环：写完一段 RTL 后的五步检查

```text
1. 标位宽：每个常量、拼接、移位、加法结果是否有明确宽度。
2. 查 X：条件、比较、case 是否可能把 X/Z 当成合法路径。
3. 查全赋值：组合逻辑所有路径是否驱动输出，是否有 default。
4. 查时序：always_ff 是否只用非阻塞，reset/enable 是否完整。
5. 查可综合：#delay、wait、动态循环、TB 方法是否误进 RTL。
```

这五步像 RTL 的安检门：语法通过只是拿到了登机牌，过安检才知道有没有危险物品。

## 复习与自测

1. `&&` 和 `&` 的区别是什么？
   - 答案要点：`&&` 把表达式整体当真假判断；`&` 逐 bit 运算。多 bit 总线中混用会改变硬件含义。

2. `==` 和 `===` 遇到 `X/Z` 时有什么区别？
   - 答案要点：`==` 结果可能为 `X`；`===` 把 `X/Z` 当可比较值。TB 检查未知态可用 `===`，RTL 条件中要谨慎，避免把未知态当合法业务值。

3. 为什么组合逻辑漏默认赋值会推断 latch？
   - 答案要点：某些路径未赋值时，输出必须保持旧值才能有定义；保持旧值对应 latch。默认值给所有路径明确驱动。

4. 固定次数 `for` 在 RTL 中通常表示什么？
   - 答案要点：综合时展开成重复硬件或连接，不是运行多拍。次数必须在综合前确定。

5. 为什么时序逻辑推荐用非阻塞赋值？
   - 答案要点：非阻塞表达同一时钟沿采样旧值并统一更新，符合寄存器并行更新模型；阻塞赋值会引入过程内读写顺序错觉。

6. `casex` 为什么危险？
   - 答案要点：它把 `X/Z/?` 都当通配，输入中的真实未知态可能被吞掉并命中某分支，隐藏控制逻辑 bug。

7. `wait` 和 `#5` 为什么通常不属于可综合 RTL？
   - 答案要点：它们描述仿真时间调度，不对应固定硬件结构；RTL 等待应建模为状态机和寄存器转移。

## 工程核对口径

本章合格不是“知道有哪些操作符”，而是能做 RTL review：

1. 能解释每个表达式的结果位宽和符号解释。
2. 能指出 X/Z 在条件、比较和 case 中可能怎样被隐藏。
3. 能把 `if/case/for` 翻译成 MUX、优先级、译码和展开硬件。
4. 能判断一段代码是可综合 RTL，还是只适合 testbench。
5. 能用默认赋值、`unique/priority`、明确位宽和非阻塞赋值降低 bug 风险。
