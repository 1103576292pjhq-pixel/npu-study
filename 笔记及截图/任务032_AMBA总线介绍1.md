## 1. AMBA 解决片内模块共享通信规则

SoC 中有 CPU、DMA、memory、UART、Timer、GPIO、SPI 等模块。如果每两个模块都单独定义连接，系统会迅速失控。总线协议提供统一规则：谁发地址、谁响应、读写怎么区分、数据什么时候有效、忙的时候如何等待。

![AMBA/AHB/APB/AXI 概览](<./screenshots/任务032_AMBA总线介绍1/amba_ahb_apb_axi_overview_140s.jpg>)

视觉核验：视频 00:45-04:00，画面承担“建立 AMBA 家族坐标系”的教学职责。看图要点：AHB、APB、AXI 不是同一个接口的不同名字，而是面向不同性能、复杂度和对象的协议层；本项目先抓 AHB 主干和 APB 外设。如果看不懂，会把协议选择当成命名偏好，后续无法解释为什么高速 DMA 不该直接按 APB 思路实现。

![系统总线角色](<./screenshots/任务032_AMBA总线介绍1/amba_protocol_role_380s.jpg>)

视觉核验：视频 04:00-07:00，画面承担“把通信拆成事务字段”的教学职责。看图要点：一次事务至少包含地址、读写方向、数据、ready/wait、response/error，协议规定这些字段何时有效、由谁驱动、何时结束。如果看不懂，会只记住连线名字，看不出波形里哪一拍才算完成。

一句话：总线协议把“每个模块私下拉线”改成“所有模块按同一套事务规则通信”。

一个准确比喻：AMBA 像 SoC 内部的交通规则，不是某一辆车。CPU、DMA、memory、bridge 是车和路口；协议规定谁能先走、到哪个窗口办事、办完怎么签收、出错怎么退回。这个比喻的边界是：硬件协议比交通更严格，ready/response 每拍都要可判定，不能靠“差不多会到”。

## 2. AHB、APB、AXI 的定位不同

本项目重点使用 AHB 和 APB。AXI 更高性能、更复杂，本章只建立位置感。

| 协议 | 典型定位 | 复杂度 | 常见对象 |
|---|---|---|---|
| AHB | 较高性能片内总线 | 中等 | CPU、DMA、memory、APB bridge |
| APB | 低功耗、低复杂度外设总线 | 低 | UART、Timer、GPIO、寄存器型外设 |
| AXI | 高性能、高并发互连 | 高 | 高带宽 CPU/NPU/DDR/NoC |

AHB + APB 是基础 SoC 的常见组合：高速主干负责 CPU/DMA/memory，低速寄存器外设通过 APB bridge 接入。

## 3. 典型结构：AHB 主干 + APB 外设

AHB 主干连接高性能 master 和 slave；APB bridge 把访问转给低速 APB 外设。这样低速外设不用实现复杂 AHB 协议，高速主干也不会被外设细节污染。

![典型 AMBA 系统](<./screenshots/任务032_AMBA总线介绍1/ahb_apb_soc_arch_640s.jpg>)

视觉核验：视频 08:00-12:00，画面承担“解释 AHB 主干 + APB 外设分层”的教学职责。看图要点：CPU/DMA/memory 走 AHB 高速路径，UART/Timer/GPIO 通过 APB bridge 接入，bridge 同时承担二级译码和等待传播。如果看不懂，会把 APB bridge 当成简单连线，漏掉协议转换、PREADY 等待和错误回传。

分层价值：

- 高速路径保留在 AHB 主干。
- UART/Timer/GPIO 这类外设使用简单 APB 协议。
- APB bridge 负责协议转换和等待传播。
- 地址译码决定一次访问落到 memory、bridge 还是其他 slave。

这就是 SoC 中“主干总线 + 外设桥”的基本结构。

## 4. master/slave：主动发起与被动响应

master 发起访问，slave 响应访问。CPU 通常是 master；memory、外设寄存器、APB bridge 通常是 slave；DMA 在不同阶段有不同角色。

![DMA 也可以是 master](<./screenshots/任务032_AMBA总线介绍1/dma_as_master_820s.jpg>)

视觉核验：视频 12:00-15:00，画面承担“打破 CPU 唯一 master 的误解”的教学职责。看图要点：DMA 配置阶段被 CPU 写寄存器，是 slave；搬运阶段由 DMA 发起读写，是 master；arbiter 必须处理 CPU/DMA 同时访问主干的场景。如果看不懂，会在设计 DMA 时只写 APB/AHB slave 寄存器，忘记 DMA master 读写通道和仲裁请求。

| 角色 | 行为 |
|---|---|
| master | 发地址、控制、读写方向，请求使用总线 |
| slave | 被地址选中后返回数据、ready 或 error |
| arbiter | 多 master 同时请求时决定谁获得总线 |
| decoder | 根据地址选择目标 slave |

外设通常不能主动把数据“推给 CPU”。它一般通过中断提示 CPU，再由 CPU 或 DMA 作为 master 去读写。

判断 master/slave 的可复现口径：谁在当前拍给出有效地址和读写控制，谁就是 master；谁被地址选中并返回 data/ready/response，谁就是 slave。不要按模块名字判断，DMA、bridge、甚至某些外设控制器都可能在不同方向上扮演不同角色。

## 5. AHB 性能来自流水、burst 和总线位宽

AHB 面向片内较高性能传输，支持地址/数据阶段重叠、burst 传输和不同总线位宽。

![burst 和 bus width](<./screenshots/任务032_AMBA总线介绍1/burst_bus_width_1060s.jpg>)

视觉核验：视频 15:00-19:00，画面承担“把总线性能拆成 burst 长度和位宽”的教学职责。看图要点：burst 决定一次获得总线后连续搬多少拍，bus width 决定每拍搬多少 byte；二者共同影响 DMA/NPU 数据搬运吞吐。如果看不懂，会只说“总线宽一点更快”，却不能解释仲裁开销、地址阶段开销和 burst 效率。

burst 的直觉：

```text
单次传输：request -> grant -> address/data -> 结束
burst 传输：request -> grant -> 连续 address/data/data/data -> 结束
```

总线位宽决定每拍搬运能力。32-bit 总线一拍 4 byte，64-bit 一拍 8 byte。但位宽越大，布线、面积、功耗和 slave 支持成本也更高。

对 NPU/DMA 来说，burst 和位宽直接影响权重、激活、输出数据搬运效率。

工程上要把性能问题问成可计算问题：传 1024 byte 数据，32-bit 总线需要 256 拍数据传输，64-bit 总线需要 128 拍；如果每个 word 都重新仲裁，控制开销会放大，burst 可以把多拍数据合成一段事务。

## 6. AHB 系统四件套：master、slave、arbiter、decoder

AHB 系统先抓四个对象，就能读懂大多数结构图。

![AHB 组成部分](<./screenshots/任务032_AMBA总线介绍1/ahb_components_1530s.jpg>)

视觉核验：视频 23:00-27:00，画面承担“建立 AHB 四件套工作顺序”的教学职责。看图要点：master 发请求，arbiter 给授权，decoder 按地址选 slave，slave 返回 ready/data/response；四件套缺一环，事务就不能闭合。如果看不懂，会在波形 debug 时只盯 HADDR，不知道还要查 HGRANT/HSEL/HREADY/HRESP。

| 组成 | 作用 | 常见设计问题 |
|---|---|---|
| master | 发起访问 | 请求/授权、burst、错误处理 |
| slave | 响应访问 | ready、read data、error、地址窗口 |
| arbiter | 多 master 仲裁 | 优先级、公平性、饥饿 |
| decoder | 地址译码 | base/size、地址冲突、default slave |

仲裁算法不由 AMBA 固定，可以是固定优先级、round-robin 或带权重策略。协议规定接口行为，架构决定策略。

可以把 arbiter 和 decoder 想成两个不同岗位：arbiter 是排队叫号，决定哪位 master 先到窗口；decoder 是分诊台，决定这个地址应该去哪个 slave 窗口。把这两个岗位混了，就会把“谁能发起访问”和“访问落到哪里”两个问题纠缠在一起。

## 7. APB bridge 是协议转换器，不是简单连线

APB 适合低速寄存器外设。APB bridge 接收 AHB 访问，锁存地址/控制/数据，产生 APB 的 `PSEL/PENABLE/PWRITE/PADDR/PWDATA`，等待 `PREADY`，再把读数据或错误返回 AHB。

![APB bridge](<./screenshots/任务032_AMBA总线介绍1/apb_bridge_low_speed_1280s.jpg>)

视觉核验：视频 20:00-23:00，画面承担“说明 bridge 不是 wire，而是事务状态机”的教学职责。看图要点：bridge 在 AHB 侧接收地址/控制/写数据，在 APB 侧产生 PSEL/PENABLE/PADDR/PWRITE/PWDATA，并把 PREADY/PRDATA/PSLVERR 转回 AHB。如果看不懂，会漏掉 AHB 等待插入，导致上游 master 以为访问已完成而 APB 外设还没完成。

![APB 组成与译码](<./screenshots/任务032_AMBA总线介绍1/apb_components_decode_1880s.jpg>)

视觉核验：视频 29:00-33:00，画面承担“展示 APB 二级译码”的教学职责。看图要点：AHB decoder 先选中 APB bridge，bridge 内部再按低位/子地址选 UART、Timer、GPIO 等 APB slave；PSEL 必须 one-hot 或有明确优先级。如果看不懂，会把所有 APB 外设看成一个 slave，后续寄存器地址冲突和 PSEL 错选很难定位。

APB 访问两阶段：

```text
setup:  PSEL=1, PENABLE=0, PADDR/PWRITE/PWDATA 稳定
access: PSEL=1, PENABLE=1, 等 PREADY=1 后完成
```

AHB 到 APB 的关键是等待传播：APB 慢时，bridge 不能让 AHB master 误以为事务完成，必须通过 ready/wait 机制让上游等待。

## 8. 一次 AHB 到 APB 读事务怎么发生

以 CPU 读 UART status 为例：

```text
CPU/AHB master 发出地址和读控制
  -> AHB decoder 判断地址属于 APB bridge
  -> bridge 接住 AHB 访问，必要时让 AHB 等待
  -> bridge 根据低位地址产生 UART 的 PSEL
  -> APB setup 阶段：PSEL=1, PENABLE=0
  -> APB access 阶段：PSEL=1, PENABLE=1
  -> UART 在 PREADY=1 时返回 PRDATA/PSLVERR
  -> bridge 把读数据和响应返回 AHB master
```

事务追踪表：

| 阶段 | AHB 侧 | Bridge | APB 侧 | 完成条件 |
|---|---|---|---|---|
| 地址阶段 | master 给地址/读写方向 | 判断命中 bridge | 空闲 | 地址有效 |
| 等待/转换 | HREADY 可能被拉低 | 锁存地址控制 | 产生 PSEL | bridge 进入 APB setup |
| APB setup | AHB 等待 | 保持 APB 地址控制 | PSEL=1, PENABLE=0 | 下拍进入 access |
| APB access | AHB 等待 | 等 PREADY | PSEL=1, PENABLE=1 | PREADY=1 |
| 返回 | HRDATA/HRESP 有效 | 转发 PRDATA/PSLVERR | 事务结束 | HREADY 释放 |

能写出这张表，才算真正理解 bridge。

字段级观察要更具体。调波形或写 testbench 时，至少盯住这些信号：

| 观察对象 | AHB/APB 字段 | 看什么 |
|---|---|---|
| AHB 地址与方向 | `HADDR`、`HWRITE`、`HTRANS` | 地址是否命中 bridge，传输是否有效，读写方向是否正确 |
| AHB 等待与响应 | `HREADY`、`HRDATA`、`HRESP` | 慢 APB 是否正确让 AHB 等待，错误是否返回上游 |
| Bridge 锁存 | 内部地址、写数据、控制寄存器 | APB 等待期间地址和控制不能漂移 |
| APB 选择 | `PSEL`、`PADDR`、`PWRITE` | 二级译码是否选中正确外设和寄存器 |
| APB 访问阶段 | `PENABLE`、`PREADY` | `PENABLE` 后等待 `PREADY`，完成条件不能提前 |
| APB 返回 | `PRDATA`、`PSLVERR` | 读数据和错误必须被 bridge 正确带回 AHB |

一个常见 bug 是 bridge 在 `PREADY=0` 时释放或覆盖锁存信息，导致 AHB 侧看到完成，但 APB 侧实际还没稳定完成。

## 9. 协议时序不是工艺时序

AMBA 协议规定信号语义和采样关系，不规定某个工艺下 cell delay 或最高频率。协议正确、RTL 正确、timing 通过是三件不同的事。

![协议不是工艺时序](<./screenshots/任务032_AMBA总线介绍1/protocol_not_timing_library_2170s.jpg>)

视觉核验：视频 33:00-36:30，画面承担“切开协议正确和工艺时序正确”的教学职责。看图要点：AMBA 规定事务语义，RTL 实现状态机和寄存器，综合/STA 检查 cell delay 和 setup/hold，工艺库提供单元和宏模型。如果看不懂，会用 STA 通过来证明协议没 bug，或用仿真通过来证明频率一定能收敛。

| 层次 | 关心内容 |
|---|---|
| AMBA 协议 | 地址、控制、握手、传输阶段、响应 |
| RTL 实现 | 状态机、寄存器、ready、decoder、bridge |
| 综合/STA | cell delay、setup/hold、频率收敛 |
| 工艺库 | 标准单元、SRAM、IO 时序模型 |

协议写对不代表频率一定能跑到；timing 过了也不代表协议事务语义一定对。

## 10. DMA 例子把寄存器配置和总线搬运串起来

DMA 的寄存器通常包含 source address、destination address、size、control、status。CPU 先配置 DMA，DMA 再作为 master 搬运数据。

![DMA source/destination/size](<./screenshots/任务032_AMBA总线介绍1/dma_source_destination_size_2370s.jpg>)

视觉核验：视频 39:00-42:00，画面承担“把 DMA 配置寄存器变成软件可控入口”的教学职责。看图要点：source、destination、size、control/status 都是 CPU 通过总线写读的寄存器；这些字段定义了后续 DMA master 行为的输入。如果看不懂，会把 DMA 搬运看成黑盒，不知道搬错地址、长度为 0、未对齐、busy 重入应从哪个寄存器查起。

```text
CPU 写 DMA source address
CPU 写 DMA destination address
CPU 写 DMA size
CPU 写 control.start
DMA 作为 AHB master 读 source
DMA 作为 AHB master 写 destination
DMA 置位 done/status/error
DMA 发 interrupt 或等待 CPU polling
```

![DMA 读写数据流](<./screenshots/任务032_AMBA总线介绍1/dma_read_write_flow_2540s.jpg>)

视觉核验：视频 42:00-45:00，画面承担“追踪 DMA 从 slave 配置到 master 搬运的状态变化”的教学职责。看图要点：CPU 写 start 后，DMA 从 idle 进入 busy，发起 source read 和 destination write，完成后置 done 或 error，并可能发 interrupt。如果看不懂，会只看到数据“搬过去了”，却无法定位 stuck busy、bus error、done 不清除或中断丢失。

这个例子最适合训练 master/slave：同一个 DMA，配置时是 slave，搬运时是 master。

DMA 的最小状态机可以按 `idle -> programmed -> busy -> done/error -> clear` 读。输入是配置寄存器和总线响应，输出是 AHB master 访问、status/error 和 interrupt；失败信号通常是 busy 不退出、done 不置位、error code 异常、目标 buffer 数据不一致。

## 11. status、interrupt 和 polling 是事务完成后的软件契约

DMA 完成、出错或忙碌都要通过 status 反馈给 CPU。CPU 可以轮询 status，也可以等中断。

![DMA status 与 interrupt](<./screenshots/任务032_AMBA总线介绍1/dma_status_interrupt_2740s.jpg>)

视觉核验：视频 45:00-46:18，画面承担“定义完成通知和错误恢复契约”的教学职责。看图要点：interrupt 只是事件提示，status/error 才说明完成、忙、异常原因；polling 和 interrupt 只是软件等待方式不同，不能省略清状态和错误处理。如果看不懂，会写出 ISR 里不读 status、done/error 清除不一致、busy 时重复 start 的驱动 bug。

硬件必须定义：

- `ready/busy/done/error` 是否互斥。
- `start` 在 busy 时写入如何处理。
- done/error/status 如何清除。
- interrupt 是否可 mask。
- bus error、未对齐、越界如何上报。

DMA 不是只会“搬数据”的模块，它还要给软件一套可控、可查、可恢复的寄存器协议。

CPU 轮询 DMA 的最小伪流程：

```c
while (dma.status.busy) {
    /* 等待上一笔事务完成，或按超时策略退出 */
}
dma.src  = src_addr;
dma.dst  = dst_addr;
dma.size = byte_count;
dma.ctrl = DMA_START | DMA_IRQ_EN;

while (!dma.status.done && !dma.status.error) {
    /* polling 模式；中断模式下这里由 ISR 接管 */
}
if (dma.status.error) {
    /* 读 error code，判断 bus error、未对齐、越界或外设错误 */
}
dma.status = DMA_CLEAR_DONE | DMA_CLEAR_ERROR;
```

这段伪代码的学习价值不在 C 语法，而在软硬件契约：`busy` 防止重入，`done/error` 给完成原因，`clear` 定义状态生命周期，`irq_en` 决定 polling 还是 interrupt。

## 12. 工程检查表：看 AMBA 外设先问什么

| 问题 | 目的 |
|---|---|
| 接 AHB 还是 APB？ | 决定协议复杂度和性能 |
| 是 master 还是 slave？ | 决定能否主动发起访问 |
| base address 和 offset 是什么？ | 决定 decoder、软件和验证 |
| 是否需要 ready/wait？ | 决定慢设备如何拖住访问 |
| 是否支持 burst？ | 决定高吞吐数据搬运能力 |
| 是否发 interrupt？ | 决定完成/错误如何通知 CPU |
| status/error 如何清除？ | 决定软硬件交互稳定性 |
| default/error 响应怎么定义？ | 决定非法地址和异常行为 |

最小练习：手写“CPU 读 UART status”的 8 步事务链，再手写“CPU 写 DMA start 后 DMA 搬运一段数据”的角色变化。每一步都标出握手完成条件和失败先查项。

## 13. 可复现流程：两条 AMBA 事务链

把协议学实，必须能把抽象图改写成逐步事务。

### 13.1 CPU 读 UART status

| 步骤 | 对象 | 输入 | 输出/状态变化 | 失败先查 |
|---|---|---|---|---|
| 1 | CPU/AHB master | UART status 地址、读方向 | `HADDR/HWRITE=0/HTRANS` 有效 | 地址是否对齐、是否落在 APB bridge 窗口 |
| 2 | AHB decoder | `HADDR` | 选中 APB bridge | base/size 是否冲突 |
| 3 | APB bridge | AHB 地址和控制 | 锁存地址，必要时拉低 `HREADY` | `HREADY` 是否过早释放 |
| 4 | APB bridge | 子地址 | 产生 UART `PSEL` | 二级译码是否选错外设 |
| 5 | APB slave | `PSEL/PENABLE/PADDR` | `PREADY` 后返回 `PRDATA/PSLVERR` | `PREADY=0` 时地址是否保持 |
| 6 | APB bridge | `PRDATA/PSLVERR` | 转成 `HRDATA/HRESP` | 错误是否回传 |
| 7 | CPU | `HREADY=1` | 采样读数据 | 是否把 wait cycle 当完成 |
| 8 | 软件 | status bit | 判断 ready/busy/error | 是否只看中断不看状态 |

### 13.2 CPU 启动 DMA 搬运

| 阶段 | DMA 角色 | 输入 | 输出/状态变化 | 失败信号 |
|---|---|---|---|---|
| 配置 | slave | `src/dst/size/control.start` | 寄存器更新，进入 programmed/busy | 写寄存器后读回不一致 |
| 搬运 | master | source 地址、destination 地址、size | 发 AHB read/write，地址递增或 burst | `HRESP=ERROR`、busy 卡住 |
| 完成 | slave/中断源 | 最后一拍完成或错误 | `done/error/status/irq` | done 不置位、中断不来、error code 缺失 |
| 清理 | slave | 软件写 clear | 清除 done/error/irq，回到 idle | clear 语义不一致、重复启动失败 |

这两条链路的验收标准是：能指出每一步谁驱动地址，谁返回响应，等待条件是什么，出错先查哪个信号或寄存器。

## 14. 与 AI+IC 工程的连接

NPU/AI 加速器通常靠总线被 CPU 配置，靠 DMA 搬运权重、激活和输出，靠中断通知任务完成。AMBA 学得不扎实，后面写 NPU 寄存器、DMA、SRAM 访问、APB slave、AHB master 都会卡。

典型 NPU 事务：

```text
CPU 写 NPU control/start
CPU/DMA 写输入 buffer 地址、权重地址、输出地址
DMA 从 memory 搬数据到片上 SRAM
NPU 计算
DMA 写回 output
NPU/DMA 置位 done/status
interrupt 通知 CPU
```

这条链路里每一步都离不开总线协议、地址译码、寄存器状态、ready/error 和中断。

## 复习与自测

1. 为什么 APB 外设通常不直接挂在 AHB 主干上？
   - 答案要点：低速寄存器外设不需要复杂 AHB 特性；通过 APB bridge 可以降低外设复杂度，保持高速主干清晰。

2. AHB arbiter 和 decoder 的职责有什么区别？
   - 答案要点：arbiter 在多个 master 之间决定谁获得总线；decoder 根据地址选择目标 slave。

3. DMA 为什么能减轻 CPU 搬数据负担？
   - 答案要点：CPU 只配置 source/destination/size/start，DMA 后续作为 master 自动读写总线，CPU 不必逐字搬运。

4. burst 为什么能提高总线效率？
   - 答案要点：一次获得总线后连续传输多个数据，减少重复仲裁和地址开销，提高吞吐。

5. AMBA 协议正确和 STA timing 通过为什么不是同一件事？
   - 答案要点：AMBA 定义握手和事务语义；STA 检查实现电路在工艺库和约束下能否满足 setup/hold/频率。

6. CPU 读一个 APB 外设寄存器时，AHB decoder、APB bridge、APB slave 分别做什么？
   - 答案要点：decoder 判断地址命中 bridge；bridge 转换 AHB 到 APB、插入等待、返回数据；APB slave 在 PSEL/PENABLE/PREADY 下完成寄存器读。
