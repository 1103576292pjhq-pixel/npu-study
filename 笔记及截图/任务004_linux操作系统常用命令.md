# 任务04：Linux 操作系统常用命令

## 本章知识全景图

Linux 命令不能按“命令表”背，要按工程动作分组：确认位置、创建对象、删除对象、查找文件、过滤内容、保存输出、修改权限、控制进程。

| 主线 | 关键命令 | 工程问题 | 成功信号 |
|---|---|---|---|
| 文件/目录 | `touch`、`mkdir`、`rm`、`cp`、`mv`、`ls` | 创建、查看、删除、复制、移动工程文件 | 文件或目录状态按预期变化 |
| 路径导航 | `pwd`、`cd`、`.`、`..`、`~`、Tab | 确认当前目录，避免命令作用到错误位置 | 能说清当前所在路径 |
| 查找过滤 | `find`、`grep`、`diff`、管道 | 在源码和日志中定位目标 | 输出目标路径、匹配行或差异 |
| 输出留存 | `>`、`>>`、`wc`、`more` | 把屏幕输出变成可复查文件 | 生成非空日志或 filelist |
| 工具定位 | `which`、`whereis`、`man` | 确认命令来自哪里，查命令怎么用 | 能看到命令路径或手册 |
| 权限/进程 | `chmod`、`Ctrl+Z`、`fg`、`Ctrl+C` | 在共享服务器上控制访问和程序状态 | 权限位或进程状态按预期变化 |

最短学习路径：先会 `pwd/ls/touch/mkdir/rm`，再会 `find/grep/重定向`，最后掌握 `chmod` 和前后台控制。前端工程里，生成 filelist、查 module、读日志、改权限都靠这些组合。

Linux 命令要像“工程现场工具箱”来学：`pwd/ls` 是先看自己站在哪里，`rm/cp/mv` 是搬动和拆除材料，`find/grep` 是在仓库里定位零件，`>` 和 `|` 是把中间结果送到下一道工序，`chmod` 是给协作者开门或关门。这个比喻的边界是：命令不是玩具，尤其删除和权限会真实改变工程状态。

## 1. 文件和目录：先分清对象类型

`touch` 创建文件，`mkdir` 创建目录。这个区别非常基础，但它决定你能不能正确组织工程目录、日志文件、脚本文件和结果文件。

```bash
touch test.log
ls -l test.log
mkdir logs
ls -ld logs
```

![touch 创建文件](<./screenshots/任务004_linux操作系统常用命令/touch_create_0120s.jpg>)

视频验证：`01:14-02:00`，画面应看到老师用 `touch` 创建一个 `.log` 文件，并用 `ll/ls` 查看文件属性。

这张图只看“动作后有证据”：`touch` 后文件列表出现目标文件，才算创建成功。命令没有报错但文件不在预期目录，仍然是失败。

这一步的判断口径是：命令执行后，文件列表里是否出现了目标文件；如果没有出现，先查当前目录，再查文件名是否敲错。

## 2. 删除命令的重点是风险分级

`rm` 会真实修改文件系统。`-i` 删除前确认，`-f` 强制删除，`-r` 递归删除目录，`-v` 显示删除过程。工程上优先记风险级别，不要把 `rm -rf` 当成高级技巧。

![rm 交互确认](<./screenshots/任务004_linux操作系统常用命令/rm_confirm_0310s.jpg>)

视频验证：`03:10-03:25`，画面应看到 `rm -i` 提示是否删除，输入 `yes` 后文件消失。

这张图要看交互确认，而不是只看 `rm`。`-i` 相当于删除前的最后一道确认闸门，适合初学阶段和不确定路径时使用。

删除前的安全三步：

```bash
pwd
ls <target>
rm -ri <target>
```

| 步骤 | 目的 |
|---|---|
| `pwd` | 确认自己站在哪个目录 |
| `ls <target>` | 确认目标确实是要删的文件或目录 |
| `rm -ri <target>` | 用递归加交互确认降低误删风险 |

很多工程事故不是命令不会用，而是当前目录判断错。删除之前先确认位置，这是 Linux 训练里最早要养成的安全习惯。

## 3. 路径意识：`pwd` 是所有危险命令前的刹车

`pwd` 打印当前绝对路径；`cd` 切换目录；`.` 表示当前目录；`..` 表示父目录；`~` 表示当前用户家目录；Tab 补全用来减少路径输入错误。

路径错误会造成三类常见问题：

| 错误 | 后果 | 先查 |
|---|---|---|
| 以为在工程目录，实际在家目录 | `find` 找不到源文件，日志写错位置 | `pwd` |
| 相对路径写错 | `cp/mv/rm` 作用到错误对象 | `ls <target>` |
| 目录未创建就写入 | 输出文件生成失败 | `mkdir -p` |

前端项目里，路径意识直接影响 filelist、仿真脚本、综合脚本和报告路径。先确认位置，再执行动作。

## 4. `find`：从人工翻目录升级到递归搜索

当工程目录里有很多 RTL、testbench、脚本和日志时，人工一级一级找文件会很低效。`find` 会递归遍历目录树，按文件名、类型、大小、权限等条件找目标。

典型前端用法是生成 Verilog filelist：

```bash
find . -name "*.v" -print > filelist.f
```

![find 查找 Verilog 文件](<./screenshots/任务004_linux操作系统常用命令/find_v_files_0800s.jpg>)

视频验证：`07:47-10:03`，画面应看到老师用 `find -name "*.v" -print` 查找 `.v` 文件，并把它讲成生成 filelist 的基础。

这张图要看递归目录层级：`find` 不是只看当前一层目录，而是从起点往下扫。生成 filelist 时，起点 `.` 选错，后面仿真或综合读到的文件集合也会错。

这条命令的结构是：从当前目录 `.` 开始，找名字匹配 `*.v` 的文件，把路径打印出来，再用 `>` 保存到 `filelist.f`。它的价值不是“能找文件”，而是能把查找结果变成后续仿真、综合、lint 可用的输入清单。

失败信号也要会判断：`filelist.f` 为空，先查当前目录是否正确，再查工程里是否真的有 `.v` 文件，最后查通配符有没有被引号或 shell 规则影响。

## 5. `grep`、管道和重定向：把屏幕输出变成工程数据

`grep` 用来按内容筛选文本，管道 `|` 把前一个命令的输出交给后一个命令，重定向 `>` 把输出写进文件。这三个放在一起，Linux 命令就从“看屏幕”变成了“处理工程数据”。

```bash
grep -Rni "module" . > module_index.log
find . -name "*.v" -print | grep rtl > rtl_files.f
```

![grep 递归查找 module](<./screenshots/任务004_linux操作系统常用命令/grep_recursive_1600s.jpg>)

视频验证：`16:00-17:30`，画面应看到老师用 `grep` 在文件中查找 `module` 一类关键词，并展示匹配行。

这张图要看输出形态：`grep` 给出的不是“文件存在”，而是“哪个文件、哪一行、哪段内容命中了”。这比人工打开每个 RTL 文件查 module 更适合工程目录。

![管道和重定向](<./screenshots/任务004_linux操作系统常用命令/redirect_pipe_2500s.jpg>)

视频验证：`25:00-26:30`，画面应围绕管道符、把前一个命令输出作为后一个命令输入、以及重定向保存输出展开。

这张图要看数据流方向：管道把上一条命令的屏幕输出交给下一条命令，重定向把输出落成文件。前端工程里，很多脚本就是把“查找 -> 筛选 -> 保存 -> 复用”串起来。

前端工程里常见组合是：用 `find` 找候选文件，用 `grep` 筛内容，用 `>` 保存报告。比如定位所有模块定义、收集报错日志、筛选 timing violation，都可以沿这条思路做。

## 6. `diff`、`wc`、`more`：比较、计数、读长文件

`diff` 用来比较两个文件差异，适合看 RTL、testbench、脚本修改前后有什么变化。`wc` 用来统计行数、字节数或词数，适合粗略判断文件规模。`more` 用来分页阅读长文件，避免终端一次刷太多内容。

这些命令的价值在场景，不在背诵：

| 命令 | 场景 |
|---|---|
| `diff old.v new.v` | 复查自己改了哪些 RTL |
| `wc -l filelist.f` | 检查 filelist 有多少条 |
| `more run.log` | 分页看长日志 |

压缩解压常见于提交作业、备份工程、传输日志和结果包。`tar` 参数多，不必一次背完，先记常用组合，再会查帮助。

## 8. 前后台控制：挂起、恢复、中断不是一回事

`Ctrl+Z` 是挂起当前前台程序，`fg` 是把挂起程序恢复到前台，`Ctrl+C` 才是中断当前程序。把挂起当成退出，会导致工具仍在占状态；把中断当成暂停，会直接结束运行。

![Ctrl+Z 与 fg](<./screenshots/任务004_linux操作系统常用命令/ctrlz_fg_4500s.jpg>)

视频验证：`45:00-46:00`，画面应看到老师演示挂起、恢复和关闭程序的区别。

这张图要区分状态：挂起不是退出，恢复不是重启，中断才是结束当前前台进程。对仿真 GUI、波形工具和长日志命令来说，这三个动作混淆会让现场状态越来越乱。

EDA 场景里这很常见：你可能挂起 gvim、仿真 GUI 或波形工具，再恢复继续用。判断状态比背快捷键更重要。

## 9. `chmod`：共享服务器里的权限判断

`chmod` 不是语法题，而是共享服务器里的协作问题。Linux 权限通常按三类对象看：`u` 当前用户，`g` 同组用户，`o` 其他用户；按三类权限看：`r` 可读，`w` 可写，`x` 可执行或可进入目录。

![chmod 权限修改](<./screenshots/任务004_linux操作系统常用命令/chmod_permission_5020s.jpg>)

视频验证：`50:20-52:00`，画面应看到老师用 `chmod` 修改文件权限，并解释用户、用户组、其他用户的权限位。

这张图要看权限位的三段结构：本人、同组、其他人分别有什么权利。共享服务器上最常见的问题不是文件不存在，而是别人没有穿过目录或读取文件的权限。

目录权限尤其容易被忽略。别人能不能进入目录，不只取决于文件权限，还取决于路径上每一级目录是否允许进入。文件权限开了，但目录 `x` 权限没开，别人仍然可能进不来。

权限排查顺序：

1. 用 `ls -l` 看文件权限。
2. 用 `ls -ld <dir>` 看目录权限。
3. 判断对象是本人、同组用户还是其他用户。
4. 再决定用 `chmod u/g/o +/- r/w/x` 调整哪一类权限。

## 10. 本讲最小工程练习

完成下面这组命令，才算把本讲从“听懂”推进到“能用”：

```bash
pwd
mkdir -p lab/logs
touch lab/logs/run.log
find . -name "*.v" -print > filelist.f
grep -Rni "module" . > module_index.log
wc -l filelist.f module_index.log
ls -l filelist.f module_index.log lab/logs/run.log
```

预期结果：`filelist.f` 保存 Verilog 文件路径，`module_index.log` 保存 module 命中行，`ls -l` 能看到三个输出文件的权限和大小。若输出为空，先查当前目录是否正确，再查工程里是否真的有 `.v` 文件。

| `touch` 和 `mkdir` 区别是什么 | `touch` 创建文件，`mkdir` 创建目录 |

| `find . -name "*.v" -print > filelist.f` 在做什么 | 递归找 Verilog 文件并保存为 filelist |

最小通过标准：你能在一个 lab 目录里创建文件、查找 `.v`、生成 filelist、筛出 `module`、保存日志，并解释每个输出文件从哪里来。
