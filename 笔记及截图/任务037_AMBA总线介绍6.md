## 本章知识全景图

### 一眼看懂这讲在讲什么

- **本章主题**：把前几讲 AHB 的多 master、仲裁、流水线访问收束成工程判断，再引出 AHB-Lite、APB 和 AHB-APB bridge。
- **核心概念**：multi-layer AHB、AHB-Lite、`BUSY/IDLE`、APB、`PSEL/PENABLE/PWRITE`、APB two-phase transfer、AHB-APB bridge、`HREADY`、interrupt、memory-mapped register。
- **逻辑主线**：AHB 服务高性能片上互连，APB 服务低速寄存器外设；bridge 的本质是在 AHB 侧扮演 slave、在 APB 侧扮演 master，并用 ready/wait 机制把慢速 APB 访问嵌回 AHB 时间线。
- **最短学习路径**：先确认多 master 为什么需要仲裁，再理解单 master 场景为何可简化成 AHB-Lite，最后掌握 APB 的 setup/enable 两阶段和 AHB-APB bridge 的等待机制。

| 概念层级 | 核心概念 | 前置知识 | 延伸应用 |
|---|---|---|---|
| 高性能互连 | multi-layer AHB、shared slave | master/slave、arbiter | SoC interconnect、共享资源访问 |
| 协议裁剪 | AHB-Lite | 单 master 约束 | 单主控子系统、简化 IP 集成 |
| 低速外设 | APB | memory map、寄存器访问 | GPIO、UART、timer、watchdog |
| APB 时序 | setup / enable | `PSEL`、`PENABLE`、`PWRITE` | APB slave RTL、寄存器写入条件 |
| 桥接机制 | AHB-APB bridge | AHB ready、APB two-phase | wait state、读数据返回、低速外设接入 |
| 软硬交互 | interrupt + status register | CPU master、IP slave | 中断服务、状态清除、寄存器设计 |

**APB 不是“低配 AHB”，而是把低速寄存器访问压成固定两阶段；AHB-APB bridge 的核心任务，是让 AHB master 在 APB 完成前别提前采样。**

## 1. multi-layer AHB 解决的是带宽隔离

单层 AHB 的根本限制是同一时刻只有一个 master 能占用一条总线。multi-layer AHB 把系统拆成多个局部 AHB 子系统，让不同 master 访问各自局部资源时并行推进，只有访问共享 slave 时才发生竞争。

![multi-layer AHB](<./screenshots/任务037_AMBA总线介绍6/task37_00_multilayer_ahb_00m47s.jpg>)

视觉核验/看图要点/漏看后果：00:47-03:30，这张图的教学职责是把“单层总线排队”升级成“多层互连并行”。先看多个局部 AHB 系统，再看哪些 slave 是局部资源、哪些是共享资源。漏看这张图，会把所有 master 争用都想成一根总线上的全局排队，读 SoC interconnect 图时分不清带宽隔离和共享瓶颈。

带宽隔离可以这样理解：

```text
单层 AHB：
CPU 访问慢外设时，其他 master 可能一起排队。

multi-layer AHB：
CPU 子系统、DMA 子系统、本地外设子系统可以分别访问局部资源；
只有访问共享 memory 或共享 bridge 时才需要协调。
```

这不是普通 slave 设计第一天就要实现的结构，但它解释了为什么 SoC 互连不只是“把所有模块挂到一根线”。前端写 IP 时至少要知道：你的模块是局部资源、共享资源，还是挂在 bridge 后面的低速资源；这个位置决定了带宽、仲裁和验证压力。

可以把 multi-layer AHB 理解成“多条局部通道加共享路口”：局部访问不必都挤到同一个路口，只有访问共享 slave 时才需要协调。这个比喻的边界是，它解释带宽隔离，不替代具体互连矩阵的仲裁、译码和时序实现。

## 2. AHB-Lite 是单 master 场景下的协议减法

AHB-Lite 的“Lite”不是随便删信号，而是基于一个硬约束：系统只有一个 master。没有多个 master，就不需要 request/grant 仲裁，也不需要为长等待释放总线的 `SPLIT/RETRY` 复杂路径。

![AHB-Lite](<./screenshots/任务037_AMBA总线介绍6/task37_01_ahb_lite_05m48s.jpg>)

视觉核验/看图要点/漏看后果：05:48-08:00，这张图的教学职责是说明 AHB-Lite 的简化前提。先确认只有一个 master，再看 arbiter、request/grant、复杂 split/retry 路径被拿掉，但地址/数据 pipeline 和 ready 机制仍保留。漏看这个前提，会把 AHB-Lite 误解成“随便像 AHB 一点”的自定义接口。

| 判断问题 | AHB-Lite 的结论 | 工程影响 |
|---|---|---|
| 是否只有一个 master | 是 | 不需要仲裁器和 request/grant |
| 是否还保留地址/数据阶段 | 是 | 仍要理解 AHB pipeline |
| slave 是否要支持 `SPLIT/RETRY` | 通常不需要 | response 逻辑简化 |
| 是否等于任意自定义接口 | 否 | `HTRANS/HWRITE/HSIZE/HREADY/HRDATA/HWDATA` 等语义仍要守住 |

如果一个小 SoC 只有 CPU 一个 master，AHB-Lite 可以显著降低设计和验证复杂度。真正危险的是把 AHB-Lite 误解成“像 AHB 就行”：只要还叫 AHB-Lite，地址阶段、数据阶段、有效传输、ready 等规则就不能乱改。

## 3. AHB 学完后要形成 feature matrix

学总线协议不能停在“知道很多信号”。写一个 AHB slave 前，必须说清它支持哪些 feature、拒绝哪些 feature、上游会不会把不支持的访问送进来。

![AHB feature 复盘](<./screenshots/任务037_AMBA总线介绍6/task37_02_ahb_review_08m02s.jpg>)

视觉核验/看图要点/漏看后果：08:02-15:00，这张图的教学职责是把 AHB feature 压成一张设计前检查表。先看组件边界，再看 transfer、burst、response、arbitration 是否都被列入约束。漏看这张图，写 slave 时容易只实现“单次 32-bit OKAY 访问”，却没有声明或验证不支持的 burst、wait、error、`BUSY/IDLE` 情况。

最小 feature matrix：

| feature | 必须回答的问题 |
|---|---|
| 数据宽度 | 支持 8/16/32 bit，还是只支持 32 bit？ |
| burst | 是否识别 `HBURST`？连续地址访问是否保证正确？ |
| wait state | 是否会拉低 `HREADYOUT`？最长等多久？ |
| response | 固定 `OKAY`，还是支持 `ERROR/RETRY/SPLIT`？ |
| `BUSY/IDLE` | 遇到无效 `HTRANS` 是否忽略？ |
| lock/master 编号 | 是否关心 `HMASTER/HMASTLOCK`？ |
| 非法地址 | default slave 处理，还是本模块内部报错？ |

`BUSY` 和 `IDLE` 特别容易混。`BUSY` 仍属于当前 burst，只是 master 暂时插入一个空拍；`IDLE` 表示当前没有有效传输，后续有效访问通常要用新的 `NONSEQ` 开始。如果把它们都当成“没事”，burst 边界、计数器和地址递增就可能出错。

写 feature matrix 的目的不是做文档装饰，而是把“不支持”也变成可验证结论。例如只支持 single transfer 的寄存器块，应明确忽略或拒绝 burst；只支持 `OKAY` 的简单 slave，应说明非法地址由 default slave 处理，不能让本模块在不认识的访问上沉默。

## 4. DMA 说明同一模块可以既是 slave 又是 master

master/slave 不是模块身份的永久标签，而是某个接口上的角色。DMA 的寄存器端口对 CPU 来说是 slave；DMA 真正搬数据时，又通过另一个总线接口作为 master 去读源地址、写目的地址。

典型 DMA 配置链：

```text
CPU 写 DMA.SRC_ADDR
CPU 写 DMA.DST_ADDR
CPU 写 DMA.SIZE
CPU 写 DMA.START
DMA 作为 AHB master 读源、写目的
DMA 完成后置状态位并中断 CPU
CPU 读 DMA.STATUS 并清中断
```

这也是 memory-mapped register 的意义：CPU 看到的是地址读写，地址背后可能是 SRAM、控制寄存器、FIFO、状态寄存器或 bridge。总线协议只提供访问框架，具体语义由 slave 内部按地址解释。

## 5. APB 面向低速寄存器外设

APB 用在 UART、GPIO、timer、watchdog、简单寄存器块这类低速外设上。它不追求高吞吐，而是用简单接口、固定两阶段访问和少量控制信号降低面积、功耗和验证复杂度。

![APB 信号总览](<./screenshots/任务037_AMBA总线介绍6/task37_03_apb_signals_17m56s.jpg>)

视觉核验/看图要点/漏看后果：17:56-25:00，这张图的教学职责是建立 APB 的最小信号字典。先看 `PADDR/PWRITE/PWDATA` 是 master/bridge 发出的访问意图，再看 `PSEL/PENABLE` 如何把访问分成选中与完成，最后看 `PRDATA` 从 slave 返回。漏看信号方向，会把 `PENABLE` 当成 slave 的“完成应答”，或者把 `PSEL` 错当写使能。

| 信号 | 方向 | 作用 |
|---|---|---|
| `PADDR` | bridge/master -> slave | 访问地址 |
| `PSELx` | decoder/bridge -> slave | 选中第 x 个 APB slave |
| `PENABLE` | bridge/master -> slave | enable 阶段，本次访问完成 |
| `PWRITE` | bridge/master -> slave | 1 写，0 读 |
| `PWDATA` | bridge/master -> slave | 写数据 |
| `PRDATA` | slave -> bridge/master | 读数据 |

不同 APB 版本可能加入 `PREADY/PSLVERR` 等信号。本讲的核心不依赖这些扩展：先掌握 `PSEL` 选中、`PENABLE` 完成、`PWRITE` 定方向，才能写出基本 APB slave。

APB 可以理解成“慢速寄存器柜台”：setup 阶段把地址、方向和数据递到柜台，enable 阶段才真正盖章办结。这个比喻的作用是防止把 `PSEL` 当完成信号；只排到柜台前，不等于业务已经办完。

## 6. APB 互连是广播加选择

APB 的地址、写数据和方向控制可以广播给多个 slave，真正决定哪个 slave 响应的是 `PSELx`。读数据返回时再根据选择信号 mux 回来。

![APB 互连](<./screenshots/任务037_AMBA总线介绍6/task37_04_apb_interconnect_25m36s.jpg>)

视觉核验/看图要点/漏看后果：25:36-29:00，这张图的教学职责是解释 APB 为什么必须看 `PSELx`。先看 `PADDR/PWRITE/PWDATA` 可以广播到多个 slave，再看只有被 `PSELx` 选中的 slave 才响应，读数据再 mux 回来。漏看这一点，所有 APB slave 都可能因为看到同一地址总线而误写寄存器。

APB slave 写寄存器的有效条件通常是：

```systemverilog
write_hit = psel && penable && pwrite;
```

只看 `PADDR` 是错的。因为广播互连下，所有 slave 都可能看到同一个地址总线和写数据总线；没有 `PSEL`，这个地址不属于你；没有 `PENABLE`，访问还没进入完成阶段。

## 7. APB transfer 固定分成 setup 和 enable

APB 基本访问至少两拍：setup 阶段给出地址、方向、选择；enable 阶段拉高 `PENABLE`，读写动作在这一阶段完成。

![APB 写时序](<./screenshots/任务037_AMBA总线介绍6/task37_05_apb_write_timing_29m41s.jpg>)

视觉核验/看图要点/漏看后果：29:41-35:30，这张图的教学职责是把 APB transfer 的 setup/enable 两阶段钉到时钟边界上。先看 `PSEL` 先起且 `PENABLE=0`，再看下一拍 `PENABLE=1`，写数据在 enable 阶段被采样。漏看这一拍差异，就会在 setup 阶段提前写寄存器，造成软件写一次、硬件动作提前或重复。

写访问：

```text
T0 setup : PSEL=1, PENABLE=0, PWRITE=1, PADDR/PWDATA 有效
T1 enable: PSEL=1, PENABLE=1, PWRITE=1, slave 写入 PWDATA
T2 idle 或下一次 setup
```

读访问：

```text
T0 setup : PSEL=1, PENABLE=0, PWRITE=0, PADDR 有效
T1 enable: PSEL=1, PENABLE=1, PWRITE=0, slave 驱动 PRDATA
T2 bridge/master 采样或进入下一次访问
```

APB 慢不是缺点，而是定位。低速外设没有必要承担 AHB pipeline、burst、arbiter 那套复杂度。

APB 读写的共同边界是：setup 阶段只建立访问，enable 阶段才完成访问。写寄存器如果在 setup 阶段就动作，会提前一拍；读数据如果 enable 阶段还没有稳定，bridge/master 就不能把这笔访问宣布完成。

可复现的 APB slave 写入条件应落成一句 RTL 判断：`psel && penable && pwrite`。如果还支持 `PREADY`，则完成条件还要并入 `pready`；本讲先按无扩展版本理解，但工程上要在接口规格里把版本说清。

## 8. APB bridge 的 FSM 很小，但边界很硬

APB bridge 或 APB master 通常用 `IDLE -> SETUP -> ENABLE` 生成 `PSEL/PENABLE`。`SETUP` 下一拍必进 `ENABLE`；`ENABLE` 结束后，如果还有下一笔访问，可以回到 `SETUP`，否则回 `IDLE`。

![APB FSM](<./screenshots/任务037_AMBA总线介绍6/task37_06_apb_fsm_35m53s.jpg>)

视觉核验/看图要点/漏看后果：35:53-39:30，这张图的教学职责是把 APB master/bridge 的控制逻辑压成 `IDLE -> SETUP -> ENABLE`。先看三个状态，再看 `PSEL` 在 setup/enable 都有效、`PENABLE` 只在 enable 有效。漏看状态输出关系，会写出 `PENABLE` 提前或 `PSEL` 中途掉下来的非法时序。

骨架：

```systemverilog
case (state)
    IDLE:   next_state = transfer ? SETUP : IDLE;
    SETUP:  next_state = ENABLE;
    ENABLE: next_state = transfer ? SETUP : IDLE;
endcase

assign psel    = (state == SETUP) || (state == ENABLE);
assign penable = (state == ENABLE);
```

APB slave 端也应按阶段写：setup 阶段识别地址和方向，enable 阶段执行读写。把 `PSEL` 当写使能，会提前一拍写寄存器。

## 9. AHB-APB bridge 用 `HREADY` 给 APB 买时间

AHB master 访问 APB 外设时，真正命中的是 AHB-APB bridge。bridge 在 AHB 侧是 slave，在 APB 侧是 master。APB 至少需要 setup + enable 两拍，所以 bridge 必须让 AHB 侧等待，不能让 master 在 APB 数据未准备好时继续采样。

bridge 可以理解成“快车道和慢柜台之间的翻译柜台”：AHB 侧来得快，APB 侧办得慢，bridge 不能让快车道司机提前拿走结果；它必须用 `HREADYOUT=0` 把 AHB 数据阶段按住，直到 APB enable 阶段完成并准备好返回值。

![AHB-APB bridge](<./screenshots/任务037_AMBA总线介绍6/task37_07_ahb_apb_bridge_40m11s.jpg>)

视觉核验/看图要点/漏看后果：40:11-46:30，这张图的教学职责是说明 bridge 为什么必须用 `HREADY` 把 AHB 暂停住。先看 AHB 地址命中 bridge，再看 APB 侧 setup/enable 两拍，最后看 bridge 在 APB 数据准备好后才把 `HRDATA/HREADY` 返回给 AHB master。漏看这张图，会写出 AHB 提前完成、APB 数据晚到的桥接 bug。

一次 APB 读的桥接链：

```text
AHB master 发地址，命中 APB bridge 窗口
  -> bridge 在 AHB 侧被选中
  -> bridge 拉低 HREADY，阻止 AHB 数据阶段提前完成
  -> bridge 在 APB 侧发 PADDR/PSEL，进入 setup
  -> 下一拍拉高 PENABLE，APB slave 输出 PRDATA
  -> bridge 把 PRDATA 放到 HRDATA
  -> bridge 拉高 HREADY，AHB master 采样读数据
```

如果 AHB 和 APB 不同频或 APB 更慢，bridge 还要处理跨时钟和数据寄存问题。本讲先按同频简化理解，但不能把这张图照搬到所有工程场景。

更工程化地看，bridge 同时维护两套身份：

| 侧 | bridge 的角色 | 必须做对的事 |
|---|---|---|
| AHB 侧 | slave | 识别 `HSEL/HTRANS/HWRITE/HADDR`，必要时拉低 `HREADYOUT`，把 `HRDATA/HRESP` 返回给 master |
| APB 侧 | master | 生成 `PADDR/PSEL/PWRITE/PWDATA/PENABLE`，按 setup/enable 两阶段访问外设 |

APB 写的桥接链：

```text
AHB 地址阶段：
  master 发 APB 外设地址，bridge 被选中

AHB 数据阶段 / APB setup:
  bridge 拿到 HWDATA
  APB 侧发 PADDR/PSEL/PWRITE/PWDATA，PENABLE=0
  AHB 侧保持等待或按设计确认写完成边界

APB enable:
  PENABLE=1，APB slave 在这一拍执行写入
  写完成后 bridge 释放 HREADYOUT
```

APB 读的风险更大，因为 `PRDATA` 要转成 `HRDATA`。视频时序图标出 `PRDATA can be directly routed back to HRDATA, or registering the read data at the end of enable cycle then drive back`：如果直接组合返回，AHB 频率可能受 APB/slave 读路径限制；如果寄存一拍返回，就要用 `HREADYOUT` 明确插入等待。两种做法都可以，不能做的是晚一拍返回却让 AHB master 以为本拍已经完成。

## 10. IP 通知 CPU 通常靠中断加状态寄存器

CPU 通常是 master，IP 通常是 slave。slave 不能随便主动把数据塞给 CPU；它有事时拉中断，CPU 进入中断服务程序后再读它的状态寄存器。

```text
IP 内部事件发生
  -> IP 拉起 interrupt
  -> interrupt controller 通知 CPU
  -> CPU 进入 ISR
  -> CPU 读 IP.STATUS / IRQ_STATUS
  -> CPU 清中断或继续读数据
```

中断不是原因本身，只是提醒。真正的完成标志、错误码、FIFO 状态、数据有效信息，都要通过 memory-mapped register 暴露出来。写 IP 寄存器时如果只给中断不给状态，软件会知道“有事”，但不知道“什么事”。

寄存器设计至少要区分四类地址：

| 寄存器 | 软件用途 | RTL 行为 |
|---|---|---|
| `CTRL` | 启动、使能、配置模式 | APB/AHB 写入后生成内部控制位或启动脉冲 |
| `STATUS` | 查询忙闲、完成、错误 | 硬件置位，软件读回判断状态 |
| `IRQ_STATUS` | 查询中断原因 | 硬件置位，CPU ISR 读取 |
| `IRQ_CLEAR` | 清除中断 | 软件写 1 清除对应状态位 |

这样 CPU/IP 通信才闭合：CPU 写控制寄存器启动 IP，IP 完成后置状态并拉中断，CPU 进 ISR 后读原因、读结果、清中断。中断线只是一根提醒线，寄存器才是可调试、可复现的软件接口。

## 最小闭环：AHB 到 APB 的一次读

```text
AHB master 发地址，落在 APB bridge 窗口
  -> bridge 被 decoder 选中
  -> bridge 拉低 HREADY
  -> APB side: PADDR/PSEL setup
  -> APB side: PENABLE enable，slave 输出 PRDATA
  -> bridge 将 PRDATA 转成 HRDATA
  -> HREADY 拉高，AHB master 完成采样
```

## 可复现实现检查：APB slave 与 bridge

这部分最适合落成两个最小实验：一个只测 APB slave，一个测 AHB-APB bridge。目标不是写完整 IP，而是把 transfer 边界跑清楚。

| 实验 | 输入步骤 | 必看信号 | 通过口径 |
|---|---|---|---|
| APB 写寄存器 | setup 拍给 `PSEL=1, PENABLE=0, PWRITE=1`，enable 拍给 `PENABLE=1` | `PSEL`、`PENABLE`、`PWRITE`、寄存器值 | setup 拍寄存器不变，enable 拍只写一次 |
| APB 读寄存器 | setup 拍给地址，enable 拍读取 | `PADDR`、`PSEL`、`PENABLE`、`PRDATA` | `PRDATA` 在 enable 阶段稳定，未选中 slave 不驱动有效返回 |
| AHB 读 APB | AHB 访问 bridge 窗口，APB slave 两拍返回 | `HSEL`、`HTRANS`、`HREADYOUT`、`PSEL`、`PENABLE`、`HRDATA` | bridge 在 APB 未完成前拉低 `HREADYOUT`，APB 完成后再释放并返回 `HRDATA` |
| 中断闭环 | CPU 写 start，IP 完成后置状态并拉中断 | `CTRL`、`STATUS`、`IRQ_STATUS`、`IRQ_CLEAR`、`interrupt` | CPU 能读到原因并写 1 清除；中断线不能替代状态寄存器 |

失败信号很具体：setup 拍寄存器已经变化，说明写使能太早；`PSEL=0` 的 slave 也在改变状态，说明选通信号没用；bridge 没拉低 `HREADYOUT` 却晚一拍给 `HRDATA`，说明 AHB master 会采到旧数据或不稳定数据。

## 常见误区和失败信号

- AHB-Lite 不是随便减协议；它只是在单 master 约束下删掉仲裁相关复杂度。
- APB slave 不能只看 `PADDR` 写寄存器，必须同时看 `PSEL/PENABLE/PWRITE`。
- `PSEL` 是选中，不是访问完成；`PENABLE` 才标出 enable 阶段。
- bridge 不拉低 `HREADY`，AHB master 会在 APB 数据未准备好前采样。
- 把 `BUSY` 和 `IDLE` 都当无效空拍，会破坏 burst 语义。
- IP 只给中断不给状态寄存器，软件无法判断中断原因。

## 和 AI+IC / NPU 学习的连接

NPU 里大量控制寄存器、状态寄存器、中断寄存器会挂在 APB 或类似低速寄存器总线上；高带宽 feature map、weight、DMA 访问通常走 AHB/AXI 类高性能通路。学会区分“数据搬运通路”和“寄存器控制通路”，后面读 NPU SoC 架构图时才不会把所有接口混成一类。

最小练习：画一个 NPU control block，左侧接 APB 寄存器，右侧输出 `start/config/irq/status`，再说明 `start` 如何从 APB 写寄存器变成内部启动脉冲。

## 复习与自测

1. **判断题**：AHB-Lite 可以忽略 AHB 的地址/数据阶段规则。  
   **答案**：错。AHB-Lite 主要删掉多 master 仲裁相关复杂度，地址/数据 pipeline、有效传输和 ready 规则仍要遵守。

2. **解释题**：APB 写寄存器为什么通常用 `PSEL && PENABLE && PWRITE`？  
   **答案要点**：`PSEL` 表示选中本 slave；`PENABLE` 表示进入访问完成阶段；`PWRITE` 表示写方向。三者同时成立才是一笔对本 slave 的有效写。

3. **推导题**：AHB-APB bridge 为什么要拉低 `HREADY`？  
   **答案要点**：APB 至少 setup + enable 两拍才能完成，AHB master 不能在 APB 读数据未稳定前完成数据阶段；bridge 用 `HREADY=0` 插入等待。

4. **工程题**：IP 有事件要通知 CPU，最小寄存器设计要有哪些内容？  
   **答案要点**：至少要有 interrupt 输出、状态寄存器或 IRQ_STATUS、清中断机制；中断只提醒 CPU，CPU 通过寄存器读原因并清除。

5. **判断题**：APB setup 阶段 `PSEL=1` 时，slave 就可以立即写寄存器。  
   **答案**：错。基本 APB 写入应在 enable 阶段完成，典型条件是 `PSEL && PENABLE && PWRITE`；setup 只建立访问。

6. **解释题**：AHB-APB bridge 在 AHB 侧和 APB 侧分别扮演什么角色？  
   **答案要点**：AHB 侧是 slave，接收 `HSEL/HTRANS/HADDR/HWRITE/HWDATA` 并返回 `HREADYOUT/HRESP/HRDATA`；APB 侧是 master，发出 `PADDR/PSEL/PWRITE/PWDATA/PENABLE` 并接收 `PRDATA`。

7. **判断题**：`BUSY` 和 `IDLE` 都不是有效数据传输，所以对 burst 计数没有区别。  
   **答案**：错。`BUSY` 仍属于当前 burst 的暂停，`IDLE` 表示无有效传输或新的序列边界；把二者混同会破坏 burst 计数和地址递增判断。

8. **工程题**：只支持 single transfer、固定 `OKAY` 的简单 AHB-Lite 寄存器块，feature matrix 里至少要写清什么？  
   **答案要点**：写清数据宽度、是否忽略 burst、是否支持 wait state、`HRESP` 固定 `OKAY` 的前提、非法地址由谁处理、`BUSY/IDLE` 如何忽略、读写寄存器何时采样。合格答案必须说明“不支持项如何被上游约束或测试证明不会误用”。
