# 任务05：Linux 与 gvim 文本编辑工具操作实践

## 本章知识全景图

### 1. 一眼看懂这讲在讲什么

本讲不是单纯复习 Linux 命令，而是在建立数字前端学习的第一条安全操作链：先把公共工程复制到个人目录，再把练习 Verilog 文件单独拷出来，然后用 gvim 练习编辑、补全和文件跳转。真正要学会的不是某一个快捷键，而是“我正在改哪份文件、为什么能确认它存在、改错后如何撤回、路径跳转为什么成功”。

核心概念：`rm -rf`、`cp -rf`、当前目录、Tab 补全、个人练习副本、gvim 插入模式补全、`gf` 文件跳转、`Ctrl-o` 返回、路径基准。

逻辑主线：

- 先清掉旧副本，避免旧文件状态污染练习。
- 再从公共目录复制 `asicflow` 到自己的工作目录。
- 然后把 `risk_control.v` 单独拷到外层目录，保护后续作业依赖的原始工程。
- 接着在 gvim 里练习编辑命令、自动补全和局部修改。
- 最后用 `gf` / `Ctrl-o` 建立“从代码里的路径跳到真实文件”的工程阅读能力。

### 2. 概念地图

| 层级 | 对象 | 本讲作用 | 数字前端工程中的后续用途 |
|---|---|---|---|
| 文件来源 | 公共目录中的 `asicflow` | 提供课程练习工程 | 后续 RTL、脚本、filelist 都来自受控来源 |
| 个人副本 | 自己目录下的 `asicflow` | 允许练习和试错 | 避免破坏公共工程或作业基线 |
| 单文件副本 | 外层目录中的 `risk_control.v` | 专门练 gvim 操作 | 防止把编辑练习混进正式工程 |
| 编辑器能力 | `Ctrl-n`、删除、复制、替换 | 提高 RTL 编辑效率 | 写端口、信号名、例化连接时减少拼写错误 |
| 路径跳转 | `gf` / `Ctrl-o` | 从 include 路径进入文件 | 阅读 filelist、include、宏定义和多文件 RTL |

### 3. 最短学习路径

1. 先用 `pwd` 和 `ls` 确认自己在哪个目录。
2. 用 `rm -rf asicflow` 清理旧练习副本。
3. 用 `cp -rf <public>/asicflow .` 拷贝工程到当前目录。
4. 进入工程目录，确认 `risk_control.v` 存在。
5. 把 `risk_control.v` 单独拷到个人外层目录，再从外层打开它。
6. 在 gvim 里练习补全、删除、复制、替换和跳转。
7. 看到空文件、找不到文件、`gf` 跳转失败时，先查路径和文件是否真实存在。

本讲最适合用“实验沙盒”理解：公共目录是原始样品库，个人 `asicflow` 是你自己的实验台，单独拷出的 `risk_control.v` 是可随手折腾的小样。不要在样品库里直接动刀，也不要在正式工程里练手；先复制，再试错，再检查，这就是工程安全感。

## 1. 先复制工程：工程练习必须和公共来源隔离

本讲第一步是删除旧 `asicflow` 再复制新副本，这一步解决的是“练习状态可控”问题。公共目录是课程材料来源，不应该被个人练习直接修改；个人目录里的副本才是允许试错的工作区。

视觉验证：01:28-02:10，画面中先清理旧目录，再从 `public` 路径复制 `asicflow`。这里要看的是终端动作链，而不是某个按钮或截图本身。

![清理并复制 asicflow](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/01_rm_asic_flow_01m28s.jpg>)

这张图只看三件事：当前目录在哪里、旧 `asicflow` 是否被清掉、新 `asicflow` 是否重新出现。截图里的绿色终端不是背景，它是在证明“删除和复制都发生在个人目录”。

可复现命令形态如下，`<public_path>` 按课程服务器实际路径替换：

```bash
pwd
ls
rm -rf asicflow
cp -rf <public_path>/asicflow .
ls
```

关键点：

- `rm -rf asicflow` 只应该删个人目录下的旧练习副本，不要对公共目录执行。
- `cp -rf` 中 `-r` 表示递归复制目录，`-f` 表示覆盖已有目标。
- 最后的 `.` 表示复制到当前目录；如果当前目录错了，副本会落到错误位置。
- 复制后必须 `ls`，因为“命令敲过”不等于“文件已经在预期目录”。

失败信号：`ls` 看不到 `asicflow`，说明复制失败、路径错、当前位置错，或者公共路径没有补全成功。不要急着打开 gvim，先回到 `pwd -> ls -> cp -> ls` 这一条闭环。

## 2. 单独拷出 `risk_control.v`：练习文件不能污染作业基线

课程反复强调把 `risk_control.v` 单独拷出来，是因为这个文件后面还会用于作业或工程练习。直接在工程内部乱改，会让后续错误来源变得不可追踪：你不知道仿真失败是课程设计问题、自己的练习修改问题，还是路径打开错了。

视觉验证：04:37-08:58，画面围绕 `asicflow` 下的 `risk_control.v` 展开，老师要求把它单独复制到外层目录后再练习。

![复制练习文件](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/03_code_view_07m24s.jpg>)

这张图要看文件身份：画面里的 `risk_control.v` 是练习对象，但你要先判断它来自工程目录还是个人外层副本。真正危险的不是改错一行代码，而是改错文件位置后还以为自己只是在练习。

推荐动作链：

```bash
cd asicflow
ls
cp -rf risk_control.v ~/
cd ~
ls risk_control.v
gvim risk_control.v &
```

这条链的本质是“源文件 -> 练习副本 -> 编辑器”。如果 `gvim risk_control.v` 打开后是空白，通常不是 gvim 坏了，而是当前目录没有这个文件，gvim 帮你新建了一个同名空缓冲区。此时应该退出不保存，再用下面三步定位：

```vim
:q!
```

```bash
pwd
ls risk_control.v
```

判断口径：

- `ls risk_control.v` 能看到文件，再打开才是编辑已有文件。
- `ls` 看不到文件，`gvim risk_control.v` 就可能打开空文件。
- 如果不确定拷到哪里了，用 `find ~ -name 'risk_control.v'` 查自己的家目录，而不是继续盲改。

## 3. Tab 补全先服务路径正确，再服务效率

Tab 补全不是“省几个字”的技巧，而是路径验证工具。课程里多次提醒在 `asicflow`、`risk_control.v` 这类名字上用 Tab，是因为长路径和长文件名最容易拼错；补全成功至少说明当前目录中存在匹配候选。

视觉验证：12:55-13:15，画面演示通过 Tab 补全目录和文件名，避免把 `asicflow` 拼成不存在的名字。

![Tab 补全文件名](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/04_visual_copy_10m22s.jpg>)

这张图要观察补全弹出的候选和光标位置。Tab 补全像“路径雷达”：能补全说明附近确实有目标，不能补全说明你的位置、前缀或目标文件至少有一个不成立。

典型用法：

```bash
cd asi<Tab>
cp -rf ris<Tab> ~/
gvim ris<Tab> &
```

Tab 补全的判断规则：

- 能补全：当前路径下存在唯一或可选候选。
- 不能补全：当前目录不对、文件不存在、拼写前缀错，或者候选太多需要再敲几个字符。
- 补出多个候选：不要随便选，先 `ls` 看清楚目标文件。

数字前端项目里，Tab 补全会一直用在 RTL 文件、脚本、filelist、仿真日志和报告路径上。路径错是最廉价也最常见的错误，应该在打开工具前就消掉。

## 4. `Ctrl-n` 补全信号名：减少 RTL 拼写错误

Shell 的 Tab 补全解决文件路径，gvim 插入模式下的 `Ctrl-n` 解决文本上下文补全。课程中的例子是输入 `out`、`DIV`、`int` 这类前缀后，让 gvim 在当前缓冲区中找可能的已有词。它最适合用在信号名、端口名、宏名和文件中已经出现过的标识符上。

视觉验证：19:37-20:20，画面演示在插入模式下输入信号名前缀，再用 `Ctrl-n` 弹出候选。

![插入模式补全](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/06_register_declare_22m13s.jpg>)

这张图要看候选来自当前文本，而不是来自工具自动理解硬件。`Ctrl-n` 像从已出现的词库里挑词，能减少拼写错误，但不能替你判断这个信号该不该接到这里。

操作闭环：

```text
i              进入插入模式
out            输入前缀
Ctrl-n         查找下一个候选
Ctrl-p         查找上一个候选
Enter          接受候选
Esc            回到普通模式
```

对 RTL 来说，这个命令的价值不在“自动写代码”，而在减少拼写分叉。例如 `data_valid` 和 `data_vaild` 只差一个字母，但会让例化连接、波形搜索和综合报错全都变得混乱。补全只能复用已有文本，不能替你判断语义；候选出现后还要检查位宽、方向和上下文。

## 5. 删除到行首、复制粘贴和替换：练习命令要带结果检查

本讲不是系统讲完整 Vim，而是让你把上一讲命令真实敲一遍。每个命令都要按“当前模式 -> 命令 -> 结果”来记，不要只背快捷键。

视觉验证：21:47-22:20，画面演示 `d0` 删除从光标到行首的内容。这里的关键不是 `d0` 本身，而是 motion 参与了删除范围的定义。

![局部删除和编辑](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/07_output_edit_25m11s.jpg>)

这张图要看选择范围和删除结果。Vim 的很多命令像“动词 + 范围”：`d` 是删除，`0` 是到行首；范围理解错，删除动作就会扩大到不该动的文本。

最低限度要熟练的动作：

| 目标 | 命令 | 结果检查 |
|---|---|---|
| 删除当前字符 | `x` | 光标处字符消失 |
| 删除到行首 | `d0` | 光标前本行内容消失 |
| 删除当前行 | `dd` | 整行消失，下一行上移 |
| 复制当前行 | `yy` | 画面不变，寄存器中有一行 |
| 粘贴 | `p` / `P` | 文本出现在光标后 / 前 |
| 撤销 | `u` | 最近一次修改回退 |
| 重做 | `Ctrl-r` | 撤销的修改恢复 |

学习建议：每次只做一个命令，立刻观察屏幕变化。连续乱敲会让你失去因果关系，不知道是哪一步导致结果变坏。

## 6. `gf` 和 `Ctrl-o`：从路径文本跳到真实文件

`gf` 是本讲最工程化的命令。它把光标下的文件路径当成目标文件打开；`Ctrl-o` 返回上一个跳转位置。这个能力会直接用于阅读 `` `include``、filelist、脚本引用、模块拆分和多文件 RTL。

视觉验证：28:17-30:00，画面创建 `define.v` 后再次执行 `gf`，跳转从失败变成成功；这证明 `gf` 依赖真实存在的路径。

![创建 define 文件并跳转](<./screenshots/任务005_linux与gvim文本编辑工具操作实践/08_case_edit_31m07s.jpg>)

这张图要看跳转前后的文件名和路径关系。`gf` 像顺着代码里的门牌号去找房间；门牌号写错、房间没建、你站错楼层，跳转都会失败。

示例：

```verilog
`include "define.v"
```

在 `define.v` 上按 `gf`，gvim 会尝试打开该文件；按 `Ctrl-o` 返回原文件。

必须理解的路径规则：

- 相对路径以当前 gvim 打开文件的工作目录为基准，不一定是你脑中以为的目录。
- 文件不存在时，`gf` 会报错或找不到目标；不要把这当成 gvim 命令问题。
- 如果 include 路径写的是相对路径，必须保证该相对路径下确实有文件。
- 绝对路径和相对路径都能跳，但相对路径更容易被当前目录影响。

最小验证链：

```bash
touch asicflow/define.v
gvim risk_control.v &
```

在文件里写入：

```verilog
`include "asicflow/define.v"
```

然后把光标放在路径上按 `gf`。如果能进入 `define.v`，说明路径成立；如果不能，先查 `pwd`、`ls asicflow/define.v` 和 gvim 的当前工作目录。

## 7. 操作课真正要形成的工程习惯

本讲的知识点很碎，但目标只有一个：你要能在 Linux + gvim 环境中安全编辑 RTL 文件，并能解释每一步为什么成功或失败。

### 7.1 操作前先确认对象

不要直接敲 `gvim xxx.v`。先问三件事：

- 我当前在哪个目录？
- 这个文件是否真实存在？
- 我是否应该改这份文件，还是先复制一个练习副本？

### 7.2 操作中保留撤退路线

修改前知道如何退出和撤销：

```vim
u      " 撤销
:q!    " 放弃修改退出
:wq    " 保存并退出
```

### 7.3 操作后检查结果

不要把“命令执行了”当成“结果正确”。每一步都要看到可检查证据：

- 复制后 `ls` 看得到目标。
- 打开后不是空文件。
- 补全后信号名拼写和位宽仍然正确。
- `gf` 跳转到的是预期文件，`Ctrl-o` 能回到原位置。

## 8. 最后速记

### 8.1 本章最该记住的结论

- 公共工程只作为来源，个人练习必须在自己的副本里做。
- `gvim file` 打开空白文件时，第一怀疑对象是路径错或文件不存在。
- Tab 补全验证文件系统路径，`Ctrl-n` 补全当前文本中的标识符。
- `gf` 是否成功取决于路径是否真实存在，`Ctrl-o` 用来返回原跳转点。
- 操作课不能只看懂，必须能复现“起点 -> 命令 -> 结果 -> 失败排查”。

### 8.2 复现清单

1. 在个人目录下删除旧 `asicflow`，从公共目录复制新副本。
2. 进入 `asicflow`，确认 `risk_control.v` 存在。
3. 把 `risk_control.v` 复制到外层目录并从外层打开。
4. 在 gvim 中练习 `i`、`Esc`、`dd`、`yy`、`p`、`u`、`d0`。
5. 输入已有信号名前缀，用 `Ctrl-n` 补全。
6. 写一条 include 路径，创建目标文件，用 `gf` 跳入，再用 `Ctrl-o` 返回。

### 8.3 自测题

1. 为什么不建议直接在公共目录里修改 `risk_control.v`？  
   答案要点：公共目录是来源，不是个人练习区；直接修改会污染后续作业基线，导致错误来源不可追踪。

2. `gvim risk_control.v` 打开后是空白，最可能的原因是什么？  
   答案要点：当前目录没有这个文件，gvim 创建了新缓冲区；应先 `:q!`，再用 `pwd`、`ls risk_control.v` 查路径。

3. Tab 补全和 `Ctrl-n` 补全分别解决什么问题？  
   答案要点：Tab 解决 shell 文件路径补全；`Ctrl-n` 解决 gvim 插入模式下已有文本标识符补全。

4. `gf` 跳转失败时先查什么？  
   答案要点：查光标下路径是否真实存在、相对路径基准是否正确、文件名是否拼错。
