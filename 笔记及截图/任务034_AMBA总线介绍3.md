# 任务34：AMBA总线介绍3

## 本章知识全景图

这一讲继续 AHB，但焦点从“单次传输和基础信号”推进到 burst 传输。核心概念是 `HBURST`、`HSIZE`、`HTRANS`、INCR、WRAP、wait state 和 1KB boundary。burst 的本质是：master 拿到总线后连续传多拍数据，用 `HBURST` 描述长度和地址模式，用 `HTRANS` 标记第一拍和后续拍，用 `HSIZE` 决定每拍地址步长；每一拍只有在 `HREADY=1` 后才算被接受，并且整个 burst 不能跨越 1KB 边界。学完本章的验收动作是手算一组 burst 地址，并能指出它是否越界、是否应当拆分。

![AHB 复习](<./screenshots/任务034_AMBA总线介绍3/review_previous_ahb_660s.jpg>)

视觉核验：视频 11:00-11:15，画面承担“把 burst 连接回 AHB 基础信号”的教学职责。看图要点：burst 不是新总线，而是 `HTRANS/HADDR/HBURST/HSIZE/HREADY` 协同定义的连续传输序列；每拍地址是否被接受仍取决于 `HREADY`。如果看不懂，会把 burst 当成纯地址表，漏掉 ready/wait 对地址推进的控制。

本章主线：

```text
复习 AHB 信号和传输状态
  -> 为什么需要 burst
  -> SINGLE / INCR / INCR4/8/16 / WRAP4/8/16
  -> 根据 HSIZE 和 HBURST 计算地址序列
  -> INCR8 / INCR4 / WRAP4 时序图
  -> 未定长 INCR burst 如何结束
  -> burst 不能跨越 1KB boundary
```

| 本章概念 | 一句话理解 |
|---|---|
| burst | 一次总线授权下连续传一组数据 |
| `HBURST` | 告诉 slave 本次 burst 的类型和长度 |
| `HSIZE` | 决定每拍传输字节数，也决定地址步长 |
| INCR | 地址一直递增，长度可以固定或未定 |
| WRAP | 地址在一个固定大小的对齐窗口内回绕 |
| 1KB boundary | AHB burst 不允许跨越 1KB 地址边界 |

一个准确比喻：burst 像一次拿到通行许可后连续通过一组收费口，`HBURST` 是通行清单，`HSIZE` 是每辆车占用的宽度，`HREADY` 是当前收费口是否放行，1KB boundary 是这张通行清单不能跨出的管理区边界。这个比喻的边界是：硬件不会“估计能过去”，每一拍都必须被 ready 接受。

## 1. 为什么 burst 能提高总线效率

如果每传一个 word 都重新请求总线、仲裁、发地址，系统会浪费很多控制周期。burst 传输把多个连续数据合成一个序列，master 一次占用总线后连续发出多拍传输，slave 也提前知道后面还有数据。

![burst 类型入口](<./screenshots/任务034_AMBA总线介绍3/burst_types_intro_810s.jpg>)

视觉核验：视频 13:30-13:45，画面承担“区分 SINGLE、INCR、WRAP 三类访问模式”的教学职责。看图要点：SINGLE 只有一拍，INCR 按步长递增，WRAP 在对齐窗口内回绕；类型由 `HBURST` 编码告诉 slave 和互连。如果看不懂，会把所有连续访问都当作 INCR，后续 cache line/WRAP 地址会算错。

典型用途：

- CPU/cache 连续取指或取数据。
- DMA 搬运一段 memory。
- memory controller 连续读写一行数据。
- 高带宽外设一次搬一块数据。

burst 提高效率的代价是协议约束更多：地址要按规则增长，不能跨越边界，slave 要能正确处理 wait state 和 response。

工程用途：CPU cache refill、DMA block copy、SRAM 连续访问和高带宽外设搬运都需要 burst；工程风险则集中在地址生成、边界拆分、wait state 保持和异常响应处理。

## 2. `HBURST` 描述 burst 类型

AHB 常见 burst 类型：

| `HBURST` | 类型 | 含义 |
|---|---|---|
| `000` | `SINGLE` | 单次传输 |
| `001` | `INCR` | 未定长度递增 burst |
| `010` | `WRAP4` | 4 拍回绕 burst |
| `011` | `INCR4` | 4 拍递增 burst |
| `100` | `WRAP8` | 8 拍回绕 burst |
| `101` | `INCR8` | 8 拍递增 burst |
| `110` | `WRAP16` | 16 拍回绕 burst |
| `111` | `INCR16` | 16 拍递增 burst |

其中 `INCR` 最灵活，也最常用，因为它不提前固定长度；`INCR4/8/16` 和 `WRAP4/8/16` 则提前告诉 slave 固定拍数。

## 3. `HSIZE` 决定地址步长

`HSIZE` 指出每拍传输大小。地址递增不是固定加 1，而是按传输字节数递增。

常见对应关系：

| 传输大小 | 每拍地址步长 |
|---|---|
| 8-bit byte | +1 |
| 16-bit halfword | +2 |
| 32-bit word | +4 |
| 64-bit doubleword | +8 |

所以如果起始地址是 `0x48`，`HSIZE=010` 表示 32-bit 传输，那么递增地址就是：

```text
0x48, 0x4C, 0x50, 0x54, ...
```

如果你把 32-bit word burst 错算成地址每拍 +1，decoder、memory byte lane、对齐检查都会错。

## 4. 地址计算表：同一起点下不同 `HBURST` 的区别

课程用起始地址 `0x48`、`HSIZE=010` 讲解地址计算。

![HBURST 地址计算表](<./screenshots/任务034_AMBA总线介绍3/hburst_address_table_1410s.jpg>)

视觉核验：视频 23:30-23:45，画面承担“用同一起点比较不同 HBURST 地址序列”的教学职责。看图要点：起点相同、`HSIZE` 相同，但 `INCR4` 继续递增，`WRAP4` 在 16 byte 窗口内回绕；表格的价值是训练地址生成器，而不是背序列。如果看不懂，会在 RTL 里只按 +step 实现所有 burst 类型。

在 32-bit 传输下：

| 类型 | 地址序列 |
|---|---|
| `SINGLE` | `0x48` |
| `INCR` | `0x48, 0x4C, 0x50, ...` |
| `WRAP4` | `0x48, 0x4C, 0x40, 0x44` |
| `INCR4` | `0x48, 0x4C, 0x50, 0x54` |
| `WRAP8` | `0x48, 0x4C, 0x50, 0x54, 0x58, 0x5C, 0x40, 0x44` |
| `INCR8` | `0x48, 0x4C, 0x50, 0x54, 0x58, 0x5C, 0x60, 0x64` |

重点看 `WRAP4`：它不是一直往上加，而是在一个 4 拍 x 4 byte = 16 byte 的窗口内回绕。起点 `0x48` 落在 `0x40-0x4F` 这个 16 byte 对齐窗口里，所以 `0x48, 0x4C` 后回到 `0x40, 0x44`。

手算时固定三步：先由 `HSIZE` 得到步长，再由 `beats * step` 得到窗口大小，最后用起始地址所在的对齐窗口计算回绕点。任何一步省略，WRAP 序列都会变成猜。

## 5. INCR burst：顺着地址一直走

INCR burst 的地址按步长持续递增。固定长度的 `INCR4/8/16` 有明确拍数；未定长 `INCR` 可以由 master 持续发 `SEQ`，直到它结束本次 burst。

![INCR8 时序](<./screenshots/任务034_AMBA总线介绍3/incr8_burst_timing_1710s.jpg>)

视觉核验：视频 28:30-28:45，画面承担“展示固定长度递增 burst 的逐拍推进”的教学职责。看图要点：`INCR8` 有 8 个有效 beat，第一拍通常 `NONSEQ`，后续有效拍 `SEQ`，地址按 `HSIZE` 步长递增。如果看不懂，会把未定长 `INCR` 和固定 8 拍 `INCR8` 混用，导致长度计数和仲裁释放时机错误。

对于 `INCR8`，如果起点是 `0x60`、步长 4，地址序列可以是：

```text
0x60, 0x64, 0x68, 0x6C, 0x70, 0x74, 0x78, 0x7C
```

![INCR4 时序](<./screenshots/任务034_AMBA总线介绍3/incr4_burst_timing_1860s.jpg>)

视觉核验：视频 31:00-31:15，画面承担“说明固定 4 拍 burst 的结束条件”的教学职责。看图要点：`INCR4` 只有 4 个有效 beat，`HREADY=0` 只拉长当前 beat，不增加 beat 数；第 4 个有效 beat 完成后，下一次有效传输应重新声明类型。如果看不懂，会把 wait cycle 误计成一个 beat，或多发/少发地址。

`INCR4` 则只传 4 拍。时序图里第一拍通常是 `NONSEQ`，后面几拍是 `SEQ`。如果有 wait state，数据阶段会被拉长，但 burst 的逻辑顺序不变。

失败信号：`HREADY=0` 期间地址生成器仍递增、beat counter 仍加一、或第 4 个有效 beat 后继续用 `SEQ`，都说明 burst 状态机没有按“被接受的有效 beat”计数。

## 6. WRAP burst：在固定窗口内回绕

WRAP burst 常和 cache line 访问有关。它允许从窗口中间开始访问，然后回绕到窗口起点补齐剩余数据。

![WRAP4 地址例子](<./screenshots/任务034_AMBA总线介绍3/wrap4_address_example_1260s.jpg>)

视觉核验：视频 21:00-21:15，画面承担“训练 WRAP 窗口计算”的教学职责。看图要点：先算窗口大小，再找到 start address 所在窗口 base，地址到窗口末端后回到 base；回绕不是回到原起点。如果看不懂，会把 `0x48,0x4C,0x40,0x44` 误写成 `0x48,0x4C,0x48,0x4C` 或继续递增。

WRAP 窗口大小由 burst 拍数和每拍字节数决定：

```text
wrap_boundary_size = number_of_beats * bytes_per_beat
```

例如：

- `WRAP4` + 32-bit：4 * 4 byte = 16 byte 窗口。
- `WRAP8` + 32-bit：8 * 4 byte = 32 byte 窗口。
- `WRAP16` + 32-bit：16 * 4 byte = 64 byte 窗口。

![WRAP4 时序](<./screenshots/任务034_AMBA总线介绍3/wrap4_burst_timing_2010s.jpg>)

视觉核验：视频 33:30-33:45，画面承担“把 WRAP 地址序列和 HTRANS 时序对齐”的教学职责。看图要点：第一拍 `NONSEQ` 给出起点，后续有效拍 `SEQ`，地址按窗口规则推进；wait state 只拉长当前 beat，不改变下一有效地址。如果看不懂，会把地址回绕对了但和数据拍错位。

地址回绕逻辑可以理解为：

```text
先按步长递增
如果到达当前 wrap 窗口末尾
  -> 下一拍回到窗口起始地址
```

注意，回绕不是随便回到 0，也不是回到起始地址，而是回到当前对齐窗口的 base。

WRAP 常见于 cache line 访问：CPU 先要当前 miss 的 word，然后补齐同一 cache line 里的其他 word。这个用途解释了为什么它要在固定窗口内回绕，而不是一直递增。

## 7. 未定长 `INCR` burst 如何结束

`INCR` 是未定长度 burst。master 可以连续发 `SEQ`，直到它决定结束当前序列。结束方式通常是下一次传输变成 `IDLE` 或新的 `NONSEQ`。

![未定长 burst](<./screenshots/任务034_AMBA总线介绍3/undefined_length_burst_2160s.jpg>)

视觉核验：视频 36:00-36:15，画面承担“说明未定长 INCR 如何结束”的教学职责。看图要点：未定长 `INCR` 可以连续发 `SEQ`，直到 master 用 `IDLE` 结束、用新的 `NONSEQ` 开始另一段，或因异常响应改变流程。如果看不懂，会以为 `INCR` 必须有固定拍数，或不知道什么时候该释放/切换序列。

可以这样理解：

```text
NONSEQ -> SEQ -> SEQ -> SEQ -> ...
```

当 master 要开始另一段不连续访问时，下一次有效传输重新用 `NONSEQ`。如果暂时没有有效传输，就进入 `IDLE`。如果 master 还占着总线但下一拍没准备好，可能出现 `BUSY`。

## 8. burst 不能跨越 1KB boundary

课程强调：AHB burst 不能跨越 1KB 地址边界。

![1KB boundary 规则](<./screenshots/任务034_AMBA总线介绍3/one_k_boundary_rule_2310s.jpg>)

视觉核验：视频 38:30-38:45，画面承担“把 1KB boundary 变成可计算约束”的教学职责。看图要点：检查 burst 的首地址和最后一个有效 beat 是否仍在同一个 1KB 区间，例如 `addr[31:10]` 是否不变；将跨界时应提前拆分。如果看不懂，会让一个连续 burst 跨到另一个 slave 地址窗口或 default slave，造成响应和数据归属不确定。

原因是从设备的最小地址窗口通常按 1KB 粒度考虑。一个 burst 如果跨过 1KB 边界，前半段可能落在 slave A，后半段落在 slave B。这样 decoder 和 slave 都很难保证一个连续 burst 的一致性。

正确做法是：

```text
如果后续地址会跨越 1KB boundary
  -> 在边界前结束当前 burst
  -> 边界后用新的 NONSEQ 开始下一段 burst
```

因此，master 不能尝试从一个可能跨越 1KB 边界的地址开始固定长度 incrementing burst。

可复现判定：计算 `last_addr = start_addr + (beats - 1) * bytes_per_beat`。如果 `start_addr[31:10] != last_addr[31:10]`，这个固定长度递增 burst 会跨 1KB boundary，应该拆成边界前后两段。

## 9. 深挖：burst 的本质是“地址生成器 + 协议承诺”

很多初学者把 burst 看成“连续传几拍”，但硬件实现上它至少包含两层：

```text
地址生成器：根据 start address、HSIZE、HBURST 生成每拍地址
协议承诺：用 HTRANS/HBURST/HREADY/HRESP 告诉对方序列如何推进、等待和结束
```

如果地址生成器错了，slave 会访问错地址；如果协议承诺错了，slave 可能把某拍数据当成另一拍，或者 master 在 wait state 中提前推进。burst 的难点不是表格，而是表格、地址、时序、ready/response 必须同时一致。

## 10. 工程检查表：实现或审查 AHB burst 先看什么

| 检查点 | 应该确认什么 |
|---|---|
| `HBURST` | 类型是否正确，固定长度 burst 拍数是否匹配 |
| `HSIZE` | 地址步长是否等于每拍字节数 |
| `HTRANS` | 第一拍 `NONSEQ`，后续有效拍 `SEQ` |
| 地址对齐 | 起始地址是否满足传输大小对齐 |
| WRAP 窗口 | base、boundary、回绕点是否算对 |
| `HREADY` | wait state 时地址/控制是否保持 |
| `HRESP` | ERROR/RETRY/SPLIT 是否能中止或重试 |
| 1KB boundary | burst 是否会跨边界 |
| decoder | 一个 burst 是否始终落在同一个 slave 地址窗口 |

## WRAP 公式、wait state 和 1KB 边界

WRAP burst 的窗口大小：

```text
bytes_per_beat = 2 ** HSIZE
window = beats * bytes_per_beat
base = floor(start_addr / window) * window
next_addr = base + ((curr_addr + bytes_per_beat - base) % window)
```

地址生成器只能在当前拍被 `HREADY=1` 接受后推进。`HREADY=0` 时，不能提前进入下一拍地址，否则波形看起来像多发了一笔。

逐拍实现口径可以写成：

```text
if reset:
  beat_count = 0
elif valid_transfer && HREADY:
  accept current beat
  update beat_count
  compute next_addr from HBURST/HSIZE
elif valid_transfer && !HREADY:
  hold current address/control/beat_count
```

这里的关键是“接受当前 beat”发生在 `HREADY=1`，不是发生在地址刚变化时。

1KB boundary 规则要用正反例检查。假设每拍 4 字节：

- 从 `0x3F0` 开始的 4 beat burst：`0x3F0,0x3F4,0x3F8,0x3FC`，不跨到 `0x400`。
- 从 `0x3F8` 开始的 4 beat INCR：`0x3F8,0x3FC,0x400,0x404`，跨越 1KB 边界，应拆成两个 burst 或重新规划访问。

## 最小闭环：从输入到验收

| 环节 | 本章最小要求 |
|---|---|
| 输入 | 围绕“AHB burst”的课程证据和工程对象：HBURST、HSIZE、INCR/WRAP、HREADY、逐周期地址推进、1KB boundary |
| 操作 | 给定起始地址、`HSIZE` 和 `HBURST`，手算每一拍地址，并在有 `HREADY=0` 时保持当前拍不推进 |
| 输出 | burst 地址序列表、WRAP 窗口计算、1KB 边界检查结论 |
| 通过标准 | 能手算 burst 地址并判断是否越界 |
| 失败先查 | 先查 `HSIZE` 是否换算成正确字节步长，再查 WRAP base/window，最后查是否跨越 1KB boundary |

这一节的最小任务：用 `start_addr=0x48`、`HSIZE=010` 分别写出 `INCR4` 和 `WRAP4` 地址序列，再判断从 `0x3F8` 开始的 4 beat word burst 为什么越过 1KB 边界。

示例复现：

| 任务 | 计算 | 结论 |
|---|---|---|
| `0x48` + `HSIZE=010` | `bytes_per_beat=4` | 每拍地址步长 4 |
| `INCR4` | `0x48, 0x4C, 0x50, 0x54` | 4 拍递增 |
| `WRAP4` | 窗口 `4*4=16`，base `0x40` | `0x48, 0x4C, 0x40, 0x44` |
| `0x3F8` 4 beat word | last `0x404`，跨 `0x400` | 越过 1KB boundary，应拆分 |

## 本章速记

- burst 是连续传输序列，不是简单的“多次 single”。
- `HBURST` 决定 burst 类型，`HSIZE` 决定地址步长。
- `INCR` 按地址递增，`WRAP` 在对齐窗口内回绕。
- 固定长度 burst 有 4/8/16 拍；未定长 `INCR` 用新的 `NONSEQ` 或 `IDLE` 结束。
- `HREADY=0` 会拉长当前数据阶段，不能让地址/控制错误推进。
- AHB burst 不能跨越 1KB boundary。

## 自测参考答案与判分点

1. `HSIZE=010` 表示每拍 4 字节，所以 `INCR4` 地址是 `0x48, 0x4C, 0x50, 0x54`。
2. `WRAP4` 的窗口大小是 `4 beats * 4 bytes = 16 bytes`，`0x48` 所在对齐窗口是 `0x40-0x4F`，所以 `0x48, 0x4C` 后回到 `0x40, 0x44`。
3. `INCR` 是未定长递增 burst，master 可持续发 `SEQ`；`INCR8` 是固定 8 拍递增 burst，slave 和 arbiter 能提前知道长度。
4. 因为一次 AHB burst 应保持在同一个 1KB 地址边界内；跨边界可能从一个 slave 地址窗口跑到另一个 slave 或 default slave，破坏连续传输语义。
5. 不能。`HREADY=0` 表示当前数据阶段未被接受，地址生成器提前推进会造成地址相位和数据相位错位。
6. 检查顺序是：`HSIZE` 步长、起始地址对齐、`HBURST` 类型、`NONSEQ/SEQ` 序列、`HREADY` 保持逻辑、WRAP 窗口、1KB boundary、异常响应处理。
