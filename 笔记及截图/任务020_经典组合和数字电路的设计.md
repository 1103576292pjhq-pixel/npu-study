# 任务20：经典组合和数字电路的设计

## 本章知识全景图

### 一眼看懂这讲在讲什么

- **本章主题**：用 Verilog/SystemVerilog 描述常见组合逻辑和时序逻辑，并把代码反推成硬件结构。
- **核心概念**：`timescale`、RTL、组合逻辑、MUX、decoder、encoder、DFF、counter、shift register、testbench。
- **逻辑主线**：HDL 不是普通软件程序，而是硬件结构描述；组合逻辑看“当前输入如何决定输出”，时序逻辑看“寄存器如何在时钟边沿保存历史”。
- **最短学习路径**：先分清仿真时间和硬件结构，再用 MUX/decoder/encoder 建组合逻辑直觉，最后用 DFF/counter/shift register 建时序逻辑直觉并写 testbench 检查。

| 概念层级 | 核心概念 | 前置知识 | 延伸应用 |
|---|---|---|---|
| 仿真边界 | `timescale` | `#delay` | TB 时间单位，不代表真实硬件等待 |
| HDL 层级 | RTL | 门级、寄存器传输 | 综合、仿真、代码审查 |
| 组合逻辑 | MUX / decoder / encoder | `assign`、`always_comb`、`case` | 地址译码、控制选择 |
| 时序逻辑 | DFF / counter | 时钟、复位、非阻塞赋值 | 状态寄存、计数、握手超时 |
| 验证 | testbench | 激励、响应、断言 | 小模块自测 |

**每写一段 RTL，都要能回答它综合后大概是什么硬件；如果只能按软件执行顺序解释，说明还没有进入数字前端的思维方式。**

## 1. `timescale` 只定义仿真时间，不生成真实等待电路

`timescale` 决定 testbench 中 `#5` 这类延时被解释成多长仿真时间。它服务仿真，不会综合出一个“等待 5ns 的硬件盒子”。

![timescale 与编译](<./screenshots/任务020_经典组合和数字电路的设计/timescale_compile_100s.jpg>)

🔍 视觉验证：视频 01:22-03:00（`timescale` 与编译页：应看到仿真时间单位被放在编译运行语境中。）

典型写法：

```systemverilog
`timescale 1ns/1ps
```

含义：

- 时间单位是 1ns。
- 时间精度是 1ps。
- `#5` 在仿真中表示 5ns。

如果你在 RTL 里想“等待多个周期”，正确结构通常是计数器或状态机，而不是 `#delay`。例如等待 16 个周期：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= 4'd0;
    else if (start && cnt != 4'd15)
        cnt <= cnt + 1'b1;
end
```

这段才会综合成寄存器和加法反馈。

## 2. HDL 不是软件语言：RTL 描述的是寄存器之间的数据传输

Verilog/SystemVerilog 的代码顺序会影响仿真语义，但学习 RTL 时必须不断把语句翻译成硬件：选择器、门、寄存器、加法器、比较器、反馈路径。

![HDL 与 RTL 层级](<./screenshots/任务020_经典组合和数字电路的设计/comb_intro_500s.jpg>)

🔍 视觉验证：视频 04:44-09:00（HDL/RTL 层级页：应看到代码需要被反推成硬件结构。）

| 写法 | 硬件直觉 |
|---|---|
| `assign y = a & b;` | 一个与门或等价组合逻辑 |
| `case(sel)` 选择 `a/b/c/d` | 多路选择器 |
| `always_ff @(posedge clk)` | 触发器或寄存器组 |
| `cnt <= cnt + 1'b1` | 寄存器 + 加法器 + 反馈 |
| `if (!rst_n)` | 复位路径 |

同一个 `for` 循环，在 testbench 中像软件循环；在可综合 RTL 中可能展开成并行硬件结构。读 HDL 时不要只问“仿真器下一步执行哪行”，还要问“综合器会看到怎样的数据通路”。

## 3. 组合逻辑：输出只由当前输入决定

组合逻辑没有记忆。当前输入变，经过门延迟后输出跟着变。RTL 中常用 `assign` 或 `always_comb` 描述组合逻辑。

基本规则：

```systemverilog
always_comb begin
    y = '0;
    unique case (sel)
        2'b00: y = a;
        2'b01: y = b;
        2'b10: y = c;
        2'b11: y = d;
        default: y = '0;
    endcase
end
```

组合逻辑的核心检查是“所有路径都给输出赋值”。漏赋值会让工具推断 latch，导致你本来想要无状态逻辑，却生成了带记忆的电路。

## 4. MUX：`case` 写法通常综合成多路选择器

四选一 MUX 的硬件语义是：`sel` 决定输出来自哪一路输入。`case` 不是软件跳转，而是选择网络。

![四选一选择器](<./screenshots/任务020_经典组合和数字电路的设计/mux_design_1225s.jpg>)

🔍 视觉验证：视频 18:53-20:15（四选一 MUX 页：应看到 `case` 分支对应多路选择器输入。）

```systemverilog
module mux4_1 (
    input  logic [7:0] a,
    input  logic [7:0] b,
    input  logic [7:0] c,
    input  logic [7:0] d,
    input  logic [1:0] sel,
    output logic [7:0] y
);
    always_comb begin
        unique case (sel)
            2'b00: y = a;
            2'b01: y = b;
            2'b10: y = c;
            2'b11: y = d;
            default: y = '0;
        endcase
    end
endmodule
```

验收时必须覆盖所有 `sel` 值，并检查输出是否等于对应输入。如果 `sel=2'b10` 时输出不是 `c`，先查 case 分支和位宽，不要先怀疑仿真器。

## 5. Decoder：编码输入展开成 one-hot 输出

译码器把较少位宽的编码输入展开成 one-hot 输出。典型 3-8 decoder：3 bit 输入选择 8 bit 输出中的一个位置。

![3-8 译码器](<./screenshots/任务020_经典组合和数字电路的设计/decoder_design_1465s.jpg>)

🔍 视觉验证：视频 22:40-23:10（三八译码器页：应看到 3 bit 编码输入展开成 8 bit one-hot 输出。）

```systemverilog
module decoder3_8 (
    input  logic [2:0] in,
    input  logic       en,
    output logic [7:0] out
);
    always_comb begin
        out = 8'b0;
        if (en)
            out[in] = 1'b1;
    end
endmodule
```

这个写法的硬件含义是：`en=1` 时只拉高 `out[in]`，其他位为 0；`en=0` 时全部为 0。验证时要检查两个维度：每个 `in` 值都能选中对应 bit，`en=0` 时不会残留旧输出。

## 6. Encoder：one-hot 输入压回编码输出

编码器做 decoder 的反向操作：从 one-hot 输入恢复二进制编码。它的前提必须说清楚：输入到底保证 one-hot，还是可能多位同时为 1？

![编码器与 one-hot 输入](<./screenshots/任务020_经典组合和数字电路的设计/encoder_design_1655s.jpg>)

🔍 视觉验证：视频 23:35-23:55（编码器页：应看到 one-hot 输入被压回编码输出，非法输入语义需要单独定义。）

one-hot encoder：

```systemverilog
always_comb begin
    y = '0;
    unique case (in)
        8'b0000_0001: y = 3'd0;
        8'b0000_0010: y = 3'd1;
        8'b0000_0100: y = 3'd2;
        8'b0000_1000: y = 3'd3;
        8'b0001_0000: y = 3'd4;
        8'b0010_0000: y = 3'd5;
        8'b0100_0000: y = 3'd6;
        8'b1000_0000: y = 3'd7;
        default:      y = '0;
    endcase
end
```

如果输入可能多位为 1，就不能假装它是普通 encoder。你要么定义非法输入输出，要么设计 priority encoder：

```systemverilog
always_comb begin
    y = 3'd0;
    valid = 1'b1;
    if      (in[7]) y = 3'd7;
    else if (in[6]) y = 3'd6;
    else if (in[5]) y = 3'd5;
    else if (in[4]) y = 3'd4;
    else if (in[3]) y = 3'd3;
    else if (in[2]) y = 3'd2;
    else if (in[1]) y = 3'd1;
    else if (in[0]) y = 3'd0;
    else            valid = 1'b0;
end
```

这个差异会影响仲裁器、优先级中断、NPU 多通道 ready 选择等真实设计。

## 7. DFF：时序逻辑的最小记忆单元

D 触发器在时钟边沿采样输入并更新输出。它是时序逻辑的基础：没有寄存器，电路就不能保存历史状态。

![同步复位触发器](<./screenshots/任务020_经典组合和数字电路的设计/seq_dff_1910s.jpg>)

🔍 视觉验证：视频 31:50-43:20（DFF 与复位写法页：应看到同步复位、异步复位和触发器更新规则。）

同步复位 DFF：

```systemverilog
always_ff @(posedge clk) begin
    if (rst)
        q <= '0;
    else
        q <= d;
end
```

异步低有效复位：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= '0;
    else
        q <= d;
end
```

时序逻辑中使用非阻塞赋值 `<=`，是为了模拟寄存器在同一时钟边沿并行采样旧值并更新新值。下面的移位链就是例子：

```systemverilog
always_ff @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
end
```

`q2` 采的是旧 `q1`，不是本拍刚更新的新 `q1`。这和硬件触发器并行更新一致。

## 8. Counter：寄存器、加法器和反馈路径

计数器不是“变量自增”这么简单。硬件结构是：寄存器保存当前值，加法器计算下一值，时钟边沿把下一值写回寄存器。

![计数器设计](<./screenshots/任务020_经典组合和数字电路的设计/counter_design_2245s.jpg>)

🔍 视觉验证：视频 25:51-38:00（计数器结构页：应看到输入、输出、复位和计数反馈路径。）

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= '0;
    else if (en)
        cnt <= cnt + 1'b1;
end
```

检查计数器要看：

- reset 后是否回到确定值；
- `en=0` 时是否保持；
- `en=1` 时是否每拍加一；
- 位宽溢出是否符合设计预期；
- 是否需要终值回绕、饱和或产生 pulse。

如果 NPU 里用计数器控制 tile、channel、burst、line buffer 地址，溢出策略和 enable 条件就是设计正确性的核心。

## 9. Shift register：移位可以是组合，也可以是时序

“移位”这个词有两个常见语义：组合移位器和时序移位寄存器。组合移位器当前输入变，输出立即按移位关系变化；移位寄存器每个时钟边沿推进一位或一组位。

![移位寄存器](<./screenshots/任务020_经典组合和数字电路的设计/shift_register_2470s.jpg>)

🔍 视觉验证：视频 39:19-40:10（移位操作页：应看到左移/右移语义以及向时序移位寄存器的过渡。）

组合移位：

```systemverilog
assign y = a << shamt;
```

时序移位寄存器：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        shift <= '0;
    else if (en)
        shift <= {shift[6:0], serial_in};
end
```

前者综合成移位网络或连线选择，后者综合成一串寄存器。两者都叫 shift，但硬件完全不同。

## 10. Testbench：检查响应正确性，不是只让仿真跑完

testbench 的任务是给输入、等待输出、比较期望值、报告错误。对小模块来说，最重要的是覆盖关键输入组合和时序阶段。

![testbench 响应检查](<./screenshots/任务020_经典组合和数字电路的设计/testbench_check_2670s.jpg>)

🔍 视觉验证：视频 44:18-45:00（testbench 检查页：应看到激励后需要比较响应正确性，而不是只跑完仿真。）

MUX TB 最小结构：

```systemverilog
initial begin
    a = 8'h11; b = 8'h22; c = 8'h33; d = 8'h44;

    sel = 2'd0; #1; assert(y == a);
    sel = 2'd1; #1; assert(y == b);
    sel = 2'd2; #1; assert(y == c);
    sel = 2'd3; #1; assert(y == d);

    $finish;
end
```

Counter TB 最小结构：

```systemverilog
initial begin
    rst_n = 0; en = 0;
    repeat (2) @(posedge clk);
    rst_n = 1;

    en = 1;
    repeat (4) @(posedge clk);
    assert(cnt == 4);

    en = 0;
    repeat (2) @(posedge clk);
    assert(cnt == 4);
end
```

组合逻辑主要覆盖输入空间；时序逻辑要覆盖 reset、enable、采样边沿、保持和溢出。

## 11. 和 AI+IC / NPU 学习的连接

NPU 里的大模块也是由这些“小硬件词汇”堆起来的：MUX 选择数据路径，decoder 选择 bank 或寄存器，encoder 做仲裁结果编码，DFF 保存 pipeline stage，counter 控制 tile 循环，shift register 做串并转换或延迟对齐。

学习这些基础模块的目标不是背“这叫选择器”，而是看到一段 RTL 就能快速判断：

- 它是组合还是时序；
- 输出是否全路径赋值；
- 是否会推断 latch；
- reset/enable 是否完整；
- testbench 应覆盖哪些输入和时钟阶段。

这就是后面读 FIFO、AMBA 控制器、eFlash 控制器、NPU 数据通路的底层能力。

## 12. 深层理解：经典电路是 RTL 的“偏旁部首”

MUX、decoder、encoder、DFF、counter、shift register 看起来是小模块，其实像汉字里的偏旁部首。复杂 SoC、AI 加速器和 NPU 数据通路不是凭空长出来的，而是由这些基础结构反复组合：MUX 负责选择路径，decoder 负责把编号展开成使能，encoder 负责把事件压回编号，DFF 负责跨周期保存状态，counter 负责推进循环，shift register 负责对齐时间或改变数据形态。

学习本章不要只背“这是什么电路”，要做到看一段 RTL 就能问出硬件问题：

| 电路 | 一句话机制 | 审查重点 |
|---|---|---|
| MUX | 多选一 | `sel` 是否覆盖所有合法值，default 是否安全 |
| Decoder | 编码展开 one-hot | 输出是否全赋值，非法输入如何处理 |
| Encoder | one-hot 压回编码 | 多位同时为 1 时优先级或错误策略是什么 |
| DFF | 时钟边沿保存状态 | reset、enable、非阻塞赋值是否正确 |
| Counter | 寄存器 + 加法器 + 反馈 | 溢出、回绕、饱和、enable 保持是否明确 |
| Shift register | 多级寄存器串接 | 移入位、移出位、方向和复位是否清楚 |
| Testbench | 激励 + 期望 + 判断 | 是否覆盖输入空间和时序边界 |

这些基础模块像电路词汇表。词汇越扎实，后面读 FIFO、AMBA、eFlash、SD host 和 NPU pipeline 时越不会被代码量吓住。

| 配图 | 读图重点 | 深层理解 |
|---|---|---|
| timescale 与编译 | 仿真时间单位和编译入口 | `#delay` 是仿真语义，不是综合延时 |
| HDL 与 RTL 层级 | HDL、RTL、门级关系 | RTL 关注寄存器间数据转移 |
| 四选一选择器 | `sel` 与数据输入 | `case/?:` 会映射成 MUX 结构 |
| 3-8 译码器 | 3 bit 输入到 8 bit one-hot | 常用于片选、bank select、寄存器使能 |
| 编码器与 one-hot | 多输入压成编号 | 必须明确多热和全零输入策略 |

| 计数器设计 | 反馈加一 | 位宽决定溢出行为 |
| 移位寄存器 | 每拍移动一格 | 本质是多级 DFF 链 |
| testbench 响应检查 | 激励后检查输出 | 验证不是跑完，而是判断结果 |

## 14. 操作闭环：每个小电路都要有边界测试

| 模块 | 最少要测 | 最容易漏 |
|---|---|---|
| MUX | 所有 `sel`，每一路数据不同 | `sel` 非法值和位宽不一致 |
| Decoder | 所有输入编码，输出 one-hot | default 赋值和非法输入 |
| Encoder | 每个 one-hot 位 | 多位同时为 1、全 0 输入 |
| DFF | reset、普通采样、连续两拍 | reset 同步/异步语义混淆 |
| Counter | reset、enable、保持、溢出 | 终值回绕还是饱和不清楚 |
| Shift register | 左移、右移、移入位、复位 | 方向写反、级数少一拍 |

小电路的 testbench 像称量砝码：每个边界都要称一次。只测“正常值”会让设计像看起来水平的桌子，真正放重物时才发现一条腿短。

## 复习与自测

1. **判断题**：`timescale 1ns/1ps` 会综合出 1ns 精度的硬件延时。  
   **答案**：错。`timescale` 只影响仿真延时解释，不生成真实硬件等待。

2. **设计题**：四选一 MUX 的 testbench 至少要覆盖什么？  
   **答案要点**：覆盖 `sel=0/1/2/3`，每个值下输出分别等于 `a/b/c/d`；还要检查位宽一致。

3. **判断题**：组合逻辑某些分支不赋值，工具可能推断 latch。  
   **答案**：对。组合逻辑必须保证所有路径都有确定输出。

4. **解释题**：为什么时序逻辑中推荐用非阻塞赋值？  
   **答案要点**：寄存器在同一时钟边沿并行采样旧值并更新新值，非阻塞赋值能更准确模拟这种硬件行为，避免语句顺序造成错误直觉。

5. **工程题**：计数器最容易漏测哪几类行为？  
   **答案要点**：reset 初值、enable 保持、加一行为、位宽溢出、终值回绕或饱和策略。

## 工程核对口径

本章学完后，看到一个小 RTL 模块要能立即判断：

1. 它是组合逻辑、时序逻辑，还是二者混合。
2. 所有输出是否在所有路径上被赋值。
3. reset/enable/非法输入/溢出是否有明确定义。
4. testbench 是否覆盖正常路径和边界路径。
5. 这个小模块在 NPU 中可能对应数据选择、bank 译码、流水寄存、计数控制还是延迟对齐。
