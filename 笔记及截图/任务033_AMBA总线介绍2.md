# 任务33：AMBA总线介绍2

## 本章知识全景图

这一讲继续 AMBA/AHB，重点从“AHB 有哪些组成部分”推进到“AHB 一次传输到底靠哪些信号协同完成”。核心概念是 `HCLK/HRESETn`、`HADDR/HTRANS/HWRITE/HSIZE/HBURST/HPROT`、`HWDATA/HRDATA`、`HREADY/HRESP`、地址阶段、数据阶段、burst、default slave。主线只有一条：master 发地址和控制，slave 返回数据、ready 和 response；地址阶段与数据阶段流水重叠；wait、error 和 default slave 让系统在慢速访问或非法访问时仍能给出确定结果。学完本章的验收动作是拿一段 AHB 波形，逐周期指出哪一拍是地址阶段、哪一拍是数据阶段、`HREADY` 是否允许推进、`HRESP` 是否正常。

![AHB 总线互连](<./screenshots/任务033_AMBA总线介绍2/ahb_signal_overview_240s.jpg>)

视觉核验：视频 04:00-04:15，画面承担“把 AHB 信号按驱动方分组”的教学职责。看图要点：master 驱动地址/控制/写数据，decoder 产生 slave select，slave 返回读数据/ready/response，arbiter 决定当前 master。如果看不懂，会在波形里只盯单个信号，漏掉一次传输必须由多个对象共同闭合。

本章主线：

```text
AHB 信号来源和方向
  -> 地址/控制信号：HADDR、HTRANS、HWRITE、HSIZE、HBURST、HPROT
  -> 数据/响应信号：HWDATA、HRDATA、HREADY、HRESP
  -> 地址阶段 + 数据阶段流水
  -> HTRANS 的 IDLE/BUSY/NONSEQ/SEQ
  -> HREADY 插入等待周期
  -> HRESP 表示 OKAY/ERROR/RETRY/SPLIT
  -> burst、地址对齐、default slave
```

| 本章概念 | 一句话理解 |
|---|---|
| address phase | master 发地址和控制，通常 1 个周期 |
| data phase | slave 返回读数据或接收写数据，可被 `HREADY` 拉长 |
| pipeline | 当前传输的数据阶段和下一次传输的地址阶段重叠 |
| `HTRANS` | 告诉总线当前传输是空闲、忙、非连续还是连续 |
| `HREADY` | slave 用来决定这次传输是否结束 |
| `HRESP` | slave 告诉 master 这次传输正常、错误、重试或拆分 |

一个准确比喻：AHB 事务像“提交工单并等窗口签收”。`HADDR/HTRANS/HWRITE/HSIZE` 是工单内容，`HREADY` 是窗口是否办完，`HRESP` 是办理结果。这个比喻的边界是：AHB 是按时钟逐拍采样的硬件协议，工单没有被 `HREADY=1` 签收前，相关状态不能随意换成下一单。

## 1. AHB 信号要按“谁驱动”来记

AHB 信号很多，死背名字容易乱。最稳的记法是先看谁驱动。

![AHB 信号表](<./screenshots/任务033_AMBA总线介绍2/single_transfer_timing_990s.jpg>)

视觉核验：视频 16:30-16:45，画面承担“把信号名变成接口职责”的教学职责。看图要点：不要平铺背信号，而要标出每个信号由谁驱动、被谁采样、影响哪个阶段；尤其区分 `HWDATA` 来自 master、`HRDATA/HREADY/HRESP` 来自 slave。如果看不懂，会把写数据和读数据方向混淆，写 testbench 时驱错信号。

| 信号 | 方向/来源 | 作用 |
|---|---|---|
| `HCLK` | clock source | 总线时钟 |
| `HRESETn` | reset controller | 低有效复位 |
| `HADDR[31:0]` | master | 地址总线 |
| `HTRANS[1:0]` | master | 当前传输类型 |
| `HWRITE` | master | 读/写方向，常见约定 1 写 0 读 |
| `HSIZE[2:0]` | master | 本次传输大小 |
| `HBURST[2:0]` | master | burst 类型 |
| `HPROT[3:0]` | master | 保护属性 |
| `HWDATA[31:0]` | master | 写数据 |
| `HSELx` | decoder | 从设备选择 |
| `HRDATA[31:0]` | slave | 读数据 |
| `HREADY` | slave/总线 | 传输是否完成，低表示等待 |
| `HRESP[1:0]` | slave | response 状态 |

这张表还暴露了一个关键事实：master 负责“我要访问哪里、怎么访问”，slave 负责“我是否准备好、返回什么结果”。decoder 只是根据地址选中目标 slave。

机制要落到输入输出：AHB master 的输入通常是 CPU load/store、DMA 描述符或控制状态机请求，输出是地址/控制/写数据；slave 的输入是被选中的地址、控制和写数据，输出是读数据、ready 和 response。工程用途是把总线问题拆成三类：master 发错、decoder 选错、slave 响应错。

## 2. 地址阶段和数据阶段分开，是 AHB 流水的基础

AHB 一次传输至少可以拆成两个阶段：

- 地址阶段：master 给出 `HADDR`、`HTRANS`、`HWRITE`、`HSIZE`、`HBURST` 等控制信息。
- 数据阶段：写传输时 master 给出 `HWDATA`；读传输时 slave 返回 `HRDATA`；slave 用 `HREADY/HRESP` 收尾。

![基本 AHB 传输](<./screenshots/任务033_AMBA总线介绍2/haddr_hwrite_hsize_390s.jpg>)

视觉核验：视频 06:30-06:45，画面承担“定义地址阶段字段”的教学职责。看图要点：`HADDR` 决定访问对象，`HWRITE` 决定方向，`HSIZE` 决定每拍字节数和对齐要求，`HTRANS` 决定这是不是有效传输。如果看不懂，会把地址变化当成传输完成，而忽略方向、大小和有效性。

课程强调地址周期一般是 1 个 cycle，数据周期可以被 `HREADY` 拉长。AHB 的效率来自流水：当第 N 笔传输进入数据阶段时，第 N+1 笔传输的地址阶段可以同时出现。

![地址/数据阶段流水](<./screenshots/任务033_AMBA总线介绍2/transfer_phase_pipeline_840s.jpg>)

视觉核验：视频 14:00-14:15，画面承担“解释 AHB 流水错拍”的教学职责。看图要点：第 N 笔数据阶段和第 N+1 笔地址阶段可以在同一拍出现；读写数据总是跟着上一拍地址语义走。如果看不懂，会把当前 `HRDATA/HWDATA` 错配给当前 `HADDR`，导致波形判读和 scoreboard 对齐错误。

可以这样看时间轴：

```text
cycle 1: A1 address
cycle 2: D1 data  + A2 address
cycle 3: D2 data  + A3 address
cycle 4: D3 data  + A4 address
```

这不是“一个周期完成全部事情”，而是“每个周期都能交错推进一笔地址和上一笔数据”。

波形判读时必须给每拍贴两个标签：本拍地址阶段属于哪一笔事务，本拍数据阶段属于上一笔还是被 wait 拉长的那一笔。只贴一个地址标签，几乎一定会在流水场景下看错数据归属。

## 3. `HTRANS` 描述当前传输状态

`HTRANS[1:0]` 是 AHB 控制里最容易被忽略但很重要的信号。它告诉 slave 和互连：当前地址阶段是什么性质。

![HTRANS 类型](<./screenshots/任务033_AMBA总线介绍2/htrans_idle_busy_nonseq_seq_690s.jpg>)

视觉核验：视频 11:30-11:45，画面承担“判断地址阶段是否有效”的教学职责。看图要点：`NONSEQ/SEQ` 才是有效传输，`IDLE` 表示无传输，`BUSY` 表示 master 暂占但当前不是有效数据传输；burst 第一拍和后续拍要靠 `NONSEQ/SEQ` 区分。如果看不懂，会把 `IDLE/BUSY` 时的地址误当成真实访问。

| `HTRANS` | 含义 | 使用场景 |
|---|---|---|
| `IDLE` | 当前没有有效传输 | master 不使用总线 |
| `BUSY` | master 占住总线但暂时不进行有效传输 | burst 中间 master 还没准备好下一拍 |
| `NONSEQ` | 非连续传输的第一拍 | 单次传输或 burst 第一拍 |
| `SEQ` | 连续传输 | burst 后续拍，地址按规则递增或回绕 |

关键判断是：`NONSEQ` 表示一个新传输序列开始；`SEQ` 表示它属于前面 burst 的连续部分；`BUSY` 不是普通空闲，它常出现在 master 仍占有总线但暂时无法给出下一次有效传输的时候。

失败信号：如果 slave 在 `HTRANS=IDLE/BUSY` 时仍产生 side effect，说明它没有正确过滤无效传输；如果 burst 后续拍没有从 `SEQ` 推进，地址生成和长度计数就可能不同步。

## 4. `HREADY` 决定数据阶段是否结束

如果 slave 能在当前周期完成访问，就把 `HREADY` 拉高；如果 slave 需要更多时间，就把 `HREADY` 拉低插入 wait state。

![HREADY wait state](<./screenshots/任务033_AMBA总线介绍2/hready_wait_state_1290s.jpg>)

视觉核验：视频 21:30-21:45，画面承担“说明 wait state 如何冻结当前传输”的教学职责。看图要点：`HREADY=0` 时数据阶段没有完成，相关地址/控制/数据语义必须保持，master 和互连不能把下一笔事务当作已接受。如果看不懂，会在慢 slave 或 APB bridge 场景下提前推进状态机，造成地址相位和数据相位错位。

这条规则非常重要：

```text
HREADY = 1：本次数据阶段结束，可以推进到下一拍
HREADY = 0：当前传输没有结束，地址/控制/数据相关状态要保持
```

所以慢速 memory、外设 bridge、Flash 控制器等都可能通过 `HREADY` 延长数据阶段。master 不能假设每次访问都一个周期完成。

工程判定口径：凡是设计里有 SRAM macro、Flash、APB bridge、低速外设或跨时钟等待，就必须验证 `HREADY=0` 场景。只测 `HREADY` 永远为 1，相当于只测理想高速 slave，不能证明 AHB 接口健壮。

## 5. `HRESP` 不是数据，而是传输状态

`HRESP[1:0]` 由 slave 返回，表示这次传输的响应状态。

![HRESP 响应](<./screenshots/任务033_AMBA总线介绍2/hresp_error_response_1440s.jpg>)

视觉核验：视频 24:00-24:15，画面承担“区分完成条件和完成结果”的教学职责。看图要点：`HREADY` 说明当前传输何时结束，`HRESP` 说明结束结果是 OKAY、ERROR、RETRY 还是 SPLIT；错误响应必须被 master 或上层软件感知。如果看不懂，会只等 ready，不处理 error，非法地址或 slave 错误就会被静默吞掉。

| `HRESP` | 含义 | 工程解释 |
|---|---|---|
| `OKAY` | 正常完成 | 地址合法、slave 正常响应 |
| `ERROR` | 错误 | 地址非法、权限错误、slave 检测到错误 |
| `RETRY` | 要求 master 稍后重试 | slave 暂时不能服务，但不是永久错误 |
| `SPLIT` | 拆分传输，释放总线给其他 master | 常用于更复杂互连中避免长时间占用 |

初学者常把 `HREADY` 和 `HRESP` 混在一起。它们的分工是：`HREADY` 管“这拍完没完”，`HRESP` 管“这次传输结果是什么状态”。

调试时先问两句：第一，`HREADY` 有没有让事务真正结束；第二，结束时 `HRESP` 是正常还是异常。前一句定位等待/卡死，后一句定位错误/重试/拆分。

## 6. 单次传输和 burst 传输的区别

单次传输是一次地址对应一次数据；burst 是一个传输序列，第一拍 `NONSEQ`，后续拍通常是 `SEQ`。

![burst 类型](<./screenshots/任务033_AMBA总线介绍2/master_lock_split_2340s.jpg>)

视觉核验：视频 39:00-39:15，画面承担“把单次传输扩展到连续传输和异常占用”的教学职责。看图要点：`HBURST` 定义序列类型，`HLOCK`/retry/split 等机制影响总线占用和让出策略；连续传输不是把多个 single 随便拼起来。如果看不懂，会无法解释 DMA/cache 为什么需要 burst，也无法处理异常响应对序列的影响。

常见 burst 类型包括：

- `SINGLE`：单次传输。
- `INCR`：未指定长度的递增 burst。
- `INCR4/8/16`：固定长度递增 burst。
- `WRAP4/8/16`：固定长度回绕 burst。

burst 的价值是提高总线效率。master 拿到总线后连续传一串数据，省掉反复仲裁和重复建立传输上下文的开销。

比喻：single 像每买一个零件都重新排队付款，burst 像一次排队后按清单连续取货。它提高效率，但清单必须讲清长度、顺序、地址步进和异常处理；否则窗口和取货人会对不上第几件货。

## 7. 递增 burst 和回绕 burst

递增 burst 中，地址按传输大小递增。例如 32-bit word 传输时，每拍地址通常加 4。

![递增 burst](<./screenshots/任务033_AMBA总线介绍2/incrementing_burst_1740s.jpg>)

视觉核验：视频 29:00-29:15，画面承担“展示递增 burst 的地址生成规则”的教学职责。看图要点：地址步长由 `HSIZE` 决定，word 传输通常每拍 +4；`HREADY=0` 时地址生成器不能提前进入下一拍。如果看不懂，会把地址固定 +1 或在 wait state 中多加一次。

回绕 burst 会在一个对齐边界内循环。它常用于 cache line 这类场景：访问某个 word 后，希望在同一个固定大小块内继续取相邻数据；地址到达块末尾后回到块起点。

![回绕 burst](<./screenshots/任务033_AMBA总线介绍2/wrapping_burst_1890s.jpg>)

视觉核验：视频 31:30-31:45，画面承担“说明 WRAP 地址在固定窗口内循环”的教学职责。看图要点：先算窗口大小，再算窗口 base，地址到窗口末尾后回到 base，不是回到 0，也不一定回到起始地址。如果看不懂，会把 cache line 或固定长度回绕 burst 的后续地址算错。

工程上要特别注意地址对齐：

- `HSIZE` 决定每拍传输多少字节。
- 地址应按传输大小对齐。
- burst 边界不能随便跨越协议不允许的边界。
- slave 不能等到第 16 拍才第一次给出错误，错误越早反馈越好。

![地址边界](<./screenshots/任务033_AMBA总线介绍2/address_boundary_2040s.jpg>)

视觉核验：视频 34:00-34:15，画面承担“提醒 burst 不能破坏地址窗口边界”的教学职责。看图要点：连续 burst 应落在同一个可响应窗口内；跨到另一个 slave 或空洞时，应拆分或返回明确错误。如果看不懂，会让一个 burst 前半段命中 slave A、后半段命中 slave B/default slave，导致协议语义和数据归属崩掉。

## 8. default slave：地址没命中时也要有确定响应

AHB decoder 根据地址产生 `HSELx`，选中某个 slave。如果地址落在没有定义的空洞里，系统不能悬空不响应，通常需要 default slave 返回错误响应。

![default slave](<./screenshots/任务033_AMBA总线介绍2/slave_decode_select_2490s.jpg>)

视觉核验：视频 41:30-41:45，画面承担“给非法地址一个确定响应”的教学职责。看图要点：decoder 正常命中时选目标 slave，未命中时应选 default slave 返回错误，而不是让 `HREADY` 永久为 0。如果看不懂，会在 CPU/DMA 打错地址时只看到总线卡死，无法得到可诊断的 error。

default slave 的价值是让非法地址访问变成可诊断错误：

```text
合法地址 -> decoder 选中目标 slave -> 正常响应
非法地址 -> decoder 选中 default slave -> HRESP = ERROR
```

如果没有 default slave，CPU 或 DMA 访问错误地址时可能看到总线挂死、`HREADY` 永远不回来，调试会非常痛苦。

## 9. AHB 互连：arbiter、decoder、mux 共同工作

AHB 系统里不止一根线。多 master、多 slave 场景下，互连通常包含：

- arbiter：决定哪个 master 当前使用总线。
- decoder：根据地址选择哪个 slave。
- address/control mux：把当前 master 的地址和控制送到 slave。
- read data/response mux：把被选中 slave 的响应送回 master。

![AHB 互连结构](<./screenshots/任务033_AMBA总线介绍2/htrans_sequence_90s.jpg>)

视觉核验：视频 01:30-01:45，画面承担“把 HTRANS 序列放回互连系统”的教学职责。看图要点：`HTRANS` 是 master 对当前地址阶段的声明，但它要和 arbiter 授权、decoder 选择、slave ready/response 一起看。如果看不懂，会把有效传输判断孤立在 master 侧，漏掉授权和 slave 选择。

这解释了为什么 master/slave 之外还要理解 arbiter 和 decoder。master 负责发请求，slave 负责响应；arbiter 决定“谁先说话”，decoder 决定“这句话发给谁”。

状态变化可以按四拍追踪：master request 有效，arbiter grant 当前 master，decoder 根据 `HADDR` 产生 `HSELx`，slave 在数据阶段返回 `HREADY/HRESP/HRDATA`。任何一拍不成立，完整事务都不成立。

## 10. default master 与 dummy master

课程还提到 dummy/default master。它们常用于总线没有真实 master 请求、或某些特殊 response/locked transfer 场景下，保持总线处于确定状态。

![dummy/default master](<./screenshots/任务033_AMBA总线介绍2/hburst_hprot_540s.jpg>)

视觉核验：视频 09:00-09:15，画面承担“说明控制信号补足地址语义”的教学职责。看图要点：`HADDR` 只说明访问位置，`HBURST/HPROT/HSIZE/HTRANS` 说明访问方式、属性和序列；default/dummy master 用来让无真实请求时总线保持确定状态。如果看不懂，会以为地址总线本身已经包含全部协议信息。

从设计习惯上看，片内总线最怕“不确定”：没有 master 时地址控制不能乱飘，没有 slave 命中时 response 不能乱飘。dummy/default 这类结构就是为了让系统在边界场景也有可预测行为。

## 11. 深挖：为什么 AHB 要流水，而 APB 不需要

AHB 面向较高性能主干，CPU、DMA、memory 这类模块会频繁访问。把地址阶段和数据阶段拆开，可以让总线每个周期都在做有用工作：一边完成上一笔数据，一边准备下一笔地址。

APB 面向低速外设寄存器，重点是简单、低功耗、低面积。外设寄存器访问不需要复杂流水，通常也不需要 burst。把 AHB 的全部复杂度压到每个 UART/Timer/GPIO 上，面积和验证成本都不划算，所以 APB bridge 承担协议转换。

这就是系统分层的工程理由：快路径用复杂协议换性能，慢路径用简单协议换面积和稳定性。

## 12. 工程检查表：看 AHB 传输波形先查什么

| 检查点 | 通过标准 | 常见问题 |
|---|---|---|
| `HTRANS` | 有效传输用 `NONSEQ/SEQ`，空闲用 `IDLE` | 把无效地址当有效传输 |
| `HADDR` | 地址按 `HSIZE` 对齐 | halfword/word 访问地址不对齐 |
| `HWRITE` | 读写方向明确 | 写数据时序与地址阶段混淆 |
| `HSIZE` | 与数据宽度和地址步进一致 | burst 地址递增步长错误 |
| `HBURST` | 与 burst 长度/类型匹配 | 固定 burst 和 INCR 混用 |
| `HREADY` | wait state 时保持相关信号稳定 | slave 慢但 master 继续推进 |
| `HRESP` | error/retry/split 有明确处理 | 只看 ready，不处理错误 |
| decoder/default slave | 非法地址返回可诊断错误 | 地址空洞导致总线挂死 |

## 最小闭环：从输入到验收

| 环节 | 本章最小要求 |
|---|---|
| 输入 | 围绕“AHB 信号/波形”的课程证据和工程对象：HCLK、HREADY、HTRANS/HADDR、HWDATA/HRDATA、HRESP |
| 操作 | 选一段含 `HTRANS/HADDR/HREADY/HRESP` 的 AHB 波形，逐周期标出地址阶段、数据阶段和等待/响应状态 |
| 输出 | 一张逐周期判读表：每拍的有效传输、地址、读写方向、数据阶段是否完成、响应状态 |
| 通过标准 | 能逐周期判断地址阶段和数据阶段 |
| 失败先查 | 先查 `HTRANS` 是否为有效传输，再查 `HREADY` 是否拉长数据阶段，最后查 `HRESP` 是否改变传输结果 |

这一节的最小任务：用本章任意一张 AHB 时序图写出 4 行逐周期说明。每一行至少包含 `HTRANS`、`HADDR`、数据阶段信号和 `HREADY/HRESP` 判断；写不出哪一拍被 wait state 拉长，就还没有真正读懂 AHB 流水。

示例输出格式：

| 周期 | 地址阶段判断 | 数据阶段判断 | 推进条件 | 失败信号 |
|---|---|---|---|---|
| N | `HTRANS=NONSEQ`，新传输地址 A1 | 上一笔数据阶段或空 | 看上一笔 `HREADY` | 把 IDLE 地址当有效 |
| N+1 | 若 `HREADY=1`，可给 A2 | A1 的 `HWDATA/HRDATA/HRESP` | A1 数据阶段完成 | 把 A1 数据配给 A2 地址 |
| N+2 | `HREADY=0` 时保持/等待 | 当前数据阶段被拉长 | 不推进计数器 | wait 中地址或状态变化 |
| N+3 | `HREADY=1` 后进入下一有效拍 | 采样 response | 检查 `HRESP` | 只看 ready 不看 error |

## 本章速记

- AHB 信号按来源记：master 发地址/控制/写数据，slave 回读数据/ready/response，decoder 选 slave。
- AHB 传输分地址阶段和数据阶段，流水使二者重叠。
- `HTRANS` 的 `NONSEQ/SEQ` 描述传输序列，`IDLE/BUSY` 描述非有效或暂占状态。
- `HREADY` 决定数据阶段是否结束，低电平会插入 wait state。
- `HRESP` 告诉 master 传输结果是 OKAY、ERROR、RETRY 还是 SPLIT。
- burst 提高连续访问效率，但必须处理地址对齐和边界。
- default slave 让非法地址访问有明确错误响应。

## 自测题

1. 为什么说 AHB 的地址阶段通常 1 个周期，而数据阶段可能被拉长？
2. `HREADY` 和 `HRESP` 的职责有什么区别？
3. `NONSEQ` 和 `SEQ` 在 burst 中分别表示什么？
4. 为什么非法地址最好由 default slave 返回 error，而不是让总线没有响应？
5. 递增 burst 和回绕 burst 的地址变化有什么区别？
6. 看到一段 AHB 波形时，你会按什么顺序检查信号？

## AHB 逐周期读法

最小两拍模型：

```text
cycle N:   地址阶段，master 给 HADDR/HTRANS/HWRITE/HSIZE
cycle N+1: 数据阶段，写时看 HWDATA，读时看 HRDATA/HRESP
```

如果 `HREADY=0`，当前数据阶段没有结束，相关地址/控制/数据不能按正常节奏推进。下一笔传输的地址阶段也要按协议保持或等待，不能提前当成已接受。

验证断言可以从这些规则开始：

- 有效传输只在 `HTRANS=NONSEQ/SEQ` 时成立。
- 非法地址必须由 default slave 返回 error，不能让 `HREADY` 永久为 0。
- `HREADY=0` 时，被等待的阶段不能被错误推进。

## 自测参考答案与判分点

1. 地址阶段由 master 给出地址和控制，通常按流水每拍推出；数据阶段要等 slave 返回或接收数据，`HREADY=0` 时会被拉长。
2. `HREADY` 判断“这拍数据阶段是否结束”，`HRESP` 判断“这次传输结果是 OKAY、ERROR、RETRY 还是 SPLIT”。
3. `NONSEQ` 是新传输序列或单次传输的第一拍，`SEQ` 是 burst 后续连续拍；二者都表示有效地址阶段。
4. default slave 把非法地址变成确定的错误响应，避免 master 永久等待或读到不确定数据。
5. 递增 burst 按 `HSIZE` 决定的步长一直增加地址；回绕 burst 在固定对齐窗口内增加，到窗口末尾后回到窗口起点。
6. 先看 `HCLK/HRESETn`，再看 `HREADY` 是否允许推进，再看 `HTRANS/HADDR/HWRITE/HSIZE/HBURST`，最后看 `HWDATA/HRDATA` 和 `HRESP`。

判分口径：答案必须能落到逐周期波形判断；只会背信号名、说不出 wait state 和 response 对流水的影响，按未掌握处理。
