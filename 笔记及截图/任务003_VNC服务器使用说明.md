# 任务03：VNC服务器使用说明

## 本章知识全景图

VNC 在这门课里不是原理课，而是进入远程 Linux/EDA 环境的第一道门。学完本讲的标准不是“知道 VNC 是什么”，而是能稳定完成一次连接、重连、打开终端，并能按失败信号排查。

| 操作阶段 | 起始状态 | 决定性动作 | 成功结果 | 失败先查 |
|---|---|---|---|---|
| 准备客户端 | 本机拿到 VNC Viewer | 打开安装版或免安装版 | 出现 VNC Viewer 主界面 | 软件是否能启动，系统位数是否匹配 |
| 新建连接 | VNC Viewer 已打开 | `File -> New Connection`、`Ctrl+N` 或右键新建 | 出现 Properties 窗口 | 是否找对新建入口 |
| 填服务器 | 已拿到服务器 IP 和端口 | 在 `VNC Server` 填 `IP:端口` | 连接项可以保存 | 英文冒号、IP、端口是否正确 |
| 连接认证 | 已保存连接项 | 双击连接并输入密码 | 进入远程桌面或下一层认证 | 密码来源、网络、服务器状态 |
| 进入工作 | 远程桌面已加载 | 打开 Terminal，执行 `pwd/whoami` | 能在终端输入命令 | 终端入口、桌面菜单、session 状态 |

最短学习路径：先照着步骤连一次，再记录自己的 `VNC Server`、`Name`、密码来源和终端打开路径。以后出错时，不要乱试密码，按“客户端 -> 连接信息 -> 密码 -> 桌面 -> 终端”分层排查。

VNC 可以理解成“去远程实验室的门禁卡”。`VNC Server` 是门牌号，端口是具体房间，密码是门禁，远程桌面只是进门后的大厅，Terminal 才是你真正开始做实验的工位。这个比喻能防止一个常见错误：把“看见桌面”误当成“环境已经会用了”。

## 1. VNC 的任务是把你送进课程服务器

本讲前 10 分钟只解决一件事：把本地电脑连接到课程服务器的远程 Linux 桌面。后续 Linux 命令、VCS、DC、SpyGlass 和项目实验都依赖这个入口。

![VNC 客户端准备](<./screenshots/任务003_VNC服务器使用说明/vnc_client_0240s.jpg>)

视频验证：`02:40-03:00`，画面应能看到老师说明免安装版 VNC Viewer 可以直接双击打开，不需要额外安装流程。

这张图只看起点：VNC Viewer 能打开并进入连接管理界面即可。不要在这里纠结协议原理，本讲的验收对象是一次稳定连接。

这里不要把注意力放在 VNC 协议细节上。本讲要保留的是一条操作链：

1. 拿到自己的服务器 IP、端口和密码信息。
2. 打开 VNC Viewer。
3. 新建连接。
4. 在 `VNC Server` 填 `IP:端口`。
5. 输入密码进入远程桌面。
6. 打开 Terminal，进入真正的 Linux 工作状态。

## 2. 新建连接：目标是进入 Properties 窗口

第一次操作最容易卡在“从哪里新建连接”。视频给了三种入口，任选一种即可：菜单 `File -> New Connection`、快捷键 `Ctrl+N`、空白区域右键 `New Connection`。

![新建连接入口](<./screenshots/任务003_VNC服务器使用说明/new_connection_0310s.jpg>)

视频验证：`03:08-03:35`，画面应看到老师演示或说明三种新建连接入口，并进入 Properties 窗口。

这张图要看动作目标：菜单、快捷键、右键都只是入口，真正的结果是打开 Properties。只要进入 Properties，就不要继续重复找入口。

判断标准很简单：只要看到 Properties 窗口，就说明“新建连接”动作已经完成。此时不要继续找菜单，下一步是填写连接目标。

## 3. `VNC Server` 决定连到哪里，`Name` 只是标签

Properties 窗口里最关键的是 `VNC Server`。它必须填真实服务器地址和端口，典型形式是 `服务器IP:端口`。这个冒号要用英文冒号，端口不能漏。

`Name` 只是本地标签，用来让你以后在 VNC Viewer 里认出这条连接。它可以写姓名、课程名、服务器编号，本身不参与网络连接。

![填写 VNC Server 与 Name](<./screenshots/任务003_VNC服务器使用说明/server_field_0455s.jpg>)

视频验证：`04:55-05:20`，画面应看到老师强调服务器 IP 和端口填在 `VNC Server`，`Name` 可以随便填。

这张图最关键的是字段分工：`VNC Server` 决定网络连接目标，`Name` 只决定你本地怎么认出它。把标签当地址，就像把“我的座位”写在快递地址栏里，系统不知道要送到哪。

常见错误和修正：

| 错误 | 后果 | 修正 |
|---|---|---|
| 把 `Name` 当服务器地址 | 连接目标仍为空或错误 | 服务器地址只填在 `VNC Server` |
| 只填 IP 不填端口 | 连不到自己的 session | 写成 `IP:端口` |
| 使用中文冒号 | 客户端可能无法解析 | 改成英文冒号 `:` |
| 端口抄错 | 连接到错误会话或失败 | 回到课程/助教给的信息核对 |

## 4. 密码登录可能出现两次，不等于前一步失败

双击连接后出现密码框是正常流程。课程环境里，密码通常和易课网登记手机号相关；是否勾选 `Remember Password` 取决于你是否在自己的安全电脑上使用。

![密码输入流程](<./screenshots/任务003_VNC服务器使用说明/password_prompt_0535s.jpg>)

视频验证：`05:35-06:20`，画面应出现连接后的密码输入，以及可选的 Remember Password。

这张图要看认证层级：密码框出现说明客户端已经开始访问目标，不等于前面配置失败。真正失败要看错误提示和是否反复回到同一认证框。

本讲最容易误判的一点是：远程桌面加载过程中可能再次要求输入密码。这不一定说明第一次输错，而可能是连接认证和桌面会话登录分成了两步。判断是否失败，要看是否出现明确错误提示、是否能进入桌面、是否反复回到同一个认证框。

密码失败时按这个顺序查：

1. 是否复制了空格或换行。
2. 是否连到了自己的服务器和端口。
3. 密码是否确实是课程环境给定的手机号或指定密码。
4. 是否网络/VPN 中断导致认证超时。
5. 是否服务器 session 已失效，需要重新分配或重启。

## 5. 成功状态：进入远程桌面，但真正工作在终端里

成功登录后会进入远程 Linux 桌面。这个桌面只是图形入口，不是主要工作方式。后续课程最重要的窗口是 Terminal。

![远程桌面结果态](<./screenshots/任务003_VNC服务器使用说明/remote_desktop_0720s.jpg>)

视频验证：`07:20-08:30`，画面应能看到远程桌面和终端窗口，老师提醒不要随便关掉终端。

这张图要把“桌面”和“工作窗口”分开看：绿色桌面只是远程环境加载成功，终端提示符才说明你能执行 Linux 命令。

进入桌面后，先确认三件事：

| 检查项 | 为什么要查 | 成功信号 |
|---|---|---|
| 桌面是否加载完成 | 避免黑屏或卡住误判 | 菜单、窗口、鼠标可操作 |
| 终端是否存在 | 后续命令练习都在终端中进行 | 能看到命令提示符 |
| 终端能否执行命令 | 确认 session 可用 | `pwd/whoami` 有输出 |

## 6. 打开终端：不要死记右键菜单

普通 Linux 桌面可能右键就能打开终端，但课程服务器不一定有这个右键入口。视频里实际推荐路径是顶部菜单：`Applications -> System Tools -> Terminal`。

![打开 Terminal 路径](<./screenshots/任务003_VNC服务器使用说明/terminal_path_1615s.jpg>)

视频验证：`16:15-16:40`，画面应看到老师说明从 `Applications -> System Tools -> Terminal` 打开终端。

这张图的教学职责是保留菜单路径。右键打不开终端时，不要判断系统坏了，先走顶部菜单路径。

终端打开后，立即执行：

```bash
pwd
whoami
```

`pwd` 用来确认当前位置，`whoami` 用来确认当前用户。能看到这两个输出，才算从“连上桌面”进入“可工作环境”。

## 7. 下次重连：优先复用已保存连接

第一次配置完成后，下次不需要重新创建连接。打开 VNC Viewer，双击已保存的连接即可。只有服务器地址、端口、密码或 session 状态变化时，才需要重新配置。

重连失败不要急着删连接，先按表排查：

| 失败信号 | 优先检查 | 成功信号 |
|---|---|---|
| 双击无响应 | VNC Viewer 是否卡死，网络是否可用 | 出现连接进度或密码框 |
| 提示连接失败 | IP、端口、VPN、服务器状态 | 出现密码框或桌面加载 |
| 密码不通过 | 密码来源、空格、是否连接错对象 | 通过认证 |
| 黑屏或桌面卡住 | session 是否异常，尝试重连一次 | 桌面可操作 |
| 找不到终端 | 走 `Applications -> System Tools -> Terminal` | 终端可输入命令 |

## 8. 本讲自测与答案

| 自测题 | 合格答案 |
|---|---|
| VNC 在这门课里解决什么问题 | 连接课程服务器，进入远程 Linux/EDA 环境 |
| `VNC Server` 和 `Name` 区别是什么 | `VNC Server` 是真实连接地址，`Name` 是本地标签 |
| 为什么可能输入两次密码 | 一次可能是连接认证，一次可能是桌面会话登录 |
| 进入桌面后为什么要打开 Terminal | 后续 Linux、脚本和 EDA 工具主要在终端里操作 |
| 连不上时先查什么 | IP、端口、英文冒号、网络/VPN、服务器状态，再查密码 |

最小通过任务：完成一次 VNC 登录，打开终端，执行 `pwd` 和 `whoami`，记录当前路径和用户名。能稳定完成这四步，才算本讲真正过关。
