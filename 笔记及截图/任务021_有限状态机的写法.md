# 任务21：有限状态机的写法

## 本章知识全景图

### 一眼看懂这讲在讲什么

- **本章主题**：把有限状态机从状态图稳定翻译成可综合、可仿真、可调试的 RTL。
- **核心概念**：FSM、状态、状态转移图、Moore、Mealy、三段式、`current_state`、`next_state`、输出逻辑、波形验证。
- **逻辑主线**：状态机用有限个状态记录历史，用输入决定下一状态，用输出驱动控制；三段式写法把状态寄存器、次态组合逻辑和输出逻辑分开，降低漏转移、漏输出和波形难定位的风险。
- **最短学习路径**：先定义接口和状态，再画转移图，决定 Moore/Mealy，最后写三段式 RTL 并用波形检查 `current_state -> next_state -> output`。

| 概念层级 | 核心概念 | 前置知识 | 延伸应用 |
|---|---|---|---|
| 控制抽象 | FSM | 时序逻辑、寄存器 | 协议控制、数据通路调度 |
| 设计输入 | 状态图 | 输入/输出定义 | 需求到 RTL |
| 输出模型 | Moore / Mealy | 组合逻辑、时钟边沿 | 稳定性与响应速度取舍 |
| RTL 结构 | 三段式 | `always_ff`、`always_comb` | 可维护状态机 |
| 验证证据 | 波形 | 当前状态、输入、输出 | debug 与审查 |

**状态机不是一段 `case` 代码，而是一张状态转移关系；RTL 只是把这张关系分成“保存当前状态、计算下一状态、产生输出”三块硬件。**

## 1. FSM 适合做控制：用状态保存历史，用转移表达规则

有限状态机适合处理“当前动作取决于历史”的控制问题。自动售货机是典型例子：是否出货不只看当前投币，还看之前已经累计了多少金额。

![自动售货机接口](<./screenshots/任务021_有限状态机的写法/fsm_intro_vending_250s.jpg>)

🔍 视觉验证：视频 01:30-05:00（售货机接口页：应看到 2.5 元饮料售货机的投币输入、出货和找零输出。）

售货机问题包含四类对象：

| 对象 | 示例 | RTL 中的对应 |
|---|---|---|
| 输入 | 投 5 毛、投 1 元、复位 | `half`、`one`、`rst_n` |
| 状态 | 已投 0、0.5、1.0、1.5、2.0 元 | `current_state` |
| 转移 | 当前金额 + 新投币 = 下一金额 | `next_state` 组合逻辑 |
| 输出 | 出货、找零 | output logic |

状态机的价值是把“历史”变成有限个可命名状态。没有状态，控制逻辑会变成一堆难审查的条件判断。

## 2. 先画状态图，再写 RTL

状态图是状态机的设计源，不是课件装饰。圆点表示状态，箭头表示输入触发的转移，箭头旁通常标条件或输出。没有状态图直接写 `case`，很容易漏状态、漏转移、漏默认恢复。

![状态转移图](<./screenshots/任务021_有限状态机的写法/state_graph_610s.jpg>)

🔍 视觉验证：视频 05:00-10:00（状态转移图页：应看到售货机状态节点、转移箭头和状态编码表。）

读这张图时不要把它当“流程图截图”，而要把它当成状态机的合同：每个圆点是一种被寄存器保存的历史，每条箭头是一条允许发生的交易规则，箭头没画出来就表示这条路在设计里不存在。自动售货机的状态像一个只记“当前已投金额”的账本，输入只是新来的硬币，状态转移才是“账本余额怎么更新”的规则。

设计顺序：

1. 明确输入输出接口。
2. 定义每个状态的语义。
3. 画状态转移图。
4. 决定 Moore 还是 Mealy。
5. 选择状态编码。
6. 写三段式 RTL。
7. 写 testbench，用波形检查状态跳转和输出。

状态编码也要作为设计选择说明：

| 编码 | 形式 | 优点 | 风险 |
|---|---|---|---|
| binary | 少量 bit 表示多个状态 | 触发器少 | 解码逻辑可能复杂 |
| one-hot | 每个状态一个 bit | 解码简单，常利于速度 | 触发器多，非法状态要恢复 |
| gray | 相邻状态少 bit 翻转 | 某些跨域/低翻转场景有用 | 编码管理更复杂 |

课程示例使用表格列状态编码，目的就是让 RTL 和状态图可对照。

## 3. Moore FSM：输出只依赖当前状态

Moore 状态机的输出由当前状态决定。它的输出通常更稳定，因为输入变化不会在同一拍直接穿过组合逻辑影响输出。

![Moore FSM RTL](<./screenshots/任务021_有限状态机的写法/moore_machine_1120s.jpg>)

🔍 视觉验证：视频 10:00-20:00（Moore FSM RTL 页：应看到状态寄存器、next-state 判断和只依赖状态的输出逻辑。）

Moore 关系：

```text
next_state = f(current_state, input)
output     = g(current_state)
```

优点：

- 输出只随状态更新而改变，波形更容易看。
- 输出对输入毛刺不敏感。
- 适合控制寄存器、片外接口控制、跨模块稳定控制信号。

代价：

- 响应可能慢一拍。
- 有时需要更多状态表达“刚收到输入但下一拍才输出”的阶段。

Moore 输出常见写法：

```systemverilog
always_comb begin
    out  = 1'b0;
    cout = 1'b0;

    unique case (current_state)
        S_DONE: out = 1'b1;
        S_CHG : begin
            out  = 1'b1;
            cout = 1'b1;
        end
        default: ;
    endcase
end
```

这里输出不直接看投币输入，只看当前状态。

## 4. Mealy FSM：输出依赖当前状态和输入

Mealy 状态机的输出同时依赖当前状态和输入。它响应更快，但输出可能受输入毛刺影响，组合路径也可能更长。

![Mealy FSM RTL](<./screenshots/任务021_有限状态机的写法/mealy_machine_1640s.jpg>)

🔍 视觉验证：视频 24:00-30:00（Mealy FSM RTL 页：应看到输出逻辑同时依赖当前状态和输入条件。）

Mealy 关系：

```text
next_state = f(current_state, input)
output     = g(current_state, input)
```

适用场景：

- 输入稳定可控；
- 需要同拍响应；
- 输出不会直接驱动敏感外部接口，或后面会再打一拍。

风险：

- 输入毛刺可能变成输出毛刺；
- 输出路径从输入穿过组合逻辑，时序压力更大；
- 波形 debug 时必须同时看 `current_state` 和输入。

工程建议：如果输出要跨模块、驱动片外、参与复杂握手，优先使用 Moore 或把 Mealy 输出寄存一拍。

## 5. Moore 和 Mealy 的选择落在波形验收上

二者差异不只是定义不同，而是波形和时序风险不同。前面 Moore 代码页的输出只从状态译码得到，Mealy 代码页的输出把输入条件也纳入组合判断；这个差异决定了输出是“随状态稳定变化”，还是“可能随输入同拍变化”。

可以把 Moore / Mealy 的区别理解成“先盖章再出货”和“边看柜台边出货”：Moore 先让状态寄存器在时钟边沿盖章，输出再按盖章后的状态产生，所以稳定但可能慢一拍；Mealy 在当前状态之外还直接看输入，响应快，但输入抖动会像柜台上突然伸进来的手，可能把输出也带着抖一下。

| 类型 | 输出依赖 | 波形特征 | 适合 |
|---|---|---|---|
| Moore | 当前状态 | 状态改变后输出改变 | 稳定控制、片外接口、寄存输出 |
| Mealy | 当前状态 + 输入 | 输入变化可能同拍影响输出 | 快速响应、输入稳定的内部控制 |

验收时要这样问：

- 输出变化是否只发生在状态寄存器更新后？
- 输入同拍变化是否会直接影响输出？
- 这个输出是否需要打一拍才能给下游使用？
- 如果输入有毛刺，输出会不会误触发？

## 6. 三段式 FSM：把硬件结构写清楚

三段式不是形式主义，它把状态机拆成三个可检查的硬件块：状态寄存器、次态组合逻辑、输出逻辑。这样写，波形和代码能一一对应。

![三段式 FSM](<./screenshots/任务021_有限状态机的写法/three_block_fsm_1870s.jpg>)

🔍 视觉验证：视频 18:30-23:00（三段式 FSM 页：应看到状态寄存器、次态逻辑和输出逻辑被拆开，并标注 `current_state`/`next_state`。）

这一组图要分工读：总图看三段式边界，状态寄存器图只看 `current_state` 如何在时钟边沿更新，次态逻辑图只看输入和当前状态如何组合出 `next_state`。三段式的价值不是让代码变长，而是让 debug 有落点：哪一段错，就查哪一类硬件。

### 第一段：状态寄存器

![状态寄存器](<./screenshots/任务021_有限状态机的写法/state_register_2035s.jpg>)

🔍 视觉验证：视频 20:25-20:45（状态寄存器页：应看到 `current_state` 作为寄存器输出，只在时钟边沿更新。）

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        current_state <= S_IDLE;
    else
        current_state <= next_state;
end
```

这段综合成状态寄存器。它回答“当前状态保存在哪里、什么时候真正跳转”。

### 第二段：次态组合逻辑

![次态逻辑](<./screenshots/任务021_有限状态机的写法/next_state_logic_2110s.jpg>)

🔍 视觉验证：视频 21:00-21:20（次态逻辑页：应看到 `next_state` 由当前状态和输入组合计算。）

```systemverilog
always_comb begin
    next_state = current_state;

    unique case (current_state)
        S_IDLE: begin
            if (half)      next_state = S_05;
            else if (one)  next_state = S_10;
        end
        S_20: begin
            if (half)      next_state = S_DONE;
            else if (one)  next_state = S_CHG;
        end
        S_DONE,
        S_CHG: next_state = S_IDLE;
        default: next_state = S_IDLE;
    endcase
end
```

这段必须有默认赋值和非法状态恢复。否则容易产生 latch 或让状态机卡在未知状态。

### 第三段：输出逻辑

```systemverilog
always_comb begin
    out  = 1'b0;
    cout = 1'b0;

    unique case (current_state)
        S_DONE: out = 1'b1;
        S_CHG: begin
            out  = 1'b1;
            cout = 1'b1;
        end
        default: ;
    endcase
end
```

输出逻辑要明确是 Moore 还是 Mealy。Moore 输出只看 `current_state`；Mealy 输出还会看输入。

## 7. 为什么要区分 `current_state` 和 `next_state`

`current_state` 是现在被寄存器保存的状态，`next_state` 是组合逻辑算出的下一拍候选状态。混在一起会让仿真、综合和波形分析都变得模糊。

更准确地说，`next_state` 是本拍组合逻辑先写好的“草稿”，只有下一个时钟边沿到来，它才会被状态寄存器“盖章”成为 `current_state`。草稿错，查转移条件；草稿对但盖章没变，查时钟、复位或 enable；盖章对但动作错，查输出译码。这个三分法能把大多数 FSM debug 从盲猜变成定位。

硬件结构：

```text
current_state 寄存器输出
    -> 组合逻辑根据 input 算 next_state
    -> 下一个时钟边沿写回 current_state
```

这一区分能回答四个 debug 问题：

- 当前到底处于哪个状态？
- 下一拍准备跳到哪个状态？
- 哪个输入触发了跳转？
- 输出是由当前状态还是当前输入直接决定？

如果状态跳错，先看 `next_state` 是否已算错；如果 `next_state` 正确但 `current_state` 没跳，查时钟、复位、使能或状态寄存器。

## 8. `case` 写法的常见坑

FSM 的 bug 经常藏在 `case` 里。

![full-case 与默认分支风险](<./screenshots/任务021_有限状态机的写法/full_case_latch_risk_2260s.jpg>)

🔍 视觉验证：视频 37:40-38:00（full-case 风险页：应看到“定义完全状态”“避免锁存器 latch”“额外延时”和“异步时序问题”这些提示。）

必须检查：

- `case` 是否覆盖所有合法状态；
- 组合逻辑开头是否有默认赋值；
- 是否有 `default` 把非法状态带回安全状态；
- 输出是否在所有路径赋值；
- 状态跳转条件是否互斥或有优先级；
- reset 是否进入确定初始状态。

推荐使用 `typedef enum`：

```systemverilog
typedef enum logic [2:0] {
    S_IDLE,
    S_05,
    S_10,
    S_15,
    S_20,
    S_DONE,
    S_CHG
} state_e;

state_e current_state, next_state;
```

枚举比裸参数更可读，也更利于波形查看和 lint 检查。大型工程中，状态名就是文档的一部分。

## 9. 波形验证：看状态、输入、次态和输出是否对齐

FSM 的最终证据不是“代码看起来像三段式”，而是波形能解释每一次跳转。

![波形调试](<./screenshots/任务021_有限状态机的写法/wave_debug_2505s.jpg>)

🔍 视觉验证：视频 34:42-47:00（波形验证页：应看到 `current_state`、输入和输出被加入波形以检查状态跳转。）

波形检查顺序：

1. reset 后 `current_state` 是否为初始状态。
2. 输入变化时 `next_state` 是否立即变成预期候选。
3. 下一个时钟边沿 `current_state` 是否更新为 `next_state`。
4. 输出是否符合 Moore/Mealy 预期。
5. 非法输入或非法状态是否能回到安全状态。

售货机例子里，一次完整检查可以写成：

```text
reset -> S_IDLE
投 1 元 -> next_state=S_10
下拍 current_state=S_10
再投 1 元 -> next_state=S_20
再投 5 毛 -> next_state=S_DONE
S_DONE 时 out=1
下一拍回 S_IDLE
```

如果波形中 `next_state` 正确但 `current_state` 不变，查时钟/复位；如果 `current_state` 正确但输出不对，查输出逻辑；如果 `next_state` 本身错，查状态转移条件。

最小仿真入口可以按下面组织：

```text
rtl/fsm_vending.sv
tb/tb_fsm_vending.sv
filelist.f
```

`filelist.f` 至少包含 RTL 和 TB：

```text
./rtl/fsm_vending.sv
./tb/tb_fsm_vending.sv
```

运行口径：

```bash
vcs -full64 -sverilog -f filelist.f -debug_access+all -l compile.log
./simv -l sim.log
verdi -f filelist.f -ssf fsm_vending.fsdb &
```

TB 的 PASS 条件不能只写“跑完不报错”，而要检查一条完整交易链：reset 后回到 `S_IDLE`，投币序列推动 `next_state`，时钟边沿后 `current_state` 跟上，达到出货状态时 `out=1`，找零状态时 `cout=1`，最后回到 `S_IDLE`。失败时按三段式定位：`next_state` 错查转移表，`current_state` 不跟查时钟/复位，输出错查 Moore/Mealy 输出段。

## 10. 和 AI+IC / NPU 学习的连接

NPU 里的控制器几乎都是状态机：DMA 搬运、AXI/AHB 事务、卷积 tile 调度、FIFO 读写控制、算子 pipeline 启停、异常恢复。真正能写 FSM，意味着你能把“流程需求”变成“可综合控制逻辑”。

NPU 控制 FSM 最小交付口径：

```text
接口：start/done/ready/valid/error
状态：IDLE/LOAD/COMPUTE/STORE/DONE/ERROR
转移：每个状态遇到哪些输入去哪里
输出：每个状态驱动哪些控制信号
异常：非法状态、timeout、reset 如何恢复
验证：波形中 current_state/next_state/output 是否对齐
```

写状态机不是画漂亮状态图，而是让控制逻辑能被综合、能被仿真、能被别人审查和维护。

## 复习与自测

1. **判断题**：FSM 可以直接先写 `case`，状态图只是辅助说明。  
   **答案**：不建议。状态图是设计源，先画状态和转移能避免漏状态、漏转移和漏恢复。

2. **对比题**：Moore 和 Mealy 的核心区别是什么？  
   **答案**：Moore 输出只依赖当前状态；Mealy 输出依赖当前状态和输入。Moore 稳定但可能慢一拍，Mealy 响应快但输出更易受输入毛刺影响。

3. **结构题**：三段式 FSM 的三段分别是什么？  
   **答案**：状态寄存器、次态组合逻辑、输出逻辑。

4. **debug 题**：波形中 `next_state` 正确，但下一个时钟边沿 `current_state` 没变，先查什么？  
   **答案要点**：查时钟边沿是否到来、reset 是否仍有效、状态寄存器是否有 enable 或写法问题。

5. **工程题**：为什么 FSM 要有 `default` 恢复？  
   **答案要点**：状态寄存器可能因复位、X 传播、软错误或设计 bug 进入非法编码；`default` 把非法状态带回安全状态，避免控制逻辑卡死。
