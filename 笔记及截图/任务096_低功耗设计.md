# 任务96：低功耗设计

## 本章知识全景图

这一讲解决一个前端 RTL 工程师必须会回答的问题：芯片功耗从哪里来，RTL 到底能改哪一部分。结论很明确：电压、工艺、版图电容多半不是普通 RTL 的直接控制项，RTL 最能控制的是无效翻转和 clock enable 的准确性。

| 层级 | 核心概念 | 这一层要抓住的判断 |
|---|---|---|
| 电路来源 | 动态功耗、静态功耗 | 有翻转会耗电，不翻转也可能因漏电耗电。 |
| 动态功耗 | 开关功耗、短路功耗 | 数字电路反复给负载电容充放电；输入翻转过渡期间 PMOS/NMOS 可能短暂同时导通。 |
| 公式入口 | $P_{switch} \approx \alpha C V_{DD}^{2} f$ | 前端最常能动的是翻转率 $\alpha$，不是随意改 $V_{DD}$ 或工艺。 |
| RTL 优化 | enable、idle、无效计数 | 不需要更新的寄存器、计数器、数据通路不应每拍跳动。 |
| Clock gating | ICG、多级 gating、enable 合并 | 低功耗不等于手写 `clk & en`，而是生成正确 enable，让工具或工艺库插入可靠门控。 |
| 系统边界 | power gating、multi-VT、DVFS、body bias | 这些方法有效，但多属于架构、后端、工艺或电源管理协同，不是单个 RTL 文件能独立完成。 |

最短学习路径：

```text
CMOS 翻转为什么耗电
  -> 动态功耗拆成开关功耗和短路功耗
  -> 静态功耗来自漏电
  -> 前端主要降低翻转率
  -> 用 enable 写出可门控的 RTL
  -> 用 ICG / 多级 clock gating 控制空闲模块
  -> 理解 power gating、multi-VT、DVFS 的工程边界
```

## 1. 功耗要先拆成动态功耗和静态功耗

功耗不是一个单一来源；动态功耗看“电路是否在切换”，静态功耗看“电路即使不切换仍然漏多少电”。

动态功耗主要包含两部分：

| 类型 | 来源 | 机制 | 设计含义 |
|---|---|---|---|
| 开关功耗 | 负载电容充放电 | 输出节点每次 0/1 翻转都要对等效电容充电或放电。 | 翻转越频繁，功耗越高。 |
| 短路功耗 | PMOS/NMOS 短暂同时导通 | 输入边沿经过中间电平时，上下管可能形成 VDD 到 GND 的瞬时通路。 | 边沿越慢、同时导通时间越长，短路功耗越明显。 |
| 静态功耗 | 漏电流 | 晶体管关断也不是理想绝缘，先进工艺下漏电可能不可忽视。 | 空闲但不断电的模块仍会耗电。 |

常用近似式是：

$$
P_{switch} \approx \alpha C V_{DD}^{2} f
$$

$\alpha$ 是翻转率，$C$ 是等效电容，$V_{DD}$ 是供电电压，$f$ 是频率。这个公式给前端的第一条规则是：不要让无意义的逻辑一直翻转。

## 2. 电压和工艺收益很大，但 RTL 通常不能直接改它们

降低 $V_{DD}$ 对动态功耗特别有效，因为功耗近似与 $V_{DD}^{2}$ 成正比。比如从 1.2 V 降到 0.6 V，在 $C$、$\alpha$、$f$ 不变时，开关功耗近似变成原来的四分之一。

但这不是普通 RTL 工程师每天可以随意改的旋钮：

| 项 | 谁主要决定 | RTL 的真实影响 |
|---|---|---|
| 工艺节点 | 产品定位、成本、代工资源 | 只能理解其影响，不能在 RTL 中切换工艺。 |
| $V_{DD}$ | 电源架构、工艺库、电压域规划 | 通常由系统和后端约束决定。 |
| $f$ | 性能目标、时钟规划 | RTL 可减少局部活动，但不能随意把系统频率降到不满足吞吐。 |
| $C$ | 标准单元、负载、扇出、布线 | RTL 可通过少翻转、少大扇出控制间接影响，主要仍靠综合和后端优化。 |

前端低功耗的主战场不是“我把电压调低”，而是“我让不该切换的逻辑不切换”。

## 3. 无效翻转是 RTL 最直接的功耗浪费

无效翻转是功能上不需要、但电路仍然每拍变化的信号。它不改变正确结果，却会真实消耗动态功耗。

一个典型坏例子：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    cnt <= '0;
  else
    cnt <= cnt + 1'b1;   // 即使当前状态不需要 cnt，也一直翻转
end
```

更合理的写法：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    cnt <= '0;
  else if (cnt_en)
    cnt <= cnt + 1'b1;
end
```

这不是语法美化，而是把功耗公式里的 $\alpha$ 降下来。写 RTL 时要问一个硬问题：当前状态下这个寄存器、计数器、FIFO 指针或数据通路有没有必要更新？如果没有，就应该有 enable、保持条件或上层 idle 约束。

## 4. Clock gating 是前端最常用的低功耗工具

Clock gating 的本质是：寄存器不需要更新时，不让有效 clock 进入这一组寄存器。clock 不进入，寄存器本身、局部 clock tree 和后级组合逻辑的切换都会减少。

普通 enable 写法：

```systemverilog
always_ff @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    q <= '0;
  else if (en)
    q <= d;
end
```

功能等价关系可以简化理解为：

```text
en = 1:
  gated clock 有有效边沿，q 捕获 d

en = 0:
  gated clock 不送入寄存器，q 保持旧值
```

工程上不应随手写：

```systemverilog
assign gclk = clk & en;
```

原因是普通组合门可能引入 glitch、占空比破坏和时序问题。更稳的做法是写出综合工具能识别的 enable pattern，让工具插入工艺库里的 ICG cell；若项目要求手动例化，也应例化经过库和时序约束支持的 ICG，而不是手工与门。

## 5. Clock enable 的准确性决定低功耗质量

Clock gating 难点不是知道有 ICG，而是能不能产生正确 enable。enable 太保守，省电少；enable 太激进，功能错。

| 要求 | 含义 | 失败信号 |
|---|---|---|
| 功能等价 | 关钟期间寄存器本来就不该更新。 | 状态机卡死、请求丢失、计数少一次、数据没写入。 |
| 空闲覆盖充分 | 尽量识别长时间 idle 周期。 | 功耗报告中 clock/network power 仍然偏高。 |
| 唤醒可靠 | 新请求、外设响应、中断清除等事件能重新打开 clock。 | 模块睡死，软件写寄存器无响应。 |
| 时序可收敛 | enable 到 ICG 的路径不能成为新瓶颈。 | 修 timing 时面积和功耗被反向放大。 |

把它放回本课程的 IP 中：

```text
eFlash controller:
  没有 AHB 访问、没有 erase/program/read FSM 活动、没有 pending interrupt 时，才可能进入模块空闲。

SD host:
  没有 command 发送、没有 data 收发、没有 DMA 搬运、没有 card busy 等待时，才可能关掉局部时钟。
```

不能因为 AHB 侧暂时没访问就关钟。eFlash 正在 program、SD card 正在 busy、DMA 正在等待 bus grant，这些都属于“看起来没新请求，但内部事务仍未结束”的状态。

## 6. Power gating、multi-VT、DVFS 只需掌握边界

这些低功耗方法都重要，但前端职责不同。

| 方法 | 主要降低 | 工程边界 | 前端必须知道的点 |
|---|---|---|---|
| Clock gating | 动态功耗 | RTL + 综合 + ICG | 写出准确 enable，减少无效翻转。 |
| Power gating | 待机漏电 | 架构、低功耗方案、后端 | 断电域需要 isolation、retention、唤醒顺序。 |
| Multi-VT | leakage | 综合、时序、后端 | 非关键路径可用高 VT 降漏电，关键路径可能需要低 VT 保速度。 |
| DVFS | 动态功耗和能效 | 系统、电源管理、软件策略 | 降频降压要看任务时间，瞬时功耗低不等于总能量一定低。 |
| Body bias | 速度/漏电权衡 | 工艺和后端 | 属于物理实现策略，普通 RTL 不直接操作。 |

面试或项目讨论中，不要只背名词。合格说法是：前端最常直接参与 clock gating；power gating 涉及电源域和状态保存；multi-VT 是 timing 与 leakage 的权衡；DVFS 要看负载、性能和能量总账。

## 7. Clock gating 要分层，不是到处插门控

高质量低功耗设计有层次：系统级关 IP，模块级关子功能，局部级关寄存器组。层次越粗，潜在收益越大，但控制、唤醒和验证越复杂；层次越细，控制更精确，但 enable 逻辑、时序和布局成本更高。

```text
系统级:
  软件或电源管理单元决定某个 IP 长时间不用。

模块级:
  IP 内部根据事务状态决定 active/idle。

局部级:
  FSM、counter、FIFO、datapath 根据局部 enable 更新。
```

多级 gating 的真正目标不是“门控越多越好”，而是找到长时间空闲、控制条件清晰、唤醒路径可靠、时序能收敛的门控点。视频后段展示的 multi-stage clock gating 和 local clock gating/decloning，本质都是在“功耗收益、enable 复杂度、时序路径、布局约束”之间找平衡。

## 深层理解：低功耗是在关阀门，不是在拔电源

RTL 低功耗最好的直觉不是“让芯片少工作”，而是像一栋大楼的水电系统：没人用的楼层要关灯，没水流的支路要关阀，但消防系统、门禁和电梯不能因为省电被关掉。Clock gating 就是给时钟水管加阀门，enable 是阀门钥匙；钥匙错了，比不省电更糟，因为它会把还在工作的房间也断掉。

这个比喻能精确落到工程边界：

| 低功耗动作 | 像什么 | RTL 关键问题 |
|---|---|---|
| 减少无效翻转 | 关掉空房间的灯 | enable 是否覆盖真正 idle 周期 |
| ICG clock gating | 在主水管上装合格阀门 | 是否无 glitch，是否可被综合/CTS 正确处理 |
| 局部门控 | 支路阀门 | enable 逻辑是否过长、过碎、难收敛 |
| Power gating | 整层断电 | isolation/retention/wakeup 是否齐全 |
| DVFS | 调水压和水流速度 | 性能、时序、电源管理是否协同 |

前端工程师真正能抓住的是翻转率 $\alpha$。在 NPU 里，一个 tile 没有计算时，地址生成器、FIFO 指针、valid 链、寄存器堆如果仍每拍跳，就像空厂房里传送带一直转。Clock gating 的价值不只是省掉寄存器翻转，还会减少时钟树本身的功耗；但它的代价是 enable 变成新的控制路径，可能引入时序、验证和 DFT 问题。

## AI+IC 连接

NPU、GPU、视频编解码和 SD/eFlash 控制器的共同点是：数据通路很宽，寄存器很多，局部模块经常处在阶段性空闲状态。AI 芯片的功耗墙并不只来自 MAC 阵列本身，片上 SRAM、NoC、DMA、寄存器堆和控制逻辑的无效翻转也会累积成大功耗。

检查一个 NPU RTL 时，可以直接复用这一讲的方法：

1. 找出每拍都在跳的计数器、地址生成器、FIFO 指针和 valid/ready 链路。
2. 判断它们是否只在特定 layer、tile、burst 或 transaction 中有效。
3. 给寄存器组写出功能等价的 enable。
4. 用仿真保证 enable 关停不丢事务。
5. 用功耗分析报告检查 clock/network/register power 是否下降。

## 工程练习

1. 找一个自己写过的 FSM，列出哪些 counter 只在部分状态有效。
2. 把一个“每拍自增”的计数器改成 `cnt_en` 控制，并说明功能为什么等价。
3. 给 eFlash controller 写一个模块级 `flash_idle` 条件，至少考虑 erase/program/read FSM、pending interrupt 和 AHB 访问。
4. 给 SD host 写一个 `sd_clk_can_stop` 条件，至少考虑 FIFO 满、DMA grant、card busy 和协议尾部 clock。
5. 检查 enable 是否跨模块路径过长，是否可能成为 timing 问题。

## 常见误区和失败信号

| 误区 | 正确判断 |
|---|---|
| 低功耗就是降频。 | 降频降低瞬时功耗，但任务时间可能变长，总能量不一定最低。 |
| Clock gating 就是 `clk & en`。 | 正确实现应使用 ICG cell 或工具识别的 enable pattern。 |
| enable 越激进越好。 | 关掉必要 clock 会造成功能错误。 |
| 静态功耗可以忽略。 | 先进工艺和长 standby 场景中 leakage 可能很重要。 |
| 前端不负责功耗。 | 前端至少负责无效翻转、idle 识别和 clock enable。 |

## 自测参考答案与判分点

1. 答：开关功耗和短路功耗。开关功耗来自负载电容充放电；短路功耗来自输入翻转期间 PMOS/NMOS 短暂同时导通。  
   判分点：必须同时说出两部分，并能指出它们各自对应的物理来源。

2. 答：开关功耗近似与 $V_{DD}^{2}$ 成正比，电压降低会带来平方级收益。  
   判分点：不仅要说“电压影响大”，还要说出平方关系。

3. 答：翻转率 $\alpha$。RTL 可以减少无效翻转，电压、工艺和物理电容通常不是普通 RTL 的直接控制项。  
   判分点：要区分 RTL 直接可控项和工艺/物理实现侧变量。

4. 答：准确的 clock enable。它必须保证功能等价、覆盖空闲周期、可唤醒、可收敛。  
   判分点：不能只答“门控时钟”，要说 enable 的正确性和工程边界。

5. 答：clock gating 停时钟，主要降低动态功耗；power gating 断电源，可降低待机漏电，但需要 isolation、retention 和唤醒控制。  
   判分点：要同时答出“主要降低哪类功耗”和“额外的系统代价”。

## 工程核对口径

给一个 RTL 模块做低功耗评审时，按下面五步走：

1. 列出高翻转对象：counter、FSM、FIFO pointer、wide datapath、valid/ready 链、寄存器堆。
2. 判断 idle 条件：哪些周期功能上不需要更新，哪些周期必须保持唤醒。
3. 写出 enable 等价性：加门控前后，所有有效事务的输出和状态必须一致。
4. 检查实现方式：优先让综合工具识别 clock enable 或例化库里的 ICG，不手写 `clk & en`。
5. 用仿真和功耗报告闭合：功能回归不坏，clock/register/network power 下降，enable 路径不成为新 timing 瓶颈。

若 enable 关闭后丢事务，说明阀门关错；若功耗报告没有下降，说明阀门没关在主要水路上；若 timing 变差，说明省电控制本身变成了新的拥堵点。
