# Verilog 到 RTL 设计总复盘：语法最终要落到寄存器、组合逻辑和验证

## 本章知识全景图

Verilog 的学习终点不是“能写合法代码”，而是“能预测这段代码会怎样仿真、会不会综合、会生成什么硬件、应该怎样验证”。

| 问题 | 判断口径 |
|---|---|
| 这段代码是什么层次 | testbench、行为模型、RTL、门级、网表 |
| 它保存状态吗 | 有无时钟边沿、锁存条件、复位 |
| 它是组合逻辑吗 | 输入变输出是否立即由完整赋值决定 |
| 它会综合成什么 | mux、加法器、比较器、触发器、锁存器、存储器 |
| 它怎么验证 | 激励、波形、打印、自检查、虚拟模型、scoreboard |

## 1. RTL 的最低定义

RTL 是寄存器传输级。它关心的是：

```text
哪些寄存器在时钟边沿更新
更新条件是什么
寄存器之间经过哪些组合逻辑
控制信号怎样决定数据走哪条路
```

一个最小 RTL 模块至少能画出：

```text
input -> combinational logic -> register -> combinational logic -> output
                         ^          |
                         |          v
                    control/FSM ----+
```

如果代码里只有“执行步骤”，却说不清寄存器、组合路径和控制信号，就还停留在软件式思维。

## 2. 语法到硬件对照表

| Verilog 写法 | 常见硬件含义 | 关键风险 |
|---|---|---|
| `module` | 硬件边界或验证模型边界 | 端口方向和位宽错会贯穿系统 |
| `wire` | 连接线、组合网络 | 不能在过程块中赋值 |
| `reg` | 过程赋值变量 | 不一定是触发器，取决于 always 写法 |
| `assign` | 连续组合逻辑 | 多驱动、位宽截断、三态边界 |
| `always @*` | 组合逻辑 | 分支不完整会推 latch |
| `always @(posedge clk)` | 边沿触发寄存器 | 时钟、复位、非阻塞赋值规则 |
| `if/else` | mux 或优先级逻辑 | 缺 else、优先级过深 |
| `case` | 多路选择或译码 | 缺 default、`casex` 掩盖未知值 |
| `for` | 静态展开或仿真循环 | 动态边界不可综合 |
| `task/function` | 代码封装或组合逻辑展开 | 不能用仿真时间控制混入 RTL |
| `$display/$stop` | 仿真观察 | 不属于硬件 |
| `#delay` | 仿真时间推进 | 不属于普通可综合等待 |

## 3. 组合逻辑的总规则

组合逻辑是无记忆函数：

```text
当前输出 = f(当前输入)
```

组合块安全模板：

```verilog
always @* begin
  y = 1'b0;
  next_state = state;

  case (sel)
    2'd0: y = a;
    2'd1: y = b;
    2'd2: y = c;
    2'd3: y = d;
    default: y = 1'b0;
  endcase
end
```

检查表：

| 检查 | 通过标准 |
|---|---|
| 敏感列表 | 用 `always @*` 或 SystemVerilog `always_comb` |
| 默认值 | 每个输出进入分支前有默认值，或每个分支完整赋值 |
| 赋值符号 | 组合过程内优先用阻塞赋值 `=` |
| 输出所有者 | 同一个变量只由一个过程或连续赋值所有者驱动 |
| 延迟 | 不用 `#delay` 表示硬件等待 |

组合逻辑最常见的三个 bug：

1. 少写某个分支，综合出锁存器。
2. 敏感列表漏信号，仿真和综合不一致。
3. 把很长表达式写成一拍完成，时序跑不动。

## 4. 时序逻辑的总规则

时序逻辑是边沿采样：

```text
下一拍寄存器值 = f(当前寄存器值, 当前输入)
```

时序块安全模板：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) begin
    q <= RESET_VALUE;
  end else if (en) begin
    q <= d;
  end
end
```

检查表：

| 检查 | 通过标准 |
|---|---|
| 时钟 | 一个时序块只有一个主时钟边沿 |
| 复位 | 关键寄存器有明确复位或明确初始化策略 |
| 赋值 | 寄存器同拍更新用非阻塞 `<=` |
| 使能 | 保持旧值用 `else if (en)`，不是组合锁存器 |
| 多驱动 | 同一个寄存器不被多个 always 写 |
| 派生时钟 | 初学和现代 FPGA 默认避免内部随意造新时钟 |

时序逻辑的核心判断：如果你想表达“这些寄存器在同一时钟边沿同时看旧值并更新”，就用非阻塞赋值。

## 5. FSM 的总规则

FSM 是多拍控制的默认结构。推荐骨架：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) state <= IDLE;
  else        state <= next_state;
end

always @* begin
  next_state = state;
  out_valid = 1'b0;

  case (state)
    IDLE: if (start) next_state = BUSY;
    BUSY: begin
      out_valid = 1'b1;
      if (done) next_state = IDLE;
    end
    default: next_state = IDLE;
  endcase
end
```

FSM 不是画图任务，而是关闭状态空间：

| 问题 | 必答 |
|---|---|
| 状态保存什么历史 | 当前流程、匹配后缀、协议阶段、写入高低字节 |
| 转移条件是什么 | 输入、计数器、busy/ready、zero、ack |
| 输出何时有效 | 组合输出、寄存输出、单拍脉冲、保持信号 |
| 复位到哪里 | 安全空闲状态 |
| 非法状态怎么办 | 回安全状态或断言报错 |

## 6. 数据通路和控制器要分开想

数据通路回答“数据怎样算”：

```text
加法器、乘法器、比较器、mux、总线、寄存器、SRAM、FIFO
```

控制器回答“哪拍让谁动”：

```text
load、enable、select、read、write、valid、ready、state
```

一个卷积器可以这样拆：

| 数据通路 | 控制器 |
|---|---|
| ADC 样本寄存器 | 什么时候启动 ADC |
| 3 点窗口移位寄存器 | 什么时候读样本 |
| 乘加组合/流水线 | 什么时候计算 |
| 结果寄存器 | 什么时候锁存 |
| SRAM 地址和数据 | 什么时候写低字节/高字节 |

如果把这两类问题混在一大段 always 里，代码会很快不可维护。

## 7. 仿真、综合、后仿真各看什么

| 阶段 | 看什么 | 不能证明什么 |
|---|---|---|
| RTL 前仿真 | 功能、周期行为、状态转移、接口握手 | 不证明物理时序能跑 |
| 综合 | 可综合性、资源、推断硬件、初步时序 | 不证明布局布线后仍满足时序 |
| 布局布线 | 器件资源和物理连线 | 不自动证明功能没变 |
| 门级后仿真/时序仿真 | 网表延迟、库模型、接近实现的行为 | 仍需约束、覆盖和硬件验证配合 |

调试顺序：

1. RTL 仿真不通过，先查规格、状态机、赋值和 testbench。
2. 综合失败，查不可综合语句、latch、多驱动、未连接和位宽。
3. 时序失败，查关键路径、流水线、约束、派生时钟和资源映射。
4. 后仿真失败，查异步复位释放、时钟域、门延迟、接口时序和 testbench 假设。

## 8. 从 Verilog 到 AI+IC 项目的迁移

| 本书能力 | NPU/AI 芯片项目中的用法 |
|---|---|
| 组合逻辑 | 激活函数近似、比较、mask、地址译码 |
| 时序逻辑 | pipeline stage、valid 寄存、配置寄存器 |
| FSM | DMA、算子调度、SRAM 读写、AXI 事务 |
| 数据通路 | MAC 阵列、累加树、量化/饱和、数据重排 |
| FIFO | 生产者/消费者解耦、跨模块缓存 |
| 虚拟模型 | SRAM/HBM/AXI BFM、输入数据文件、golden model |
| CPU 案例 | RISC-V 控制核、微码控制器、命令解释器 |

最小项目建议：

```text
写一个 3x3 或 1D 卷积小模块
  -> 输入流 valid/ready
  -> 行缓冲或移位窗口
  -> MAC 数据通路
  -> 输出结果寄存
  -> testbench 读取输入向量
  -> Python/golden model 对比输出
```

这比单纯多背几个语法关键字更接近 AI+IC 的真实入口。
