# 最短学习路径：先建立 RTL 判断力，再补全练习闭环

## 本章知识全景图

这本书的最短路径不是从语法表开始背，而是先建立一个硬件问题框架：数据放在哪里，什么时候计算，什么时候保存，谁控制下一步，怎样证明它能综合并运行。

| 阶段 | 必读文件 | 本阶段只抓一个问题 |
|---|---|---|
| 入门 | `01_算法到硬线逻辑` | 为什么软件算法要改造成硬件结构 |
| 语法 | `02_Verilog基础语法` | 每个语法写法对应什么仿真/综合后果 |
| 模型 | `03_Verilog建模抽象级别` | testbench、行为模型、RTL、网表的边界 |
| 数据通路 | `04_运算逻辑与数据通路` | 运算器、mux、总线、流水线怎样承载数据 |
| 控制 | `05_数据流动控制与同步设计`、`06_FSM与可综合Verilog风格` | 状态机怎样决定每一拍做什么 |
| 系统 | `07_简化RISC_CPU设计`、`08_虚拟器件与接口模型` | 小 CPU 和外部模型怎样构成可验证系统 |
| 实践 | `09_Verilog设计练习路线`、`93_练习路线与自测题` | 怎样从小模块练到卷积器和 FIFO |

## 1. 第一遍只学主线，不陷入所有细节

第一遍目标是建立“RTL 是什么”。按这个顺序读：

```text
01 -> 02 的模块/赋值/always/if/case -> 03 -> 04 -> 05 -> 06 的 FSM 和赋值规则
```

第一遍可以暂时跳过：

- 第 2 章中很长的系统任务和预处理细节。
- 第 6 章中大量小模块样板的逐行代码。
- 第 8 章 CPU 的完整源代码清单。
- 第 9 章 8251A 和 8085A 的长行为模型逐行细节。

但不能跳过下面这些判断：

| 判断 | 必须会说清 |
|---|---|
| C 和 Verilog 的差别 | C 描述执行步骤，RTL 描述寄存器和组合逻辑 |
| `reg` 的真实含义 | 过程赋值变量，不一定自动等于触发器 |
| `always @*` 和 `always @(posedge clk)` | 一个描述组合逻辑，一个描述时序寄存器 |
| `=` 和 `<=` | 一个过程内立即更新，一个仿真时刻末尾统一更新 |
| testbench 和 RTL | testbench 可以用延迟/文件/显示任务，RTL 必须能综合 |
| FSM 的核心 | 当前状态寄存器 + 下一状态组合逻辑 + 输出逻辑 |

## 2. 第二遍按“语法到硬件”补细节

第二遍读 [02_Verilog基础语法.md](chapters/02_Verilog基础语法.md) 时，不要按关键字记忆，而要按下面的硬件问题重排：

| 硬件问题 | 对应语法 |
|---|---|
| 模块边界是什么 | `module`、端口方向、位宽 |
| 线网怎么连接 | `wire`、连续赋值、模块实例化 |
| 哪些值需要保存 | `reg`、时序 `always`、复位 |
| 当前输入怎样决定当前输出 | 组合 `always`、`assign`、`if/case` |
| 多拍流程怎样推进 | 计数器、FSM、非阻塞赋值 |
| 重复结构怎样写 | `generate` 思想、静态循环、function/task |
| 验证怎样观察 | `$display`、`$monitor`、`$strobe`、`$readmemh` |

每学一个语法，问三个问题：

1. 它在仿真器里什么时候执行。
2. 它能不能综合。
3. 如果能综合，会生成组合逻辑、触发器、锁存器、mux、加法器、存储器，还是根本不该生成硬件。

## 3. 第三遍按“数据通路 + 控制器”重读中段章节

第 4-7 章是整本书的 RTL 核心。

```text
数据通路：加法器 / 乘法器 / 比较器 / mux / 总线 / 流水线
控制器：使能 / 复位 / 计数器 / FSM / 阻塞非阻塞 / testbench
```

读第 4 章时，关注“资源和时序”：

- 加法器的进位传播决定速度。
- 乘法器是资源大户。
- mux 是数据通路选择器。
- 总线必须只有一个发送者。
- 流水线用寄存器切断长组合路径，但会增加延迟。

读第 5-6 章时，关注“什么时候保存”：

- 组合逻辑只算当前输出，不保存历史。
- 时序逻辑在边沿保存值。
- 控制信号决定哪条数据路径在这一拍有效。
- FSM 的状态寄存器保存流程进度。
- 缺省赋值不完整会推锁存器。
- 阻塞/非阻塞混乱会让仿真和硬件意图错位。

## 4. 第四遍用 CPU 案例把知识串起来

读 [07_简化RISC_CPU设计.md](chapters/07_简化RISC_CPU设计.md) 时，只抓一条指令怎样走完：

```text
PC 给地址 -> ROM 出指令 -> IR 保存 opcode 和 address
-> 控制器按 8 个阶段发控制信号
-> 数据从 RAM/总线/ALU/累加器流动
-> PC 顺序加一或装载跳转地址
-> testbench 装程序并打印诊断结果
```

手工追踪三条指令：

| 指令 | 追踪重点 |
|---|---|
| `LDA addr` | 数据从 RAM 到 ALU 通路，再进入累加器 |
| `STO addr` | 累加器怎样驱动总线，RAM 哪拍写入 |
| `JMP addr` | PC 什么时候从顺序地址变成目标地址 |

能追完这三条，就已经具备读小型 CPU、微控制器、NPU 控制器和 DMA 控制器的基础。

## 5. 第五遍补验证环境

读 [08_虚拟器件与接口模型.md](chapters/08_虚拟器件与接口模型.md) 时，只抓一个边界：

```text
DUT 是我要设计和综合的硬件。
虚拟器件/接口模型是 testbench 里的外部世界。
```

最小验证环境应包含：

| 组件 | 作用 |
|---|---|
| driver | 给 DUT 输入有效激励 |
| virtual model | 模拟外设、存储器或总线 |
| monitor | 观察 DUT 输出 |
| checker/scoreboard | 比较期望和实际 |
| assertion | 检查协议、时序、互斥和非法状态 |

这部分对 AI+IC 很关键。NPU 的 SRAM、AXI、NoC、DMA、激活/权重输入流，都需要行为模型或 BFM 才能在仿真里暴露问题。

## 6. 最短练习组合

如果时间有限，至少完成这 6 个练习：

| 练习 | 为什么必须做 | 完成标准 |
|---|---|---|
| 8 位比较器 | 建立组合逻辑和 testbench 基础 | 全边界测试通过 |
| 分频器/波形发生 | 建立时序、复位和计数意识 | 无差一拍 |
| 阻塞/非阻塞对比 | 建立仿真事件队列意识 | 能解释 `b/c` 波形差异 |
| 序列检测器 | 建立 FSM 和重叠匹配意识 | 覆盖连续和重叠输入 |
| SRAM FIFO | 建立指针、空满和异常测试意识 | 空读、满写、回环通过 |
| 简单卷积器 | 建立小型 AI 数据通路直觉 | ADC 模型、3 点卷积、RAM 写入闭环 |

## 7. 什么时候算学完这一轮

达到下面标准再进入下一轮项目：

- 能写一个组合模块和对应 testbench。
- 能写一个带复位的时序模块。
- 能解释阻塞/非阻塞波形差异。
- 能写一个两段式 FSM。
- 能区分 testbench 行为模型和可综合 RTL。
- 能读综合警告，特别是 latch、多驱动、未连接、位宽截断。
- 能把一个小算法拆成数据通路、控制器、存储器和验证环境。

如果这些还做不到，不要急着读更复杂的 RISC-V 或 NPU 开源项目。先把 [92_易错点总表.md](92_易错点总表.md) 和 [93_练习路线与自测题.md](93_练习路线与自测题.md) 过一遍。
