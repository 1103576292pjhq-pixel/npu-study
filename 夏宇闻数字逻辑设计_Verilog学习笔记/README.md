这套笔记的目标不是复述 Verilog 语法，而是帮零基础学习者建立一条 RTL 设计主线：把算法和实时计算需求，逐步变成可仿真、可综合、可验证、能落到 FPGA/ASIC 的硬线逻辑。

## 读者应该学到什么

读完这套笔记，最低目标是能回答六个问题：

1. 一个算法为什么要重构成数据通路和控制器，而不是直接翻译成 Verilog。
2. `wire/reg/assign/always/if/case/task/function` 在仿真、综合和硬件结构上分别意味着什么。
3. 怎么判断一段 Verilog 是 testbench、行为模型、RTL，还是门级/网表描述。
4. 加法器、乘法器、比较器、mux、总线、流水线和寄存器如何组成数据通路。
5. FSM、复位、阻塞/非阻塞赋值、锁存器风险怎样影响真实硬件。
6. 如何用 testbench、虚拟外设、诊断程序、综合报告和后仿真验证一个小系统。

更高一级目标是：能把这些知识连接到 AI+IC 学习路线，例如 NPU 的 MAC 阵列、DMA、SRAM/FIFO、AXI 接口、RISC-V/微控制器、算子控制器和验证环境。

## 学习边界

这套笔记保留了书中 Verilog-95 时代的核心教学价值，但会把历史写法和现代 RTL 实践分开。遇到下面几类内容时，按“理解思想，不机械照抄”处理：

| 内容 | 应保留的学习价值 | 现代使用边界 |
|---|---|---|
| `casex`、`x` 默认值 | 理解未知值、通配和优化 | 控制逻辑优先普通 `case`、安全默认值、断言 |
| 内部三态总线 | 理解总线所有权 | FPGA 片内多用 mux，顶层 I/O 才常见三态 |
| 派生时钟 | 理解节拍划分 | 现代 RTL 优先单主时钟加 enable |
| `#delay`、`fork/join`、`event` | 写 testbench 和行为模型 | 不作为可综合 RTL 等待机制 |
| 早期供应商和工具名 | 理解行业历史 | 当前选型必须看新的工具链、IP 和验证生态 |

## 建议练习顺序

1. 先用 [93_练习路线与自测题.md](93_练习路线与自测题.md) 做组合比较器、分频器、阻塞/非阻塞对比、组合 ALU。
2. 再写两段式 FSM：序列检测器、EEPROM/串行控制器骨架。
3. 然后做 SRAM FIFO，重点测空读、满写、回环和复位。
4. 最后把卷积器练习改造成更接近 NPU 数据通路的小项目：输入流、3 点卷积、结果写 SRAM、testbench 自检查。

完成标准不是代码能编译，而是能解释波形里每个寄存器、控制信号、地址、数据和状态为什么变化。
