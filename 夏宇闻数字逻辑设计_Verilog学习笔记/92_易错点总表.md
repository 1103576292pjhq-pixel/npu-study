# 易错点总表：按现象定位 RTL 问题

## 本章知识全景图

RTL bug 通常不是“语法不会”，而是把仿真语义、综合语义和硬件时序混在了一起。本表按现象给出定位口径。

| 大类 | 高频后果 |
|---|---|
| 软件思维 | 写出不可综合或结构低效的 Verilog |
| 组合逻辑 | 推锁存器、敏感列表漏信号、默认值不完整 |
| 时序逻辑 | 阻塞/非阻塞 race、复位不清、派生时钟混乱 |
| 数据通路 | 位宽截断、资源爆炸、流水线错拍 |
| FSM | 状态漏转移、非法状态卡死、输出毛刺 |
| 总线/接口 | 多驱动、三态误用、读写时序错 |
| 验证 | testbench 太理想，能跑但不能定位失败 |

## 1. 语法和模型边界

| 易错点 | 典型表现 | 后果 | 正确判断 |
|---|---|---|---|
| 把 Verilog 当 C 写 | 写顺序步骤、动态循环、临时等待 | 综合失败或硬件结构失控 | 先画寄存器、组合逻辑和控制器 |
| 以为能仿真就能综合 | `#delay`、`initial`、`$display` 写进设计主体 | 工具拒绝或行为不一致 | testbench 和 RTL 分文件、分边界 |
| 以为 `reg` 必然是寄存器 | 组合 always 里给 `reg` 赋值 | 误判硬件结构 | 是否有边沿触发才决定是不是触发器 |
| 把系统任务当硬件功能 | `$stop/$display/$readmemh` 依赖进 DUT | 综合不可用或只在特定存储初始化可用 | 系统任务默认属于仿真环境 |
| 不写位宽 | 常量默认宽度和符号扩展失控 | 截断、符号错、比较错 | 所有数据路径写清位宽和符号 |

## 2. 组合逻辑

| 易错点 | 典型代码味道 | 失败信号 | 修正 |
|---|---|---|---|
| 分支不完整 | `if (en) y = a;` 无 else | 综合报告出现 latch | 给默认值或补全所有分支 |
| 敏感列表漏信号 | `always @(a or b)` 内读了 `c` | 仿真输出不随 `c` 变 | 用 `always @*` |
| 组合块用非阻塞 | `tmp <= a & b; y <= tmp;` | `y` 读旧值，仿真多一拍 | 组合 always 用阻塞 `=` |
| 过深优先级 | 长链 `if/else if` | 时序路径过长 | 改 case、并行比较、流水线 |
| `case` 无 default | 某些 opcode 输出保持旧值 | latch 或未知行为 | 默认安全值或断言非法值 |
| 滥用 `casex` | `x/z` 被当通配匹配 | 未知状态被误当合法 | 控制逻辑优先普通 `case` 或 `casez` |

## 3. 时序逻辑

| 易错点 | 典型表现 | 后果 | 修正 |
|---|---|---|---|
| 时序块用阻塞写流水 | `q1 = d; q2 = q1;` | 同拍穿透，仿真不像寄存器链 | 用 `q1 <= d; q2 <= q1;` |
| 多 always 写同一寄存器 | 一个复位块、一个功能块都写 `q` | 多驱动或仿真 race | 一个寄存器一个过程所有者 |
| 复位极性混乱 | `rst`、`rst_n` 命名和条件相反 | 上电状态不确定 | 命名和条件一致，关键寄存器复位 |
| 异步复位释放无同步 | 复位释放靠近时钟边沿 | 亚稳或寄存器不同拍释放 | 异步拉低、同步释放或同步复位 |
| 派生时钟随意扩散 | 用普通逻辑生成新 clock | 时钟约束和 CDC 风险 | 单主时钟 + clock enable |
| 用 `#0` 修 race | 加零延迟让波形看似变好 | 竞争没有从结构上消失 | 修所有权、赋值类型和时序边界 |

## 4. FSM

| 易错点 | 现象 | 后果 | 修正 |
|---|---|---|---|
| 状态含义不清 | 状态名只是步骤编号 | 后续维护无法判断转移 | 写出每个状态保存的历史或阶段 |
| 忘记默认输出 | 某状态没给输出赋值 | latch 或旧输出延续 | 组合输出先默认，再按状态覆盖 |
| 非法状态无处理 | 仿真 `x` 或硬件卡死 | 上电/扰动后无法恢复 | `default` 回安全状态或断言 |
| Mealy 输出直接控关键寄存器 | 输入毛刺直接进使能 | 偶发误写、重复触发 | 输入同步或输出寄存 |
| 重叠序列没处理 | 检测完直接回空闲 | 漏掉重叠匹配 | 状态保存最长有效后缀 |
| 主 FSM 与子 FSM 完成标志错拍 | 协议多一拍或少一拍 | 串行控制器错位 | 完成标志寄存并明确握手 |

## 5. 数据通路和资源

| 易错点 | 现象 | 后果 | 修正 |
|---|---|---|---|
| 位宽不够 | 加法、乘法结果截断 | 高位丢失 | 结果位宽按最大值计算 |
| 把复杂运算塞一拍 | 乘法、除法、阶乘都在一个组合路径 | 频率跑不动 | 多周期、流水线、查表或资源复用 |
| 流水线只加寄存器不对齐 valid | 数据和控制错位 | 输出看似随机错 | 每级同时寄存 data 和 valid/control |
| mux 选择条件不完整 | 输出旧值或非法选择 | 数据路径错误 | default 安全值，非法选择断言 |
| 内部三态总线误用 | 多方同时驱动或 FPGA 转 mux | `x`、资源异常 | 片内用 mux，顶层 I/O 才用三态 |

## 6. 存储器、FIFO 和接口

| 易错点 | 现象 | 后果 | 修正 |
|---|---|---|---|
| SRAM 读延迟没考虑 | 读地址刚变就采样数据 | 采到旧值 | 建立地址、等待有效、再采样 |
| 写使能早于地址/数据 | 写入位置或内容错 | RAM 数据损坏 | 地址/数据先稳定，再拉写使能 |
| FIFO 只用 `rp==wp` 判断空满 | 空和满无法区分 | 覆盖未读数据或读无效数据 | 用计数、多一位指针或 near 标志 |
| 满后继续写 | 旧数据被覆盖 | 队列顺序破坏 | `nfull/full` 阻止写 |
| 空后继续读 | 输出伪有效数据 | 下游使用无效值 | `nempty/empty` 阻止读 |
| valid-ready 未保持 valid | 接收端未 ready 时请求消失 | 事务丢失 | valid 保持到 handshake 完成 |

## 7. 验证和仿真环境

| 易错点 | 现象 | 后果 | 修正 |
|---|---|---|---|
| 只看波形不自检查 | 每次靠人眼判断 | 回归不可持续 | testbench 加 expected/scoreboard |
| 激励太理想 | 只测正常路径 | 边界 bug 留下 | 加复位、空读、满写、非法 opcode、太快请求 |
| 虚拟模型太宽松 | DUT 违例也给正确响应 | 接口 bug 被隐藏 | 加脉宽、保持、恢复、三态检查 |
| 把环境模型综合进 DUT | ROM/RAM/ADC 行为模型混入顶层 | 综合失败或硬件错误 | DUT 顶层和 testbench 顶层分开 |
| `$display` 看非阻塞旧值 | 打印结果和最终波形不一致 | 误判 bug | 观察 NBA 后结果用 `$strobe` 或下一拍检查 |
| 后仿真失败只降频 | 未找到根因 | 结构问题长期存在 | 查关键路径、约束、派生时钟、异步释放 |

## 8. 快速定位表

| 现象 | 优先检查 |
|---|---|
| 输出一直是 `x` | 复位、未驱动、总线冲突、case 未覆盖 |
| 综合报告出现 latch | 组合 always 默认赋值和分支完整性 |
| 仿真对、综合后不对 | 敏感列表、阻塞/非阻塞、不可综合结构、工具警告 |
| 前仿真对、后仿真错 | 时序约束、关键路径、复位释放、派生时钟、接口建立保持 |
| FIFO 顺序错 | 指针更新时机、空满判断、读写同拍规则 |
| FSM 卡住 | default、转移条件、完成标志、复位、非法状态 |
| NPU 数据错一拍 | valid/control 与 data 是否同级流水 |

## 9. 最小检查清单

每次写完 RTL，先问：

1. 所有寄存器是否只有一个过程所有者。
2. 所有组合输出是否在所有路径赋值。
3. 所有状态机是否有复位、default 和非法状态策略。
4. 所有时序块是否用非阻塞赋值。
5. 所有内部等待是否由计数器、FSM 或握手表达，而不是 `#delay`。
6. 所有位宽是否按最大结果计算。
7. testbench 是否覆盖复位、边界、错误和连续操作。
8. 综合警告是否逐条解释。
