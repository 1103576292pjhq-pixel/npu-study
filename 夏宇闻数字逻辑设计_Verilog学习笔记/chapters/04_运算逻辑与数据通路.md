# 04 运算逻辑与数据通路：从表达式到加法器、乘法器和流水线

## 本章知识全景图

数据通路不是“几个运算符拼起来”，而是由加法器、乘法器、比较器、多路器、总线、寄存器和流水线共同决定的计算结构。

| 模块 | 解决什么问题 | 学习重点 |
|---|---|---|
| 加法器 | 两个数相加和进位传播 | 位宽、进位链、超前进位、时延 |
| 乘法器 | 产生部分积并求和 | 阵列、进位节省、资源和流水线 |
| 比较器 | 判断大小和相等 | 逐位比较、参数化位宽 |
| 多路器 | 在多路数据中选一路 | 地址/选择信号、组合选择、数据调度 |
| 总线 | 多模块共享数据通道 | 三态/多路选择、方向控制、冲突避免 |
| 流水线 | 提高重复计算吞吐量 | latency、throughput、寄存器切分 |

最短路径：先理解每个组件的硬件结构，再理解 Verilog 表达式如何交给综合器选择结构，最后理解流水线为什么用更多寄存器换更高吞吐。

## 1. 加法器：进位传播决定速度上限

加法器的核心瓶颈是进位；低位进位没有确定，高位求和就不能完全稳定。

一位全加器的逻辑可以写成：

```text
sum_i  = a_i xor b_i xor c_i
cout_i = a_i b_i + a_i c_i + b_i c_i
```

常用的进位生成/传播写法：

```text
g_i = a_i & b_i          // generate，本位一定产生进位
p_i = a_i ^ b_i          // propagate，本位会传播输入进位
c_{i+1} = g_i | (p_i & c_i)
sum_i = p_i ^ c_i
```

串行进位加法器要等进位从低位一级一级传到高位。位数越大，最长组合路径越长。超前进位加法器用额外逻辑提前计算多个进位，减少等待链，但会增加面积和布线复杂度。

Verilog 表达式写法很简单：

```verilog
module add_4(
  input  [3:0] x,
  input  [3:0] y,
  output [3:0] sum,
  output       cout
);
  assign {cout, sum} = x + y;
endmodule
```

这段 RTL 没有指定“串行进位”还是“超前进位”。综合器会根据目标器件、库、约束和优化目标选择结构。初学者要理解这个边界：

- RTL 表达功能和位宽。
- 综合器选择具体加法器结构。
- 布局布线后才能知道真实延迟。
- 最高时钟频率由关键路径决定。

如果 32 位或 64 位加法器成为关键路径，常见处理是：

1. 换更快的加法结构。
2. 插入流水线寄存器。
3. 分多周期完成。
4. 改变算法或数据通路，降低单周期组合深度。

## 2. 乘法器：部分积求和是硬件资源大户

乘法器不是一个“比加法复杂一点”的符号；它会产生大量部分积，并需要多级加法网络。

两个无符号数相乘可以看成：

```text
A * B = sum_i (A[i] ? (B << i) : 0)
```

也就是每一位 `A[i]` 决定是否选择一份移位后的 `B`，然后把所有部分积加起来。

Verilog 写法：

```verilog
module mult_8(
  input  [7:0]  x,
  input  [7:0]  y,
  output [15:0] product
);
  assign product = x * y;
endmodule
```

这同样只表达功能，不保证具体结构。综合器可能用：

- 组合乘法阵列。
- 进位保存树。
- FPGA DSP block。
- 多周期乘法器。
- 已有乘法器宏单元。

乘法器速度优化常见思路：

| 结构 | 思想 | 代价 |
|---|---|---|
| 并行阵列乘法器 | 同时生成部分积并逐级相加 | 面积大，路径长 |
| 进位节省乘法器 | 多行部分积先不立即传播进位 | 结构复杂，但速度更好 |
| 流水线乘法器 | 在部分积和求和层之间插寄存器 | 延迟周期增加，吞吐提高 |
| DSP block | 使用 FPGA/ASIC 专用乘法资源 | 依赖目标器件和资源数量 |

AI+IC 里乘法器通常不会孤立出现，而是乘加结构：`sum += a * b`。卷积、矩阵乘法、注意力计算都要面对同一个问题：乘法阵列、加法树、累加寄存器、数据复用和流水线如何配合。

## 3. 比较器：参数化位宽比硬编码更重要

比较器判断两个数大小或相等。基本输出可以是：

- `x > y`
- `x < y`
- `x == y`

参数化比较器：

```verilog
module compare_n #(
  parameter W = 8
)(
  input  [W-1:0] x,
  input  [W-1:0] y,
  output         x_gt_y,
  output         x_lt_y,
  output         x_eq_y
);
  assign x_gt_y = (x > y);
  assign x_lt_y = (x < y);
  assign x_eq_y = (x == y);
endmodule
```

比较器的硬件结构通常从高位到低位判断。高位一旦不同，低位不再影响大小关系。位宽越大，比较链和扇入越长。

常见误用：

| 问题 | 后果 | 修正 |
|---|---|---|
| 忽略有符号/无符号 | 大小关系错误 | 明确 signed/unsigned |
| 位宽不一致 | 隐式扩展或截断 | 统一比较位宽 |
| 用 `==` 检查含 x 的仿真值 | 检查失效 | testbench 中按需用 case equality |

## 4. 多路器：数据通路里的“选择阀”

多路器根据选择信号，从多路输入中选一路输出。

```verilog
module mux4 #(
  parameter W = 8
)(
  input  [1:0]   sel,
  input  [W-1:0] in0,
  input  [W-1:0] in1,
  input  [W-1:0] in2,
  input  [W-1:0] in3,
  output reg [W-1:0] y
);
  always @* begin
    case (sel)
      2'd0: y = in0;
      2'd1: y = in1;
      2'd2: y = in2;
      2'd3: y = in3;
      default: y = {W{1'b0}};
    endcase
  end
endmodule
```

多路器在数据通路中非常重要：

- ALU 输入选择。
- 寄存器写回数据选择。
- CPU 取指地址和访存地址选择。
- NPU 数据复用路径选择。
- 总线主设备选择。

多路器的风险是选择信号和数据有效性没有对齐。选择信号晚到，会拉长组合路径；选择条件不完整，会引入锁存器；多级多路器串联，会成为时序关键路径。

## 5. 总线：共享通道必须有唯一发送者

总线是多个模块共享的数据通道。总线设计的核心规则是：任一时刻最多只能有一个发送者，接收者可以有多个。

早期教材常用三态总线表达：

```verilog
module bus_port(
  inout  [11:0] data_bus,
  input         drive_en,
  input         write,
  input  [11:0] out_data,
  output reg [11:0] in_data
);
  assign data_bus = drive_en ? out_data : 12'hzzz;

  always @(posedge write) begin
    in_data <= data_bus;
  end
endmodule
```

现代边界：

- 芯片或 FPGA 顶层 I/O 可能真的有三态。
- FPGA 内部逻辑通常没有真正内部三态，总线会被综合成多路器。
- ASIC 内部也更常用显式多路选择、握手和互连结构。

因此，学习这段代码的价值是理解“共享通道和方向控制”，不是鼓励在所有内部数据通路里滥用 `inout` 和高阻态。

更现代的内部总线口径：

```text
master0_valid/master0_data
master1_valid/master1_data
arbiter selects one master
selected data goes to shared destination
```

总线检查点：

| 检查项 | 失败后果 |
|---|---|
| 是否有多个驱动者同时发送 | 总线冲突、x 传播 |
| 是否有发送者但没人接收 | 数据丢失 |
| 数据和控制是否同拍有效 | 采样旧值或无效值 |
| 位宽是否一致 | 截断、扩展、接口错 |

## 6. 流水线：用寄存器切断长组合路径

流水线提高的是吞吐量，不一定降低单个数据从输入到输出的总周期数。

把一个两级组合逻辑拆成流水线：

```text
组合逻辑：
input -> [logic A] -> [logic B] -> output

流水线：
input -> [logic A] -> reg -> [logic B] -> reg -> output
```

如果组合路径延迟是：

```text
T_comb = T1 + T2
```

插入寄存器后，时钟周期近似受每一级最大延迟限制：

```text
T_clk >= max(T1, T2) + Tco + Tsetup + margin
```

流水线的两个关键指标：

| 指标 | 含义 |
|---|---|
| latency | 一个输入从进入流水线到结果输出要经过多少周期 |
| throughput | 流水线填满后，每隔多少周期能输出一个结果 |

两级流水线可能需要两个周期得到第一个结果，但填满后可以每周期输出一个结果。组合逻辑可能一个周期出结果，但周期必须很长。

| 方案 | 首个结果 | 稳态吞吐 | 资源 |
|---|---|---|---|
| 纯组合 | 1 个长周期 | 每个长周期 1 个结果 | 寄存器少 |
| 流水线 | 多个短周期后出第一个结果 | 每个短周期 1 个结果 | 寄存器多 |

本书中的加法器和乘法器比较说明了同一个原则：流水线会消耗更多寄存器和控制复杂度，但可以显著提高重复运算的吞吐。对 FPGA 尤其重要，因为许多 FPGA 结构有丰富寄存器资源，适合用寄存器换频率。

## 7. Verilog 运算符与结构化流水线的边界

一句 `assign product = x * y;` 不一定生成你想要的流水线乘法器。

如果综合库或 FPGA 资源中有合适的流水线宏，工具可能根据约束使用它；如果没有，工具可能生成组合乘法器。想明确得到流水线结构，通常要在 RTL 中显式插入寄存器。

例子：两级流水线加法路径。

```verilog
module pipe_add3(
  input             clk,
  input             rst_n,
  input      [15:0] a,
  input      [15:0] b,
  input      [15:0] c,
  output reg [16:0] y
);
  reg [16:0] stage1;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      stage1 <= 17'd0;
      y      <= 17'd0;
    end else begin
      stage1 <= a + b;
      y      <= stage1 + c;
    end
  end
endmodule
```

这段代码明确插入了 `stage1` 寄存器。它改变了时序行为：输出 `y` 对输入有流水线延迟。testbench 必须按延迟周期对齐预期结果。

## 8. 数据通路设计的统一检查表

| 问题 | 加法器 | 乘法器 | 比较器 | 多路器 | 总线 | 流水线 |
|---|---|---|---|---|---|---|
| 位宽 | 进位和溢出 | 结果位宽通常是输入位宽之和 | 比较双方统一 | 输出位宽统一 | 全通道统一 | 各级寄存器统一 |
| 时延 | 进位链 | 部分积求和 | 高位比较链 | 选择链 | 仲裁和多路选择 | 每级最大路径 |
| 资源 | 加法器数量 | DSP/乘法器数量 | 比较器扇入 | MUX 数量 | 互连和仲裁 | 寄存器增加 |
| 控制 | 是否每拍计算 | 是否多周期/流水 | 比较结果何时有效 | sel 何时有效 | 谁驱动总线 | valid 对齐 |
| 验证 | 边界值、溢出 | 0、最大值、符号 | 相等/大/小 | 每路选择 | 冲突和空闲 | latency 对齐 |

## 9. AI+IC 连接：MAC 数据通路

NPU 中最常见的数据通路是乘加：

```text
activation * weight -> partial product -> adder tree / accumulator -> output
```

这正好把本章内容串起来：

- 乘法器生成部分积。
- 加法器或加法树累加。
- 比较器用于边界、饱和、控制判断。
- 多路器选择输入来源、旁路路径、写回数据。
- 总线/互连搬运 activation、weight、partial sum。
- 流水线把长组合路径切短，提升吞吐。

如果只会写 `assign y = a * b + c;`，还没有真正理解硬件。硬件设计必须回答资源数量、流水级数、数据复用、控制对齐和验证方式。

## 10. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 只看 Verilog 表达式，不看综合结构 | 面积/时序不可控 | 查看综合报告和目标资源 |
| 忽略结果位宽 | 乘法或加法结果截断 | 明确输出位宽和溢出策略 |
| 以为流水线降低单个样本延迟 | 测试对齐错误 | 区分 latency 和 throughput |
| 内部总线滥用三态 | FPGA/ASIC 内部结构不可控 | 用仲裁和多路器表达 |
| 多路器选择信号晚到 | 关键路径变长 | 寄存选择信号或重划分数据通路 |
| 用一个大组合乘加链 | 时钟频率上不去 | 插入流水线或分多周期 |

## 11. 自测题

1. 为什么多位加法器的关键路径常常与进位传播有关？
2. `assign product = x * y;` 为什么不足以说明乘法器的面积和速度？
3. 比较器为什么要特别注意 signed/unsigned 和位宽？
4. 内部总线为什么通常不建议依赖三态高阻，而更推荐仲裁和多路器？
5. 两级流水线为什么可能增加首个结果延迟，却提高稳态吞吐？
6. 给一个 `y = a * b + c` 数据通路，说明你会在哪里插入寄存器，为什么。

答案检查口径：

- 能把运算表达式翻译成数据通路结构。
- 能解释位宽、资源、时延、吞吐的取舍。
- 能把流水线 latency 和 throughput 分开。
- 能把本章组件连接到后续 FSM、CPU 和 NPU 数据通路。
