# 09 Verilog 设计练习路线：从小模块到可验证系统

## 本章知识全景图

会写 Verilog 语法不等于会做 RTL 设计。真正的训练路线是：先写能综合的小模块，再写能暴露错误的 testbench，最后把模块、状态机、虚拟外设和系统验证连成闭环。

| 阶段 | 核心训练 | 产物 |
|---|---|---|
| 组合逻辑 | 比较器、ALU、mux | 正确的 `assign` 或组合 `always` |
| 时序逻辑 | 分频器、计数器、波形发生 | 明确复位、时钟边沿和寄存器更新 |
| 赋值语义 | 阻塞与非阻塞对比 | 能解释仿真调度和硬件结构 |
| 结构化代码 | function、task | 把重复运算或操作片段写成可复用单元 |
| FSM | 序列检测、嵌套状态机 | 用状态保存历史，用控制信号推动数据 |
| Top-Down | 并串/串并转换系统 | 上层模块清楚连接下层端口 |
| 小系统 | 卷积器、FIFO | 外设模型、控制器、存储器、测试平台一起验证 |

最短路径：每个练习都按“规格、RTL、测试、波形、综合边界、失败信号”六步做，而不是只把示例代码敲一遍。

## 1. 每个练习都要按同一条工程闭环完成

本章所有练习都可以用这条闭环检查：

```text
明确规格 -> 写 RTL -> 写 testbench -> 跑前仿真 -> 看波形/打印 -> 修 RTL
       -> 必要时综合 -> 看综合警告/资源/时序 -> 必要时后仿真
```

练习完成的标准不是“仿真能跑”，而是：

1. 输入输出定义清楚。
2. 复位后状态确定。
3. testbench 覆盖正常、边界和错误场景。
4. 波形能解释每个关键寄存器为什么变化。
5. 综合日志没有未解释的 latch、多驱动、不可综合语句和宽度截断。
6. 如果有外部模型，能说清模型和 DUT 的边界。

下面的路线表给出每个练习的训练目标和失败信号。

| 练习 | 设计任务 | 必须掌握 | 验证重点 | 常见失败信号 |
|---|---|---|---|---|
| 1 | 组合比较器 | 连续赋值、比较运算 | 全输入组合或代表性边界 | 等于/大于条件写反，位宽没扩展 |
| 2 | 1/2 分频器 | 时钟边沿、`reg`、复位 | reset 前后输出是否确定 | 复位极性错，初始 `x` 不消失 |
| 3 | 计数分频/周期波形 | `if`、计数器、周期换算 | 10M 到 500K、指定高低时间 | 计数边界差一拍 |
| 4 | 阻塞/非阻塞 | 仿真调度、寄存器并行采样 | `b/c` 是否同拍或延后一拍 | 用阻塞写流水，仿真综合理解混乱 |
| 5 | 组合 ALU/mux | 组合 `always`、`case/default` | 输入或 opcode 变化立即响应 | 敏感列表漏信号，缺 default 推 latch |
| 6 | function | 可复用组合运算 | 不同 `n` 的结果和资源风险 | 复杂函数组合路径过长 |
| 7 | task 排序 | 多输出操作、阻塞临时变量 | 排序结果和交换顺序 | task 写成动态不可综合流程 |
| 8 | FSM 序列检测 | 状态保存历史、重叠检测 | 连续码流中的命中点 | 检测后回空闲导致漏重叠 |
| 9 | 嵌套 FSM | 主状态机加子流程 | 地址/数据串行输出和 `ack` | 主 FSM 与子 FSM 完成标志不同步 |
| 10 | Top-Down 模块组合 | 端口连接、`inout`、模块实例化 | 并串和串并转换能闭环 | 端口接反、总线驱动方向错 |
| 11 | 简单卷积器 | 外设模型、FSM、RAM 写入 | 采样、卷积、写低/高字节 | 等待 ADC 太久或采样/写入错拍 |
| 12 | SRAM FIFO | 环形指针、空满判断、SRAM 时序 | 空读、满写、复位、读写交替 | 空满同指针无法区分，覆盖旧数据 |

## 2. 练习 1-3：组合和时序的最低门槛

### 2.1 组合比较器：先把组合逻辑写成无记忆函数

比较器的本质是：

```verilog
assign equal = (a == b) ? 1'b1 : 1'b0;
```

这里没有时钟，没有状态，也不需要保存旧值。输入变，输出立即由组合路径重新计算。

扩展成 8 位大小比较器时，要明确目标：

```verilog
assign greater = (a[7:0] > b[7:0]);
```

测试不能只测一两个值，至少要覆盖：

| 场景 | 输入例子 | 期望 |
|---|---|---|
| 相等 | `8'h00` vs `8'h00`，`8'hff` vs `8'hff` | `greater=0` |
| 小于 | `8'h01` vs `8'h02` | `greater=0` |
| 大于 | `8'h80` vs `8'h7f` | `greater=1` |
| 边界 | `8'hff` vs `8'h00` | `greater=1` |

如果比较的是有符号数，不能继续默认无符号比较；要明确使用 `$signed` 或有符号声明。这是从练习阶段就要养成的位宽和符号意识。

### 2.2 分频器：时序逻辑必须有确定复位

1/2 分频器每个输入时钟边沿翻转一次输出：

```verilog
always @(posedge clk_in or negedge rst_n) begin
  if (!rst_n) clk_out <= 1'b0;
  else        clk_out <= ~clk_out;
end
```

训练点：

| 点 | 判断 |
|---|---|
| `clk_out` 是 `reg` | 因为它在过程块里被赋值，并保存跨周期状态 |
| 复位必须明确 | 否则仿真开始可能长期为 `x` |
| 时序块用 `<=` | 输出在时钟边沿并行更新 |
| 分频输出不能随便当新时钟扩散 | 现代工程中优先用 clock enable |

如果题目要求输出与示例反相，不要改 testbench 糊弄波形。应明确复位值或翻转逻辑，让复位后第一段输出相位相反。

### 2.3 计数分频和周期波形：最容易差一拍

10 MHz 时钟周期是 100 ns。要得到 500 kHz 方波，完整周期是 2 us，半周期是 1 us，也就是 10 个 10 MHz 周期。如果代码在 `j==19` 时才翻转，则要检查它到底是在 20 个输入周期翻转一次，还是把高低半周期都拉长了。

写计数器时，先把规格换成计数目标：

```text
目标波形高电平多久 -> 需要多少个输入时钟周期
目标波形低电平多久 -> 需要多少个输入时钟周期
计数范围是 0 到 N-1，还是 1 到 N
翻转发生在当前拍，还是下一拍输出才变
```

周期波形练习的失败信号通常是：

- 高电平或低电平多一拍/少一拍。
- 复位后第一次周期长度和后续周期不同，却没有说明原因。
- 计数器位宽不够，最大计数值溢出。
- 用 `#delay` 在 RTL 里制造波形，这是 testbench 写法，不是可综合设计。

## 3. 练习 4-5：赋值语义和组合 always

### 3.1 阻塞和非阻塞不是风格偏好

两个模块只差赋值符号：

```verilog
// 阻塞
always @(posedge clk) begin
  b = a;
  c = b;
end

// 非阻塞
always @(posedge clk) begin
  b <= a;
  c <= b;
end
```

在阻塞版本里，`c` 同一个过程内读到刚更新的 `b`，所以 `a` 可以同拍传到 `c`。在非阻塞版本里，`b` 和 `c` 都先读旧值，到仿真时刻末尾一起更新，所以 `c` 看到的是上一拍的 `b`。

工程判断：

| 你想表达 | 推荐写法 | 原因 |
|---|---|---|
| 多个寄存器同一边沿同时采样 | `<=` | 符合触发器并行更新 |
| 组合逻辑中先算临时值再算输出 | `=` | RHS 立即可见 |
| 同一个寄存器由多个 always 写 | 不允许 | 多驱动和 race |
| 用语句顺序修复时序 | 不可靠 | 综合后硬件并不按软件顺序执行 |

题目要求比较 blocking 写法变体，重点不是看波形新奇，而是回答：哪一种行为依赖过程内语句顺序，哪一种行为依赖多个 always 的调度顺序，哪一种能稳定表达寄存器链。

### 3.2 组合 `always` 必须像完整函数

组合 ALU 可以用 `always @*` 加 `case` 表达：

```verilog
always @* begin
  case (opcode)
    PLUS:    out = a + b;
    MINUS:   out = a - b;
    BAND:    out = a & b;
    BOR:     out = a | b;
    UNEGATE: out = ~a;
    default: out = 8'h00;
  endcase
end
```

组合块的最低要求是：每条路径都给输出赋值。如果缺少 `default`，当 `opcode` 不匹配任何分支时，`out` 必须保持旧值，综合器就会推断锁存器。

8 路 4 位 mux 的练习应按这个标准检查：

| 检查项 | 通过标准 |
|---|---|
| 选择信号 | 至少 3 位，覆盖 8 路 |
| 敏感列表 | 使用 `always @*` 或包含所有输入 |
| 输出默认值 | 有 `default` 或进入 case 前默认赋值 |
| 数据宽度 | 每路输入和输出都是 4 位 |
| 测试 | 每个选择值至少激励一次，输入变化也能触发输出变化 |

## 4. 练习 6-7：function 和 task 是结构化工具，不是魔法

### 4.1 function 每调用一次就是一块组合运算逻辑

函数适合“一个输入集合产生一个返回值”的组合运算。例如阶乘：

```verilog
function [31:0] factorial;
  input [3:0] operand;
  integer index;
  begin
    factorial = 1;
    for (index = 2; index <= operand; index = index + 1)
      factorial = factorial * index;
  end
endfunction
```

函数训练的是代码复用，但硬件代价不会凭空消失。`n * factorial(n) / ((n*2)+1)` 看起来像一个表达式，综合后可能是乘法器、除法器和很长的组合路径。工程上遇到复杂运算，要考虑：

1. 是否需要多周期实现。
2. 是否需要流水线。
3. 是否可以查表。
4. 是否需要限制输入范围。
5. 是否有溢出和截断。

练习里的平方、立方、阶乘控制电路，应在 testbench 里检查至少：

- 控制端选择正确运算。
- `0/1/最大输入` 的结果合理。
- 输出位宽能容纳最大结果，或明确截断。
- 时钟触发后结果在哪一拍有效。

### 4.2 task 适合多输出或一组重复操作

任务不返回单个值，但可以通过 `output`、`inout` 或模块变量修改多个结果。排序例子中，`sort2` 用阻塞赋值交换两个临时变量：

```verilog
task sort2;
  inout [3:0] x, y;
  reg [3:0] tmp;
  begin
    if (x > y) begin
      tmp = x;
      x = y;
      y = tmp;
    end
  end
endtask
```

这里用阻塞赋值是合理的，因为它描述的是组合过程中的临时交换顺序，而不是多个寄存器同拍采样。

task 的可综合边界：

| 可以 | 不可以 |
|---|---|
| 固定次数比较交换 | 在可综合 RTL task 里写 `#delay` |
| 静态可展开的循环 | 等待任意事件 `@(posedge ...)` 来控制硬件时间 |
| 组合临时变量操作 | 调用 `$display/$stop` 作为硬件行为 |
| 多输出运算封装 | 动态创建硬件或不定次数操作 |

三输入冒泡排序练习如果要求“每个时钟周期完成一次数据交换”，就不再是纯组合排序网络，而是时序排序控制器。要增加状态或计数器，明确第几拍比较哪两个数，排序完成信号什么时候有效。

## 5. 练习 8-10：FSM、嵌套 FSM 和 Top-Down

### 5.1 序列检测器：状态保存的是“有效历史后缀”

检测 `10010` 的状态机不能只记“匹配到第几位”。它还必须处理重叠序列。例如刚检测完一个序列后，末尾几位可能同时是下一次匹配的前缀。

一个可复用的设计方法：

```text
状态含义 = 当前输入历史中，仍可能成为目标序列前缀的最长后缀
输入一位 -> 计算新的最长后缀 -> 必要时输出命中
```

连续 4 个或 4 个以上的 1 检测器可以用状态数量表示已经连续看到多少个 1：

| 状态 | 含义 | 输入 0 | 输入 1 | 输出 |
|---|---|---|---|---|
| `S0` | 连续 0 个 1 | `S0` | `S1` | 0 |
| `S1` | 连续 1 个 1 | `S0` | `S2` | 0 |
| `S2` | 连续 2 个 1 | `S0` | `S3` | 0 |
| `S3` | 连续 3 个 1 | `S0` | `S4` | 0 |
| `S4` | 连续至少 4 个 1 | `S0` | `S4` | 1 |

测试要覆盖 `1111`、`11110`、`0111110`、不足 4 个 1、多个片段连续出现。否则容易只测到第一次命中，看不到“4 个以上保持输出”的要求。

### 5.2 嵌套 FSM：主流程管阶段，子流程管位级动作

EPROM 串行写入器的核心分工：

| 层次 | 状态 | 任务 |
|---|---|---|
| 主 FSM | `idle/addr_write/data_write/stop_ack` | 决定当前写地址、写数据还是应答 |
| 子 FSM | `bit0` 到 `bit7` | 每拍移出一个 bit |
| 完成标志 | `finish_F` | 告诉主 FSM 一个字节已经串行输出完 |
| 总线控制 | `link_write` | 决定 `sda` 是否由本模块驱动 |
| 应答 | `ack` | 通知信号源可以提供下一个地址和数据 |

复杂控制器不要把所有 bit 级动作塞进一个巨大 case。主 FSM 负责“做什么阶段”，子 FSM 或 task 负责“阶段内部怎样一拍一拍做完”。这和 I2C、SPI、UART、AXI burst、DMA burst 的控制方法一致。

练习要求改成串行读取时，要重新定义：

- `sda` 或输入数据线什么时候由外设驱动。
- 控制器在哪一拍采样输入位。
- 8 位数据拼接到哪个寄存器。
- 读完一个字节后如何产生 `ack` 或 valid。
- testbench 怎样提供串行数据并检查并行结果。

### 5.3 Top-Down 模块组合：端口连接就是系统合同

并串转换和串并转换被拆成两个模块，再由顶层 `sys` 连接。这训练的是模块层次，而不是某个移位表达式。

| 模块 | 作用 | 易错点 |
|---|---|---|
| `p_to_s` | 并行 8 位数据移位输出为串行 | 置数边沿、移位方向、输出 bit 顺序 |
| `s_to_p` | 串行输入移位收集为并行 | 采样边沿、数据锁存、输出三态控制 |
| `sys` | 实例化两个子模块并连接共享 data 总线 | `inout` 方向和控制信号不能冲突 |
| `Top` testbench | 驱动控制信号和数据总线 | 必须避免 testbench 和 DUT 同时驱动总线 |

原例中使用中间缓冲变量帮助综合器识别移位。这种提醒的现代意义是：不要只追求表达式短，要让综合器和读代码的人都能看懂时序边界。今天写移位寄存器通常可以直接使用清晰的非阻塞时序块，但仍要检查工具支持、位宽和赋值时机。

序列发生器练习可以把前面的序列检测器接成闭环：

```text
8 位输入数据 -> 判定范围输出 0/1 串行 bit -> 序列检测器 -> z 命中输出
```

验收不是“两个模块都能单独仿真”，而是顶层连接后 `z` 的命中时刻和输入序列一致。

## 6. 练习 11：简单卷积器是第一个小型专用计算系统

卷积器练习把前面所有能力合在一起：外设模型、FSM、RAM 写入、多字节结果、测试平台和性能改进。

### 6.1 规格先行

卷积器的任务是：

```text
控制 ADC 采样 -> 取得 8 位样本 -> 计算 3 点卷积
-> 把 16 位卷积结果拆成低字节和高字节 -> 写入 RAM
```

教学设计使用三个系数：

```text
h1 = 1, h2 = 2, h3 = 3
result = x[n] * h1 + x[n-1] * h2 + x[n-2] * h3
```

数据通路可以理解成：

```text
ADC data[7:0] -> line[23:0] shift register -> multiply/add -> result[15:0]
                                                |
                                                v
                         low byte RAM + high byte RAM
```

### 6.2 FSM 分阶段控制采样、计算和写入

单 ADC 版本的主要状态：

| 状态 | 动作 |
|---|---|
| `IDLE` | 等待 `start`，清计数和历史样本 |
| `START` | 等待采样节拍，准备启动 ADC |
| `NCONVST` | 拉低再释放 `nconvst`，开始转换 |
| `READ` | 等待 `nbusy/EOC`，读入 ADC 数据 |
| `CALCU` | 计算 3 点卷积结果 |
| `WRREADY` | 建立 RAM 地址和输出数据 |
| `WR` | 片选 RAM，拉低写使能 |
| `WREND` | 结束写，决定写高字节还是进入等待 |
| `WAITFOR` | 控制采样频率，判断 RAM 是否写满 |

这个状态机训练两个关键点：

1. 外设 `nbusy` 不应直接随便采样。例子在时钟下降沿同步得到 `EOC`，再在上升沿驱动主 FSM，避免边沿太近导致状态机错判。
2. 16 位结果写入 8 位 RAM 时必须分两次写，`high` 标志决定当前写低字节还是高字节。

### 6.3 前仿真、后仿真和性能改进

testbench 至少要包含：

| 模块 | 作用 |
|---|---|
| ADC 行为模型 | 提供 `nbusy` 和输入样本 |
| SRAM 行为模型 | 接收写地址、写数据和写使能 |
| 卷积器 DUT | 产生采样控制、计算结果、RAM 写控制 |
| 时钟/复位/start 激励 | 启动一次或多次卷积过程 |

单 ADC 版本的问题是串行等待：采样、转换、计算、写 RAM 顺序执行，很多时间耗在等 ADC 转换。改进版本使用三片 ADC 交错工作，让采样、计算和写入部分重叠。

| 版本 | 结构 | 采样效率 |
|---|---|---|
| 单 ADC | 一个 ADC 完成采样后再计算和写入 | 简单，等待时间多 |
| 三 ADC 交错 | 三个 `nconvst` 分时启动，轮流读 `EOC` | 吞吐提高，但控制更复杂 |

这就是硬件加速的基本思想：不是把一个操作“算得更努力”，而是让多个阶段并行重叠。NPU 的流水线、DMA double buffering、矩阵乘阵列都是这类思想的放大版本。

卷积器的常见失败信号：

- `nconvst` 脉宽不满足 ADC 模型检查。
- `READ` 状态读到旧样本或高阻数据。
- `line` 移位顺序错，卷积窗口反了。
- 低字节和高字节写入地址或片选错。
- RAM 写满后仍继续写，覆盖已有结果。
- 后仿真中写使能和地址/数据相位不满足器件时序。

## 7. 练习 12：SRAM FIFO 训练环形指针和异常测试

FIFO 的外部行为是不带地址的先进先出队列；内部实现可以用 SRAM 加读写指针。

```text
用户接口：fifowr / fiford / in_data / out_data / nfull / nempty
内部接口：SRAM address / sram_data / rd / wr
```

### 7.1 空满判断的关键是“同指针不同状态”

环形数组里，读指针和写指针相等可能表示两种完全不同的情况：

| 条件 | 含义 |
|---|---|
| 刚复位后 `rp == wp` | FIFO 空 |
| 连续写满后 `rp == wp` | FIFO 满 |

因此不能只用 `rp == wp` 判断空满。参考设计用 `near_empty` 和 `near_full` 辅助记录“下一次读会空”或“下一次写会满”，再更新 `nempty/nfull`。

基本指针规则：

```text
写成功：SRAM[wp] <- in_data，wp 前进
读成功：out_data <- SRAM[rp]，rp 前进
wp 到末尾后回 0
rp 到末尾后回 0
满时禁止写，空时禁止读
```

### 7.2 SRAM 操作也需要状态机

FIFO 控制器不能只在一个时钟里同时建立地址、拉读写、释放总线。参考设计把 SRAM 操作拆成状态：

| 状态 | 作用 |
|---|---|
| `idle` | 等待用户读写请求 |
| `read_ready` | 建立读地址 |
| `read` | 保持读使能，等待用户释放读请求 |
| `read_over` | 保持地址，采样输出，读指针前进 |
| `write_ready` | 建立写地址和写数据 |
| `write` | 保持写使能，等待用户释放写请求 |
| `write_over` | 保持地址和数据，写指针前进 |

这和真实 SRAM 时序一致：地址和数据先稳定，读写控制再有效，最后控制信号释放。即使练习使用行为模型，也要按真实器件时序训练。

### 7.3 FIFO testbench 必须主动测异常

好的 FIFO 测试不是只写一个读一个。至少要覆盖：

| 测试 | 目的 |
|---|---|
| 复位后立即检查 `nempty/nfull` | 确认初始空、未满 |
| 连续写到满 | 检查写指针回环和 `nfull` |
| 满后继续写 | 确认不会覆盖旧数据 |
| 连续读到空 | 检查读出顺序和 `nempty` |
| 空后继续读 | 确认不会输出伪有效数据 |
| 写后立即读 | 检查最短路径和状态切换 |
| 多轮回环 | 检查指针 wrap-around |

testbench 里用 `task write_fifo` 和 `task read_fifo_compare` 是正确方向：把重复握手动作封装起来，把数据缓存 `data_buf` 作为期望结果队列。更现代的写法会把它扩展成 scoreboard。

FIFO 和 AI+IC 的关系非常直接：几乎所有 NPU 数据通路都有 FIFO 或队列，用于解耦生产者和消费者。如果空满判断错，轻则吞吐下降，重则丢数据、重复读、覆盖未读数据。

## 8. 本章练习路线建议

不要按“看完代码就算学完”的方式过本章。推荐三轮：

### 第一轮：复现和解释

每个练习只做一件事：跑通示例，并能解释每个关键信号。

通过标准：

- 能说出输入、输出、状态寄存器、组合输出。
- 能在波形上找到复位、使能、写入、读出、命中等事件。
- 能解释 testbench 为什么这样激励。

### 第二轮：改题和加测试

把每个练习的“练习要求”做出来，并加自己的检查。

通过标准：

- 比较器覆盖边界。
- 分频器和波形发生器计数无差一拍。
- blocking/nonblocking 变体有波形解释。
- FSM 覆盖重叠、连续、复位中断。
- FIFO 覆盖空读、满写、回环。

### 第三轮：现代化重写

选择 3 个练习重写成更接近现代 RTL 的风格：

| 原练习 | 重写目标 |
|---|---|
| 分频器 | 改成主时钟 + enable，不把分频输出扩散成内部时钟 |
| 序列检测器 | 用两段式 FSM、默认赋值、普通 `case` |
| 卷积器 | 增加 valid/ready，分离 ADC BFM、DUT、scoreboard |
| FIFO | 用清晰空满计数或多一位指针方案，增加自检查 testbench |

这轮才真正把教材例子转化为工程能力。
