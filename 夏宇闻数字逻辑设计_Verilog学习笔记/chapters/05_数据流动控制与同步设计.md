# 05 数据流动控制与同步设计：让运算结果在正确的时钟被保存

## 本章知识全景图

数据通路只负责“能算什么”，控制逻辑负责“什么时候让谁算、什么时候把结果保存到哪里”。

| 学习块 | 核心问题 | 工程判断 |
|---|---|---|
| 组合逻辑和时序逻辑 | 输出只由当前输入决定，还是还依赖状态 | 数据通路和状态寄存器要分开理解 |
| 数据流动控制 | 运算结果什么时候稳定、什么时候采样 | 控制信号必须与时钟和延迟对齐 |
| 同步状态机 | 谁产生开关、使能、读写、装载信号 | 复杂控制默认由同步 FSM 管理 |
| 同步与异步 | 状态何时允许改变 | RTL 初学默认走同步主线 |
| 冒险竞争 | 组合逻辑变化期间会产生毛刺 | 用寄存器在稳定时刻采样 |

最短路径：先理解组合逻辑会延迟，再理解寄存器只在时钟边沿采样，最后理解状态机如何按拍控制数据流动。

## 1. 组合逻辑与时序逻辑的分工

组合逻辑负责计算，时序逻辑负责记住状态；没有寄存器，复杂运算就很难被可靠地分阶段控制。

| 类型 | 输出取决于 | 常见模块 | RTL 写法 |
|---|---|---|---|
| 组合逻辑 | 当前输入 | 加法器、乘法器、比较器、多路器、译码器 | `assign` 或 `always @*` |
| 时序逻辑 | 当前输入 + 过去状态 | 寄存器、计数器、状态机、控制器 | `always @(posedge clk)` |

组合逻辑一定有传播延迟。输入变化后，输出不会瞬间稳定。对于加法器、乘法器、比较器、多路器这类数据通路组件，传播延迟决定了下一拍能不能安全采样。

时序逻辑用寄存器把“什么时候采样”固定到时钟边沿：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) q <= 8'd0;
  else        q <= d;
end
```

这里 `d` 可以来自一段组合逻辑。只要时钟周期足够长，`d` 在下一个时钟边沿前稳定，`q` 就能保存正确结果。

## 2. 数据流动控制：运算不是一直打开就行

数据流动控制的任务是让数据按顺序经过寄存器、组合逻辑、总线和下一级寄存器。

一个最小数据通路：

```text
reg_A -> [组合运算 logic] -> reg_B
```

安全采样条件：

```text
Tclk >= Tco(reg_A) + Tcomb(logic) + Tsetup(reg_B) + margin
```

含义：

- `reg_A` 在时钟边沿后输出新数据，需要 `Tco`。
- 组合逻辑需要 `Tcomb` 才能稳定。
- `reg_B` 在下一个时钟边沿前需要满足建立时间 `Tsetup`。
- 还要留出时钟偏斜、布线和工艺余量。

控制逻辑要决定：

1. 哪个寄存器当前把数据送出。
2. 哪段组合逻辑参与计算。
3. 哪个寄存器在下一个时钟边沿装载结果。
4. 总线或多路器当前选择哪一路。
5. 如果结果还没稳定，是否要等待更多周期。

## 3. 开关模型：理解数据流动的直觉桥

可以把控制信号想成一组开关：某个开关打开，数据通道接通；某个写使能有效，寄存器在时钟边沿保存数据。

```text
reg_C --S6--> logic --S1--> reg_A
```

正确时序是：

1. 在采样边沿前，让 `reg_C` 的输出路径有效。
2. 等组合逻辑结果稳定。
3. 在时钟边沿让 `reg_A` 装载结果。
4. 下一个周期再切换到下一条数据路径。

如果开关控制和时钟边沿没有对齐，就会出现两类错误：

- 采样太早：寄存器保存了还没稳定的中间值。
- 多路冲突：多个输出同时驱动共享通道。

在真实 RTL 中，“开关”通常不是物理开关，而是多路器选择信号、寄存器使能、总线仲裁、读写控制和状态机输出。

## 4. 同步有限状态机是控制逻辑核心

同步 FSM 的状态只在时钟边沿改变；输入条件决定下一状态和控制输出。

最小同步控制骨架：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) state <= IDLE;
  else        state <= next_state;
end

always @* begin
  next_state = state;
  load_a = 1'b0;
  load_b = 1'b0;

  case (state)
    IDLE: begin
      if (start) next_state = CALC;
    end
    CALC: begin
      load_a = 1'b1;
      next_state = DONE;
    end
    DONE: begin
      load_b = 1'b1;
      if (ack) next_state = IDLE;
    end
  endcase
end
```

这个骨架体现三件事：

- 状态寄存器只在时钟边沿更新。
- 组合逻辑根据当前状态和输入算下一状态。
- 控制信号由状态机产生，用来控制数据流动。

第 7 章会深入 FSM 写法，本章先建立它和数据流动的关系。

## 5. 为什么初学 RTL 默认使用同步时序逻辑

同步设计的核心好处是：所有状态变化都被限制在统一时钟边沿，设计者可以用一个时钟周期来容纳组合逻辑稳定过程。

异步时序逻辑的问题是触发条件分散，任何相关信号跳变都可能引发状态变化。电路复杂后，组合延迟、毛刺、工艺偏差和布线变化都会让行为难以预测。

| 对比项 | 同步时序逻辑 | 异步时序逻辑 |
|---|---|---|
| 状态变化时刻 | 统一时钟边沿 | 多个控制因素都可能触发 |
| 分析方法 | 静态时序分析清晰 | 时序关系难穷尽 |
| 可移植性 | 更适合综合和跨工艺迁移 | 工具支持和调试难度高 |
| 风险 | 需要处理时钟偏斜、建立/保持时间 | 容易产生竞争、冒险、毛刺 |

现代边界：不是所有“异步”都禁止。常见异步复位、跨时钟域同步器、异步 FIFO、低功耗握手电路都可能合理存在。但零基础写可综合 RTL 时，主数据通路和主控制状态机应默认同步化；异步结构必须有明确工程理由和验证方法。

## 6. 冒险竞争：组合逻辑中间值不要直接当最终结果

组合逻辑输入同时变化时，不同路径延迟可能不同，输出会短暂出现毛刺。

例子：

```text
C = a & b
```

如果 `a` 和 `b` 不是严格同一时刻变化，`C` 可能出现短脉冲。这个短脉冲在纯组合观察中存在，但只要我们在足够晚的时钟边沿采样，就能保存稳定后的结果。

同步设计的基本策略：

```text
上一拍寄存器输出 -> 组合逻辑传播并稳定 -> 下一拍寄存器采样
```

这不是说毛刺不存在，而是说它不会被错误采样成状态。

## 7. 时钟网络和时钟周期

同步设计成立的前提是时钟能尽量同时到达各触发器，并且时钟周期大于关键路径延迟。

关键约束：

```text
Tclk >= Tco + Tcomb + Tsetup + Tskew + margin
```

如果时钟太快，组合逻辑还没稳定，下一级寄存器就采样，错误会进入状态。解决办法通常是：

- 降低时钟频率。
- 优化组合逻辑。
- 插入流水线。
- 调整状态机，分多周期完成。
- 改善布局布线和时钟约束。

书中提到全局时钟网络和平衡树，是为了减少时钟偏斜。今天 FPGA/ASIC 都有专门时钟资源和 CTS 流程，但设计者仍要遵守一个原则：不要随便用普通逻辑生成新时钟去触发寄存器。

推荐做法是：

```verilog
always @(posedge clk) begin
  if (enable) q <= d;
end
```

而不是用 `enable` 去门控或派生一个不受约束的新时钟。真正需要门控时钟时，应使用工具和工艺库支持的专用门控单元，并经过时序和低功耗验证。

## 8. 从第 5 章到第 7 章的连接

第 5 章的数据通路回答“有哪些运算硬件”。第 6 章回答“这些硬件什么时候被使用”。第 7 章会回答“如何用 FSM 可靠地产生这些控制时序”。

例子：三拍完成一次乘加。

| 周期 | 数据通路动作 | 控制信号 |
|---|---|---|
| 0 | 装载 `a`、`b` | `load_in=1` |
| 1 | 乘法结果进入中间寄存器 | `load_mul=1` |
| 2 | 加上累加值并写回 | `load_acc=1` |

这类控制如果用散乱的组合条件堆出来，很快失控。用同步 FSM，则可以把每拍动作写成状态，波形也更容易检查。

## 9. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 组合结果刚变化就采样 | 保存毛刺或中间值 | 留足时钟周期或插流水线 |
| 用组合逻辑生成时钟 | 时钟偏斜和毛刺触发 | 用统一时钟 + enable |
| 多个控制源同时驱动总线 | 总线冲突和 x 传播 | 仲裁，保证唯一发送者 |
| 把异步逻辑当默认方案 | 难综合、难调试、难迁移 | 主控制默认同步 FSM |
| 只看功能仿真，不看时序 | 上板/后仿真失败 | 检查时序报告和关键路径 |
