# 07 简化 RISC CPU 设计：从指令到控制信号

## 本章知识全景图

CPU 不是一段会“自己运行”的程序，而是一组寄存器、组合逻辑、总线、存储器接口和控制状态机共同完成“取指、译码、执行”的硬件系统。

| 学习块 | 核心问题 | 工程判断 |
|---|---|---|
| CPU 基本任务 | CPU 到底在控制什么 | 控制存储器、运算器、寄存器和下一条指令地址 |
| RISC 指令格式 | 指令怎样变成操作 | 操作码决定动作，地址字段决定数据或跳转目标 |
| 模块拆分 | 复杂 CPU 怎样拆成小硬件 | 用寄存器、ALU、PC、地址选择、数据控制、状态机分工 |
| 指令周期 | 一条指令需要几拍 | 本教学 CPU 用 8 个时钟阶段完成取指和执行 |
| 总线读写 | 数据什么时候出现在总线上 | 读写必须满足地址先建立、控制后有效、数据再采样 |
| 调试路径 | CPU 怎样证明自己能跑 | 用 ROM/RAM 行为模型装程序，跑诊断程序和 Fibonacci |
| 综合与后仿真 | 代码怎样变成 FPGA 逻辑 | 分模块综合，分离可综合 CPU 与仿真外围，再看时序报告和门级仿真 |

最短路径：先把 CPU 看成“指令驱动的控制器”，再按一条 `LDA/ADD/STO/JMP` 指令走完数据路径，最后用仿真、综合、门级后仿真三层检查它是否真的能落到硬件。

## 1. CPU 的核心动作只有三类：取指、分析、执行

CPU 的最小工作循环可以写成：

```text
取指令：PC 给出地址，存储器返回指令字节
分析指令：指令寄存器保存操作码和地址，控制器判断要做什么
执行指令：ALU、累加器、PC、数据总线和存储器按控制信号动作
```

这三个动作在软件里像顺序语句，在硬件里是多个模块按时钟节拍并行配合。CPU 设计的难点不是“知道 ADD 是相加”，而是确定相加发生在哪一拍，数据从哪里来，结果写到哪里，下一条指令地址如何更新。

一个简单 CPU 至少要有这些部件：

| 部件 | 保存或计算什么 | 如果缺失会卡在哪里 |
|---|---|---|
| ALU | 算术和逻辑运算结果 | 指令只能搬数据，不能计算 |
| 累加器 | 当前运算结果和 ALU 一个操作数 | 多条指令之间无法保存中间值 |
| 程序计数器 PC | 下一条指令地址 | 不能按程序顺序取指，也不能跳转 |
| 指令寄存器 IR | 当前指令的操作码和地址字段 | 执行阶段不知道当前指令是什么 |
| 状态控制器 | 每拍发出 `rd/wr/load_ir/load_acc/inc_pc` 等控制信号 | 各模块不知道什么时候读、写、更新 |
| 地址选择器 | 在 PC 地址和指令地址之间选择 | 取指和读写数据会抢同一地址总线 |
| 数据控制器 | 控制累加器何时驱动数据总线 | 总线可能多驱动，或写存储器时没有数据 |

RISC 的教学价值在于把复杂指令集压缩成少量固定动作，让读者能看见每条指令怎样落到控制信号，而不是被大量寻址方式和微码细节淹没。

## 2. 指令格式：3 位操作码加 13 位地址

这个简化 CPU 是 8 位数据通路、13 位地址、16 位指令字。每条指令占两个字节，指令高 3 位是操作码，低 13 位是地址。

```text
bit: 15 14 13 | 12 ............... 0
     opcode  | address
```

数据总线只有 8 位，所以一条 16 位指令要分两次取：先取高 8 位，再取低 8 位。指令寄存器内部用一个 1 位状态记录“下一次装高字节还是低字节”。

8 条指令可以按控制动作分成四组：

| 指令 | 类型 | 执行动作 | 关键控制 |
|---|---|---|---|
| `HLT` | 停机 | 产生 `halt`，CPU 停在诊断点 | 控制器识别操作码后拉高 `halt` |
| `SKZ` | 条件跳过 | 若累加器为 0，跳过下一条指令 | ALU 产生 `zero`，控制器让 PC 额外加 1 |
| `ADD` | 算术 | `accum <= accum + mem[addr]` | 读数据、ALU 运算、装载累加器 |
| `AND` | 逻辑 | `accum <= accum & mem[addr]` | 同 ADD，但 ALU 选择与运算 |
| `XOR` | 逻辑 | `accum <= accum ^ mem[addr]` | 同 ADD，但 ALU 选择异或 |
| `LDA` | 装载 | `accum <= mem[addr]` | 读数据，经 ALU 通路送入累加器 |
| `STO` | 存储 | `mem[addr] <= accum` | 数据控制器驱动总线，写信号有效 |
| `JMP` | 跳转 | `PC <= addr` | PC 装入指令地址字段 |

这个 CPU 使用直接寻址：指令里给出的地址就是数据或跳转目标地址。直接寻址最容易理解，但表达能力有限；它适合教学 CPU，不代表现代处理器只需要这种寻址方式。

## 3. 顶层结构：一条总线把寄存器、ALU 和存储器连起来

可以把这个 CPU 的内部连接压缩成下面的结构：

```text
                 +-------------------+
clk/reset -----> | clock generator   | --> clk1 / fetch / alu_clk
                 +-------------------+

       PC ----+                         +------+
              |                         | ROM  |
              v                         +------+
         +---------+       addr
IR addr ->| addr mux|-------------------+
         +---------+                   data[7:0]
                                         |
                                         v
          +----------------+      +-------------+
data ---->| instruction IR |----->| opcode/addr |
          +----------------+      +-------------+
                                         |
                                         v
             +---------+          +---------------+
data ------->|  ALU    |<---------| accumulator   |
             +---------+          +---------------+
                  |                       |
                  v                       v
              alu_out              data controller -> data bus

                 +-------------------+
opcode/zero ---> | machine controller| -> rd/wr/load_ir/load_acc/load_pc/inc_pc
fetch/reset ---> +-------------------+
```

模块职责要分清：

| 模块 | 输入 | 输出 | 本质 |
|---|---|---|---|
| `clk_gen` | 外部 `clk/reset` | `clk1/fetch/alu_clk` | 用 8 状态同步机产生内部节拍 |
| `register` | 数据总线、`load_ir`、`clk1` | `opcode`、`ir_addr` | 分两拍装载 16 位指令 |
| `accum` | ALU 输出、`load_acc` | 当前累加器值 | 保存运算结果 |
| `alu` | 数据总线、累加器、操作码 | `alu_out`、`zero` | 执行 8 类操作的结果通路 |
| `datactl` | ALU 输出、`datactl_ena` | 数据总线 | 只在写存储器时驱动总线 |
| `adr` | `fetch`、PC 地址、IR 地址 | 地址总线 | 取指阶段选 PC，执行阶段选指令地址 |
| `counter` | `load_pc/inc_pc/rst` | PC 地址 | 顺序加 1 或装载跳转地址 |
| `machinectl` | `fetch/rst` | `ena` | 复位后在取指节拍启动控制状态机 |
| `machine` | `clk1/ena/opcode/zero` | 控制信号组 | CPU 的微操作状态机 |

注意历史边界：这个例子把 `fetch`、`alu_clk`、`inc_pc` 这类信号当成内部时钟或派生时钟使用。它能帮助理解节拍，但现代 FPGA/ASIC RTL 更推荐“一个主时钟 + clock enable”的写法，减少时钟树、时钟域和约束风险。

## 4. 指令寄存器、累加器和 ALU：先存住，再执行

指令寄存器解决一个硬件事实：数据总线只有 8 位，而指令有 16 位。

```verilog
always @(posedge clk1) begin
  if (rst) begin
    opc_iraddr <= 16'b0;
    state <= 1'b0;
  end else if (ena) begin
    if (!state) begin
      opc_iraddr[15:8] <= data;
      state <= 1'b1;
    end else begin
      opc_iraddr[7:0] <= data;
      state <= 1'b0;
    end
  end
end
```

关键不是这段代码本身，而是它背后的时序约束：

1. `load_ir` 有效时，数据总线上必须正好是指令字节。
2. 第一拍和第二拍不能混乱，否则操作码和地址会错位。
3. 复位后内部半字节状态必须清零，否则第一条指令可能从低字节开始装。

累加器只在 `load_acc` 有效的时钟边沿装入 ALU 输出：

```verilog
always @(posedge clk1) begin
  if (rst) accum <= 8'b0;
  else if (ena) accum <= data;
end
```

ALU 根据操作码选择结果，并给出 `zero`：

```verilog
assign zero = (accum == 8'b0);

always @(posedge alu_clk) begin
  case (opcode)
    ADD:  alu_out <= data + accum;
    ANDD: alu_out <= data & accum;
    XORR: alu_out <= data ^ accum;
    LDA:  alu_out <= data;
    STO:  alu_out <= accum;
    JMP:  alu_out <= accum;
    default: alu_out <= accum;
  endcase
end
```

原例中部分代码使用 `casex` 和 `x` 默认值来表达未知或优化空间。学习时要理解它的历史语境；现代可交付 RTL 中，状态和操作码译码通常优先使用普通 `case`、安全默认值、断言和覆盖检查，避免 `x` 被通配匹配掩盖真实错误。

## 5. 状态控制器：8 个时钟阶段把一条指令跑完

这个 CPU 的指令周期固定为 8 个控制阶段。状态变量不是“程序状态”，而是“当前指令周期走到第几拍”。

| 阶段 | 主要动作 | 控制信号含义 |
|---|---|---|
| 0 | 读指令高字节 | `rd=1`、`load_ir=1`，IR 装高 8 位 |
| 1 | PC 加 1，读指令低字节 | `inc_pc=1`、`rd=1`、`load_ir=1` |
| 2 | 空操作 | 给信号稳定和阶段切换留空间 |
| 3 | PC 再加 1，识别 `HLT` | PC 指向下一条指令；若 `HLT`，拉高 `halt` |
| 4 | 取操作数或准备跳转/写 | `ADD/AND/XOR/LDA` 读数据，`JMP` 准备装 PC，`STO` 开始驱动数据 |
| 5 | 执行操作 | ALU 运算、累加器装载、PC 装载、写存储器、`SKZ` 判断 |
| 6 | 空操作或保持读写相关信号 | 给存储器和控制线收尾 |
| 7 | `SKZ` 额外跳过 | 若 zero 为真，PC 再加 1，跳过下一条指令 |

把 `LDA addr` 展开就是：

```text
阶段 0-1：IR <- ROM[PC], ROM[PC+1]
阶段 3：PC <- PC + 1，指向下一条指令
阶段 4：addr bus <- IR.addr，rd 有效，存储器把数据放到 data bus
阶段 5：ALU 选择 LDA 通路，load_acc 有效
阶段 6-7：收尾，进入下一条指令
```

把 `STO addr` 展开就是：

```text
阶段 0-1：取指
阶段 3：PC 指向下一条指令
阶段 4：addr bus <- IR.addr，datactl_ena 有效，累加器驱动 data bus
阶段 5：wr 有效，RAM 在目标地址写入 data bus
阶段 6：写信号收尾
阶段 7：回到下一条取指
```

把 `JMP addr` 展开就是：

```text
阶段 0-1：取指
阶段 3：PC 先按顺序指向下一条
阶段 4：load_pc 准备使用 IR 地址字段
阶段 5：PC <- IR.addr
阶段 7：下一轮取指从跳转目标开始
```

`SKZ` 的关键是 PC 的额外增量。因为每条指令占两个字节，本设计中 PC 在取指阶段已经跨过当前指令，`SKZ` 为真时还要再跳过下一条指令的地址。读波形时如果只看操作码，不看 PC 在第 5 和第 7 阶段的变化，很容易误判条件跳转是否正确。

## 6. 读总线和写总线：地址先稳定，控制再有效

总线读操作的时序可以抽象成：

```text
地址建立 -> rd 有效 -> 外设/RAM 驱动 data -> CPU 采样 -> rd 无效 -> 地址回到取指路径
```

在这个 CPU 中，数据读通常发生在指令周期后半段。第 3.5 个周期附近，地址多路器把地址总线切到指令地址字段；第 4 到第 6 个周期，`rd` 有效，存储器或端口把数据送到数据总线；第 7 个周期以后，地址重新准备下一次取指。

总线写操作的时序可以抽象成：

```text
地址建立 -> 累加器数据驱动 data -> wr 有效 -> RAM 写入 -> wr 无效 -> 数据释放
```

写操作最怕两个错误：

| 错误 | 后果 | 检查信号 |
|---|---|---|
| `wr` 早于地址或数据稳定 | 写错地址或写入不确定值 | 地址、data、`wr` 的相对边沿 |
| 累加器和外设同时驱动数据总线 | 总线冲突，仿真出现 `x` 或硬件短路风险 | `datactl_ena`、外设输出使能 |

内部三态总线在教材和早期 FPGA 例子中很常见。现代 FPGA 内部大多没有真正三态线，综合器会把内部 `z` 转成多路选择器。学习时可以借它理解“谁拥有总线”，工程实现时要明确是顶层 I/O 三态还是片内 mux。

## 7. 仿真不是只跑波形，而是跑可定位的诊断程序

CPU 的前仿真需要把可综合 CPU 放进一个仿真环境：

| 环境模块 | 作用 | 是否属于最终 CPU |
|---|---|---|
| ROM 行为模型 | 用 `$readmemb` 装入机器码程序 | 不属于 |
| RAM 行为模型 | 用 `$readmemb` 装入初始数据，接受读写 | 不属于 |
| 地址译码器 | 根据地址选择 ROM 或 RAM | 可按需求综合或作为环境 |
| `cputop` 测试平台 | 复位、装程序、打印 PC/指令/数据 | 不属于 |
| CPU 顶层 | 连接时钟、控制、ALU、PC、IR、总线 | 属于可综合对象 |

诊断程序的价值在于：CPU 错了以后要能定位是哪条指令或哪条路径坏了。

| 测试 | 目标 | 通过标志 |
|---|---|---|
| `test1` | 基本指令诊断，重点检查 `JMP/LDA/SKZ/STO/XOR` | 在地址 `0x2e` 执行 `HLT` |
| `test2` | 高级诊断，继续检查 `AND/ADD/XOR/STO/SKZ` 组合行为 | 在地址 `0x20` 执行 `HLT` |
| `test3` | 运行 Fibonacci 程序，验证循环、存储和加法链路 | 输出 `0,1,1,2,3,5,...,144` 后停机 |

`test3` 的程序结构很适合练习手工执行：

```text
FN2 -> accum
accum -> TEMP
accum + FN1 -> FN2
TEMP -> FN1
TEMP XOR LIMIT
SKZ 为真则 DONE，否则 JMP LOOP
```

这不是为了学 Fibonacci，而是为了检查 CPU 能不能把“读、写、加、比较、条件跳过、跳转”连续组合起来。一个单条指令测试通过，不等于指令之间的数据依赖和 PC 更新都正确。

测试平台中用 `$strobe` 打印，是为了在当前仿真时刻所有非阻塞赋值更新后再观察结果。这个选择和第 7 章的事件队列知识直接相连。

## 8. 综合流程：先分模块，再分离仿真环境

复杂系统不要第一次就把所有东西丢进综合器。更稳妥的流程是：

| 阶段 | 做什么 | 目的 |
|---|---|---|
| 子模块综合 | 分别综合状态机、IR、ALU、累加器、PC 等 | 尽早发现不可综合语句和局部时序问题 |
| CPU 顶层综合 | 只保留真正要做成硬件的 CPU 模块 | 避免把 ROM/RAM 测试模型和 testbench 错当硬件 |
| 时序报告检查 | 查看时钟、最差路径、slack、资源 | 判断目标频率下是否可实现 |
| 布局布线 | 生成厂商器件相关网表和延迟 | 从逻辑综合进入物理实现 |
| 门级后仿真 | 用网表和库模型替换 RTL CPU 再跑测试 | 检查门延迟、布线延迟和 RTL 意图是否一致 |

时序报告里最有学习价值的不是旧工具名，而是报告思路：

| 报告项 | 读法 |
|---|---|
| Found clock | 工具识别了哪些时钟或类时钟信号 |
| Requested frequency/period | 你要求电路跑多快 |
| Estimated frequency/period | 工具估计当前实现能跑多快 |
| Slack | 要求时间减实际路径延迟，负值表示不满足 |
| Critical path | 哪条寄存器到寄存器或输入到输出路径最慢 |
| Resource usage | 使用了多少 LUT/触发器/I/O/专用资源 |

门级后仿真的模型和 RTL 前仿真不同：

| 前仿真 | 后仿真 |
|---|---|
| 使用 RTL 代码 | 使用综合/布局后生成的门级网表 |
| 主要检查功能逻辑 | 同时带有门延迟、布线延迟、库单元行为 |
| 波形边沿理想化 | 信号相对时钟会出现实际延迟 |
| 失败多为设计逻辑问题 | 失败可能来自关键路径、约束、异步释放、派生时钟 |

如果后仿真失败，不能只降低主时钟频率然后结束。正确追问是：失败是否说明时序约束不完整、关键路径过长、内部派生时钟不可控，还是某个模块没有按同步设计原则写。

## 9. 这个教学 CPU 的现代边界

这章的价值是建立“RTL 代码可以构造完整 CPU”的直觉，但不能把所有写法原样搬进现代工程。

| 教学写法 | 学习价值 | 现代工程边界 |
|---|---|---|
| 内部派生 `fetch/alu_clk/inc_pc` | 看清微操作节拍 | 优先改成单主时钟和 enable |
| 内部三态数据总线 | 理解总线所有权 | FPGA 片内多用 mux，顶层 I/O 才用三态 |
| `casex` 和 `x` 默认值 | 认识 don't-care 优化思路 | 控制路径优先普通 `case`、安全默认、断言 |
| 手写 ROM/RAM 行为模型 | 学会搭仿真环境 | 可综合存储器与仿真模型要分开管理 |
| 固定 8 拍指令周期 | 简化控制，便于跟踪 | 真实 CPU 会有流水线、暂停、握手和异常 |
| 直接寻址 8 条指令 | 降低 ISA 学习成本 | 真实 ISA 有寄存器堆、立即数、访存宽度、异常和特权级 |

把这章升级成现代练习，可以做四件事：

1. 用单一 `clk` 和 `state` 代替多个内部时钟。
2. 把数据总线改成明确的 mux 和写回通路。
3. 把 `HLT/SKZ/ADD/...` 写成 `localparam` 或 SystemVerilog `enum`。
4. 给 `PC`、`IR`、`accum`、`rd/wr` 加断言和自检查 testbench。

## 10. 和 AI+IC 硬件设计的连接

AI 芯片里的 NPU 控制器、DMA、片上总线接口和微码控制器都在重复本章的核心结构。

| CPU 例子 | AI+IC 中的对应物 | 共同问题 |
|---|---|---|
| PC 选择下一条指令 | DMA 地址发生器选择下一段数据 | 下一地址何时更新，跳转/循环如何处理 |
| IR 保存操作码 | 命令寄存器保存 NPU 配置命令 | 控制字段如何译码成使能信号 |
| ALU 和累加器 | MAC 阵列、累加树、后处理单元 | 数据何时进入计算，结果何时写回 |
| 状态控制器 | 卷积层调度 FSM、AXI 事务 FSM | 每一拍哪个模块拥有数据和控制权 |
| ROM/RAM 虚拟模型 | SRAM/HBM/AXI BFM、权重/激活数据模型 | 环境模型是否准确，测试是否可定位 |
| 诊断程序 | NPU 指令流、算子级回归测试 | 失败能否定位到指令、地址、数据或控制拍 |

读完本章后，不应只记住“做了一个 CPU”。更重要的是形成一个 RTL 系统分析框架：

```text
指令或命令是什么 -> 状态机怎样分阶段 -> 数据从哪里来 -> 哪拍被寄存
-> 谁驱动总线或 mux -> 结果写到哪里 -> 仿真怎样定位失败
```

## 11. 自测题
