# 练习路线与自测题：把笔记变成可运行的 RTL 能力

## 本章知识全景图

练习路线要按硬件能力递进，而不是按代码长短递进。每个练习都要产出 RTL、testbench、波形解释和失败定位。

| 等级 | 练习 | 目标 |
|---|---|---|
| L1 | 比较器、mux、ALU | 组合逻辑和完整赋值 |
| L2 | 分频器、计数波形 | 时序、复位、计数边界 |
| L3 | 阻塞/非阻塞实验 | 仿真调度和寄存器链 |
| L4 | function/task | 结构化代码和资源意识 |
| L5 | 序列检测器、串行控制 | FSM 和多拍协议 |
| L6 | 并串/串并系统 | Top-Down 和端口连接 |
| L7 | 卷积器、FIFO | 小型系统、虚拟模型、自检查 |

## 1. 每个练习的统一交付格式

每个练习建立一个文件夹，至少包含：

```text
rtl/<module>.v
tb/tb_<module>.v
sim/README.md
```

`sim/README.md` 写四件事：

1. 规格：输入、输出、时钟、复位、有效条件。
2. 验证：测了哪些正常和边界场景。
3. 波形：关键状态或寄存器在哪几拍变化。
4. 失败信号：如果错，最可能从哪里查。

## 2. L1：组合逻辑

### 2.1 8 位比较器

规格：

```text
输入：a[7:0], b[7:0]
输出：greater，当 a > b 时为 1，否则为 0
```

测试集：

| a | b | 期望 |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 2 | 0 |
| 2 | 1 | 1 |
| 255 | 0 | 1 |
| 128 | 127 | 1 |

自测问题：

1. 如果比较有符号数，代码要怎样改？
2. 如果忘了写位宽，会出现什么风险？

### 2.2 8 路 4 位 mux

规格：

```text
输入：d0..d7，每路 4 位；sel[2:0]
输出：y[3:0]
```

通过标准：

- `sel=0..7` 都测到。
- 任意输入变化，当前选中的输出立即变化。
- `default` 有安全输出。

自测问题：

1. `always @*` 和手写敏感列表有什么差别？
2. 如果少写 `default`，综合器可能生成什么？

## 3. L2：时序、复位和计数

### 3.1 1/2 分频器

要求：

- 低有效复位。
- 复位后 `clk_out=0`。
- 每个输入时钟上升沿翻转一次。

自测问题：

1. 为什么 `clk_out` 要在时序块中赋值？
2. 为什么现代设计不建议把分频输出随意当内部时钟使用？

### 3.2 周期波形发生器

要求：

- 输入时钟 10 MHz。
- 输出一个周期波形，高 20 us，低 10 us。
- 复位后从低电平开始。

验收：

- 计数器位宽足够。
- 第一个周期和后续周期长度一致，除非明确设计了启动相位。
- testbench 自动统计高低电平持续周期数。

自测问题：

1. 10 MHz 对应多少 ns 一个周期？
2. 20 us 需要多少个输入时钟周期？
3. 计数从 0 到 N-1 和从 1 到 N 有什么差一拍风险？

## 4. L3：阻塞和非阻塞实验

写两个模块：

```verilog
always @(posedge clk) begin
  b = a;
  c = b;
end
```

```verilog
always @(posedge clk) begin
  b <= a;
  c <= b;
end
```

测试：

- 每 2 个时钟改变一次 `a`。
- 打印或检查 `b/c`。
- 画出 `a -> b -> c` 的延迟关系。

必须回答：

1. 阻塞版本中 `c` 看到的是旧 `b` 还是新 `b`？
2. 非阻塞版本为什么更像两级寄存器链？
3. 如果把 `b` 和 `c` 放到两个 always 里用阻塞赋值，会产生什么 race？

## 5. L4：function 和 task

### 5.1 受控平方/立方/阶乘

规格：

```text
输入：n[3:0], op[1:0], clk, rst_n
op=0: n^2
op=1: n^3
op=2: n!
输出：result[31:0]
```

验收：

- `n=0/1/5/10` 至少测试。
- 明确结果在哪一拍有效。
- 解释阶乘在综合后的资源风险。

### 5.2 三数排序 task

规格：

```text
输入：a,b,c，每个 8 位
输出：ra<=rb<=rc
```

两种实现：

1. 组合排序网络：输入变化后输出立即稳定。
2. 时序冒泡：每拍做一次比较交换，若干拍后 `done=1`。

自测问题：

1. task 里什么时候可以用阻塞赋值？
2. 组合排序网络和多周期排序控制器的资源/延迟差别是什么？

## 6. L5：FSM

### 6.1 连续 4 个或以上 1 检测器

规格：

```text
输入：x，每拍一位
输出：z，连续 4 个或更多 1 时为 1
```

状态建议：

```text
S0: 连续 0 个 1
S1: 连续 1 个 1
S2: 连续 2 个 1
S3: 连续 3 个 1
S4: 连续至少 4 个 1
```

测试序列：

- `0000`
- `1110`
- `1111`
- `0111110`
- `110111101111`

通过标准：

- 第 4 个连续 1 出现时 `z` 拉高。
- 后续继续为 1 时 `z` 保持高。
- 输入 0 后回到未匹配状态。

### 6.2 串行读控制器

从串行写入器改写成读取器：

| 设计点 | 要求 |
|---|---|
| 主 FSM | 空闲、读地址、读数据、应答 |
| 子 FSM | bit0 到 bit7 采样 |
| 数据寄存器 | 串行输入拼成并行 8 位 |
| 输出 | `data_valid` 或 `ack` 表示完成 |
| testbench | 提供串行数据并检查并行结果 |

自测问题：

1. 主 FSM 和子 FSM 的完成标志怎样避免错拍？
2. 串行输入在哪个时钟边沿采样？
3. 如果输入线有高阻或未知，testbench 怎样暴露？

## 7. L6：Top-Down 小系统

把并串转换器和序列检测器接成闭环：

```text
8 位输入 -> 按规则输出串行 bit -> 序列检测器 -> 命中输出 z
```

要求：

- 顶层只做模块例化和连线。
- 子模块端口方向清楚。
- testbench 同时观察串行输出和检测结果。
- 若共享 `inout` 总线，必须有唯一驱动者。

自测问题：

1. 顶层模块里哪些信号是 wire，哪些是 reg？
2. 子模块端口顺序连接和命名连接哪个更安全？
3. 如果两个模块同时驱动 `data`，仿真会出现什么？

## 8. L7：卷积器和 FIFO

### 8.1 简单 1D 卷积器

规格：

```text
输入样本 x[n]，8 位
系数 h1=1,h2=2,h3=3
result = x[n]*h1 + x[n-1]*h2 + x[n-2]*h3
结果 16 位，拆成低字节和高字节写 RAM
```

最小实现：

- 输入样本来自 testbench 或 ADC 行为模型。
- 三个样本用移位寄存器保存。
- 乘加结果寄存。
- 写 RAM 分低字节和高字节两拍。
- testbench 用数组计算期望结果并比较。

进阶：

- 增加 `valid/ready`。
- 增加输入流暂停。
- 增加三 ADC 交错或多路输入，观察吞吐变化。

### 8.2 SRAM FIFO

规格：

```text
同步 FIFO
输入：clk, rst_n, fifowr, fiford, in_data
输出：out_data, nfull, nempty
内部：SRAM 行为模型，读写指针
```

必测：

| 测试 | 检查 |
|---|---|
| 复位后读 | `nempty=0`，读无效 |
| 连续写满 | `nfull` 变低或 full 标志有效 |
| 满后继续写 | 不覆盖旧数据 |
| 连续读空 | 输出顺序正确 |
| 空后继续读 | 不产生伪有效数据 |
| 写读交替 | 指针回环正确 |

自测问题：

1. 为什么 `rp==wp` 不能单独判断空满？
2. SRAM 读写为什么要先建立地址和数据？
3. testbench 的 `write_fifo/read_fifo_compare` task 应该检查什么？

## 9. 全书综合自测

完成以下问题，才算本轮过关：

1. 画出一个 RTL 模块的组合逻辑、寄存器和控制信号关系。
2. 解释 `wire`、`reg`、`memory` 的差别。
3. 写出组合 always 的安全模板。
4. 写出带低有效复位的时序 always 模板。
5. 解释阻塞和非阻塞在同一时钟边沿的差别。
6. 写出两段式 FSM 模板。
7. 解释为什么 `#delay` 属于 testbench，不属于普通可综合 RTL。
8. 说明 CPU 中 PC、IR、ALU、累加器、状态控制器分别做什么。
9. 说明虚拟 ADC 模型为什么要检查 `nconvst` 脉宽。
10. 说明 FIFO 空满判断为什么需要额外状态。
11. 对一个小卷积器，列出 DUT、虚拟模型、scoreboard 各自职责。
12. 面向 NPU，举例说明一个语法 bug 怎样变成数据错拍或吞吐下降。
